# web — 프론트엔드 작업 규칙

> 이 파일은 `web/` 안의 파일을 다룰 때 함께 읽힌다. **저장소 전체 규칙은 루트 `CLAUDE.md`**, 스택 전제는 `web/README.md`. 여기 있는 건 프론트에만 해당하는 것들이다.

## 절대 하지 않는 것

- **`src/api/types.gen.ts`를 손으로 고치지 않는다.** `make contracts`가 `/openapi.json`에서 생성한다. 타입이 안 맞으면 이 파일이 아니라 **API가 틀린 것**이고, `api-requests/open/`에 요청을 쓴다.
- **아이 화면에 이 말들을 쓰지 않는다** — 점수, 등급 문자(A·B·상·중·하), "연습", "학습", "채점", "보스", "앨범". 변수명·주석은 자유지만 **화면에 렌더되는 문자열**은 `docs/용어사전.md`의 **아이 화면** 열을 따른다.
- **아이 입력 원문을 클라이언트 로깅·오류 리포터(Sentry 등)에 넣지 않는다.** 입력 필드 값이 breadcrumb·state 스냅샷으로 딸려 나가는 경로도 막는다 (PRD 1.1b).
- **`docs/`를 직접 수정하지 않는다.** PR 본문의 「명세 변경 요약」으로 제안한다.

## 항상 하는 것

- **프론트 PII 마스킹은 아이에게 주는 즉시 피드백일 뿐이다.** 최종 판정은 언제나 서버다. 프론트 검사를 통과했다고 서버 결과를 낙관적으로 그리지 않는다.
- 가이드 캐릭터는 서버가 내려주는 `guide` 객체를 그대로 쓴다. 프론트는 `expression` → PNG 매핑만 한다 (`docs/캐릭터/` 표정 4종). **대사를 프론트에서 지어내지 않는다.**
- `POST /attempts`의 `outcome` 3분기(`result` / `scaffold` / `blocked`)를 모두 화면으로 처리한다. `blocked`를 오류 화면으로 때우지 않는다 — 아이는 자기가 뭘 잘못했는지 모른 채 막힌다.

## API가 필요하면

`api-requests/open/`에 `_TEMPLATE.md`를 복사해 요청을 쓴다. **PM 승인 없이 백엔드 승인으로 진행된다.**
착수 가능 시점은 파일이 `done/`에 있는 것이 아니라 **`make contracts`가 성공하고 타입이 생기는 것**이다 (`api-requests/README.md`).
