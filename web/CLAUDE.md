# web — 프론트엔드 작업 규칙

> 이 파일은 `web/` 안의 파일을 다룰 때 함께 읽힌다. **저장소 전체 규칙은 루트 `CLAUDE.md`**, 스택 전제는 `web/README.md`. 여기 있는 건 프론트에만 해당하는 것들이다.

## 절대 하지 않는 것

- **`src/api/types.gen.ts`를 손으로 고치지 않는다.** `make contracts`가 `/openapi.json`에서 생성한다. 타입이 안 맞으면 이 파일이 아니라 **API가 틀린 것**이고, `api/` 세션에서 고친 뒤 다시 생성한다.
- **아이 화면에 이 말들을 쓰지 않는다** — 점수, 등급 문자(A·B·상·중·하), "연습", "학습", "채점", "보스", "앨범". 변수명·주석은 자유지만 **화면에 렌더되는 문자열**은 `docs/용어사전.md`의 **아이 화면** 열을 따른다.
- **학부모 화면 문구에 전문 용어를 쓰지 않는다.** PRD·ADR 문장을 그대로 옮기지 않고, **아이 화면 열의 어휘도 쓰지 않는다.** 기준은 `docs/용어사전.md` 9장 — **읽어도 모르면 고지가 아니라 알리바이다.**
- **아이 입력 원문을 클라이언트 로깅·오류 리포터(Sentry 등)에 넣지 않는다.** 입력 필드 값이 breadcrumb·state 스냅샷으로 딸려 나가는 경로도 막는다 (PRD 1.1b).
- **`docs/`를 이 세션에서 수정하지 않는다.** 같은 사람이 PM 모자도 쓰지만 **모자가 다르다.** 명세가 틀렸다고 판단되면 여기서 고치지 말고 **루트 PM 세션에서 별도 커밋으로** 반영한다 — 섞이면 명세 변경이 코드 diff에 묻힌다. (`api-requests/`는 휴면이다.)

## 항상 하는 것

- **화면에 그대로 나가는 문장은 `docs/문구.md` 가 SSOT 이고 코드가 따라온다.** 없는 문구를 코드에서
  지어내지 않는다 — **낱말은 `용어사전.md`, 문장은 `문구.md`** 다.
  - **⚠ 프론트는 문구가 `src/**/copy.ts`·`src/components/children-copy.ts` 에 복사돼 있어
    문서를 고쳐도 안 따라온다.** **백엔드는 런타임에 읽어서 따라오는데 프론트만 다르다** —
    그래서 **문서가 먼저 바뀌고 화면이 옛말을 하는 상태**가 조용히 생긴다.
    **2026-09-10 에 그 구조를 그대로 밟았다**: PM 이 `문구.md` 3.1·3.4 를 고쳤는데 화면이 안 따라와
    별도 항목으로 다시 쳐야 했다. **기계 대조 장치는 `docs/미룬것.md` 에 있고 09-20 뒤다** —
    그때까지는 **사람이 지키는 것이지 장치가 있는 게 아니다.**
- **프론트 PII 마스킹은 아이에게 주는 즉시 피드백일 뿐이다.** 최종 판정은 언제나 서버다. 프론트 검사를 통과했다고 서버 결과를 낙관적으로 그리지 않는다.
- 가이드 캐릭터는 서버가 내려주는 `guide` 객체를 그대로 쓴다. 프론트는 `expression` → PNG 매핑만 한다 (`docs/캐릭터/` 표정 4종). **대사를 프론트에서 지어내지 않는다.** **제출 전(입력 중) 화면 상태는 서버 응답이 없으므로 프론트가 정하되, 표정 4종은 쓰지 않는다** — 입력 중 캐릭터는 `default` 고정이고 글자 수 격려는 표정이 아닌 다른 수단(나침반 빛)으로 한다 (`docs/api/Stage0.md` 3절).
- `POST /attempts`의 `outcome` 3분기(`result` / `scaffold` / `blocked`)를 모두 화면으로 처리한다. `blocked`를 오류 화면으로 때우지 않는다 — 아이는 자기가 뭘 잘못했는지 모른 채 막힌다.
- **Next.js 16은 API·규칙·파일 구조가 이전 버전과 다르다.** 코드를 쓰기 전에 `web/node_modules/next/dist/docs/`의 해당 가이드를 먼저 확인한다. 기억에 있는 이전 버전 관례로 쓰지 않는다.

## 이번 주에 할 일

계획은 `docs/주차계획/W<n>.md` 「작업 쪼갬 · 프론트」, 진척 체크는 **`web/tasks/W<n>.md`**.

- **`web/tasks/W<n>.md` 가 없으면 먼저 `/my-week W<n>` 을 돌리라고 알린다.** 계획에서 이 패키지 몫만 뽑아 만든다
- **범위를 진척 파일에서 조용히 바꾸지 않는다 — 새로 생기면 PM 에게 말한다.**
  **막지 않는다.** 계약이 바뀌거나 실기기에서 결함이 나오면 **그것을 만난 세션의 파일에 먼저 앉는 것이
  정상이다.** 2026-09-09 하루에 넷이 그랬고 **셋은 막혔으면 아예 안 나왔다**(배포 · 액자 · 즉시 `ready`).
  **대신 `신설` + 날짜 + 근거 커밋을 적고 PM 에게 말한다.** 계획이 원본이라는 것은
  **「거기서 태어나지 않는다」가 아니라 「거기로 옮겨 간다」**는 뜻이다
- 항목을 끝내면 그 파일의 체크박스를 갱신하고, 상대에게 말할 것이 있으면 함께 짚는다
- **하위 체크박스 하나가 한 세션 분량이다.** 하나를 끝내면 커밋하고 **세션을 새로 띄우라고 권한다** — 한 세션에서 크게 하면 컨텍스트가 늘어져 위의 「절대 하지 않는 것」을 뒤로 갈수록 놓친다

## 커밋하기 전

- `pnpm typecheck && pnpm lint && pnpm test` — **로컬에서 먼저 돌린다.** CI는 `main` push 후에 도는 사후 통보다
  - **`typecheck` 이 빠지면 안 된다.** `eslint` 는 **깨진 import 를 못 잡는다** — 2026-09-09 에
    헬퍼 이름을 바꾸고 한 곳이 옛 이름을 가리키는 채로 **lint 가 초록이었다.** CI 도 같은 셋을 돈다
- **⛔ `pnpm build` 도 돌린다** (2026-09-16 신설). **Vercel 이 도는 것이 그것**이고,
  **위 셋이 다 초록인 채로 배포가 죽었다.**
  - **⚠ 셋과 다른 것을 잡아서가 아니다 — 다른 것을 보고 잡는다.** `typecheck` 은 **네 워킹
    트리**를 보고, Vercel 은 **저장소를 클론해서 커밋된 것**을 본다. **세션이 셋이라 그 둘이 갈린다**
  - **그날 난 것** — 백엔드가 `types.gen.ts` 를 **재생성했는데 아직 커밋 전**이었다. 나는 그
    새 타입에 맞춰 픽스처에서 필드를 걷어냈고 **내 `typecheck` 은 초록**이었다. Vercel 은
    **옛 타입을 클론해서** `Property 'bonus' is missing` 으로 죽었다. **`main` 이 몇 분 깨져 있었다**
  - **⛔ 그래서 진짜 규칙은 위가 아니라 이것이다 — 남의 미커밋에 기대어 커밋하지 않는다.**
    계약이 바뀌면 **백엔드가 `types.gen.ts` 를 커밋한 뒤**가 신호다(「착수해도 되는 시점」과 같은 말).
    **메시지로 「지금 걷어라」가 와도 신호는 커밋이다** — 그날 그걸 메시지로 받아서 밟았다
  - **⚠ 남의 미커밋을 `stash` 로 치워 놓고 재지 않는다.** 루트 `CLAUDE.md` 가 `--autostash` 를
    금지한 것과 같은 이유다 — **그 사이 상대 세션이 저장하면 꼬인다.** `pnpm build` 는
    **워킹 트리를 그대로 두고** 도므로 그 위험이 없다. **대신 이 검사도 워킹 트리를 본다**:
    **커밋된 상태를 재는 것은 `pnpm build` 가 아니라 위 「남의 미커밋에 기대지 않는다」**이다
  - **⚠ 느리다** (2.7초 컴파일 + 타입 6초). 매번 돌리는 값이 아까우면 **계약·타입이 움직인
    날에만** 돌려도 된다 — **그날이 바로 이것이 나는 날**이다
- `main`은 백엔드와 공용이다. 반쯤 된 것을 올리지 않는다

## API가 필요하면

**`api-requests/` 는 휴면이다** (2026-09-06~, `adr/0008`). **요청자와 담당자가 같은 사람이 되어
왕복이 성립하지 않는다** — 개발자가 둘이 되면 되살린다. **위 11행이 이미 그렇게 적어 두고 있었는데
이 절만 살아 있는 절차로 남아 같은 파일 안에서 모순이었다** (2026-09-10 정리).

**백엔드 세션에서 고친 뒤 `make contracts` 를 다시 돌린다.** 아직 안 정한 설계 결정은
`docs/api/미결.md`, 대표 판단이 필요한 것은 주차 계획의 「막힌 것」에 적는다.

## 착수해도 되는 시점

**`/api-check` 로 확인한다.** 현황·접수 여부·기계 검증을 한 번에 해준다.

파일이 `done/`에 있는 것은 사람이 옮긴 주장일 뿐이다. **기계 신호 둘을 확인한다.**

1. `make contracts-check` 가 통과한다 — **`make contracts` 로 확인하지 않는다.** 그건 재생성용이라 서버가 필요하고, **서버가 죽어 있으면 curl 단계에서 멎어 재생성이 안 된 채 `git diff` 만 통과한다** — 계약이 틀려도 초록으로 보인다 (2026-09-07 실측). `contracts-check` 는 서버도 curl 도 안 쓰고 워킹 트리도 안 건드린다
2. 목 서버 또는 스테이징에서 그 엔드포인트가 응답한다

**기계가 보는 것은 「지금 트리와 명세가 같다」까지다.** 「백엔드가 커밋한 뒤 **한 번 더 돌려** 드리프트 0 인 것」이 착수 신호라는 것은 기계가 모른다 — **기계 통과를 착수 허가로 오해하지 않는다.** 스키마가 바뀌는 작업이면 그 파일은 **반드시 바뀌고**, 바뀐 것을 백엔드가 커밋한 **뒤**가 신호다.

**어긋나면 코드가 맞다.**

- **`web/out` 은 세션 둘이 같이 쓰는 하나의 상태다. 남이 구워 둔 것을 믿지 않고 쓰기 직전에 굽는다.**
  같은 폴더를 **정적 e2e(상대 경로)와 실기기(LAN 절대 주소)가 번갈아** 쓰는데 **겉이 같다.**
  2026-09-09 에 **「LAN 상태로 두겠다」고 말해 놓고 몇 분 전 내 손으로 상대로 덮은 것을 몰랐다.**
  **빌드는 `out/` 을 비우고 다시 쓰므로 섞이지는 않는다** — 문제는 섞임이 아니라 **누가 마지막이냐**다.
  잘못 쓰면 양쪽에서 죽는다 (`playwright.static.config.ts` 의 `globalSetup` · api 의 `serve_web_out.py`).
  **그래서 아무 상태로 둬도 되고, 대신 상태에 기대지 않는다.**

- **서비스워커가 낸 요청은 `page.route` 가 못 가로챈다.** 정적 빌드는 `public/sw.js` 를 등록하므로
  **첫 요청만 잡히고 그 뒤가 통째로 빠져나간다** — 화면은 「서버가 거절했다」로 떨어지는데
  **제품이 아니라 검사가 만든 실패**다. 정적 빌드를 재는 하네스에는 `serviceWorkers: "block"` 을 넣는다
  (`playwright.static.config.ts`). **서비스워커 자체를 재는 것은 `e2e/pwa.spec.ts` 의 몫이다.**
  (2026-09-09 실측 — 이걸 모르고 **엔진 탓으로 세 시간을 썼다.** 모양이 같다고 원인이 같지 않다)

- **React 훅 이름과 컴포넌트 이름이 영문이다.** 그 밖의 식별자는 그대로 한글을 쓴다
  (`못닿음원인`·`실행형태판정`·`별명이걸렸다`).
  `react-hooks/rules-of-hooks` 가 **훅은 `use` + 대문자**, **컴포넌트는 첫 글자 대문자**로 검사하는데
  **한글에는 대문자가 없다.** 그래서 `use실행형태` 는 훅으로 인식되지 않고,
  **한글 이름의 컴포넌트 안에서는 훅을 아예 못 쓴다**(「컴포넌트도 커스텀 훅도 아니다」로 4줄이 한 번에 뜬다).
  **규칙의 예외가 아니라 도구의 제약이다.**
