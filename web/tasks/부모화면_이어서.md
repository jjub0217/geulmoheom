**⛔ 「그림」이 들어갔는지는 `check-copy` 가 못 본다** — 별명이 끼는 문장이라 대조에서 빠진다.
그래서 `e2e/parent-children.spec.ts` 에 그 문장을 직접 보는 검사를 세웠다.
**걷은 「같은 주소」가 되살아나는 것도 같은 파일이 본다** — 없어진 문장은 `check-copy` 가 못 본다.

## 남은 것

### ⛔ push — 사용자 승인을 받아야 한다

**PM 문서 커밋과 프론트 코드 커밋을 같이 올린다.** 문서 커밋만 올리면 **문서에서 사라진 문장이
코드에는 남아 있는 상태**가 원격에 잠깐 선다.

### 브라우저로 눈으로 못 본 것

- **실기기** — 에뮬레이션만 했다
- **다크 모드**
- **삭제 완료 뒤 목록 갱신** — 검사로만 봤고 눈으로는 안 봤다

바뀐 두 화면(접속 코드 안내 · 삭제 확인창)은 **태블릿 가로 크기로 화면을 찍어 확인했다.**

## ⛔ 별건 — 삽화 파일 파기는 코드가 섰지만 운영에서는 아직 안 돈다

**PM 세션이 구현해 커밋했다** (`1e96aa3`). 프론트 몫이 아니고 백엔드 몫도 아니다 —
사용자가 이 건을 PM 세션에 직접 지시했다.

방향은 **개인 삽화 파일은 실제로 지우고, 여러 아이가 함께 쓰는 공용 삽화 18장은 남기고,
AWS 삭제에 실패했는데 삭제 완료로 처리하지 않는 것**이다.

**⛔ 운영에서는 아직 안 돈다.** AWS 권한에 파일 삭제 권한(`s3:DeleteObject`)이 없다.
**사용자가 AWS 화면에서 직접 붙인다.** 붙기 전까지 **운영에서 자녀 삭제를 누르면 서버가
거절하고, 부모 화면에는 「잠시 문제가 생겼습니다. 잠시 뒤에 다시 시도해 주세요.」가 뜬다.**
**지운 척하는 것보다 낫다고 사용자가 판정한 방향이라 의도된 동작이다.**

**⚠ 부모 화면 브라우저 검사는 이것과 무관하게 통과한다.** 그 검사는 서버를 아예 안 부르고
`page.route` 로 응답을 흉내 내기 때문이다 — **검사가 초록이라고 운영에서 도는 것이 아니다.**

## 검사 돌리는 법 (⚠ 함정 셋)

```
NODE_OPTIONS="" pnpm typecheck && NODE_OPTIONS="" pnpm lint && NODE_OPTIONS="" pnpm test
NODE_OPTIONS="" pnpm build
node infra/check-copy.mjs          # 저장소 루트에서
```

**⛔ 모든 node·pnpm 앞에 `NODE_OPTIONS=""` 를 붙인다** — 이 환경에서 그 변수가 깨져 있다.

브라우저 검사는 **떠 있는 3004 에 붙어** 돈다. **그 서버는 백엔드 세션이 띄우고 관리하며
프론트가 같이 쓴다** — 검사 전에 서버가 응답하는지 먼저 본다 (사용자 지시).
붙는 설정은 세션 스크래치패드에 있고, 없으면 `playwright.config.ts` 를 베껴
`webServer` 를 빼고 `baseURL` 만 3004 로 바꾼다.

**⛔ 브라우저 검사가 도는 동안 `pnpm build` 를 같이 돌리지 않는다** (2026-09-21 실측).
빌드가 개발 서버를 다시 만들게 해서 **화면을 처음 여는 검사 한 건이 요청을 두 번 세고 실패한다.**
`book-journey.spec.ts:474` 가 그렇게 걸렸다 — **제품 결함이 아니다.**
그 파일을 통째로 돌리면 앞선 검사가 화면을 미리 열어 둬서 18건 모두 통과한다.

**⛔ 서버를 직접 띄우면 `NEXT_PUBLIC_API_BASE_URL=/api/v1` 을 반드시 준다.**
다른 오리진을 주면 JSON 요청 앞에 preflight 가 붙고 `page.route` 가 못 가로채
**화면이 통째로 「못 닿음」이 되어 검사가 무더기로 죽는다.** 2026-09-21 에 8건이 그랬다.
**숫자를 말할 때는 `--workers=1`** — 여럿이면 같은 가짜 서버 상태를 나눠 쓴다.
