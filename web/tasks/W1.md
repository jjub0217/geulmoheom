## 메모

     docs/api/미결.md 또는 api-requests/ 로 간다 -->

- **매니페스트는 `public/manifest.json` 이 아니라 `src/app/manifest.ts`** — Next 16 App Router 의 파일 컨벤션이다.
  타입(`MetadataRoute.Manifest`)으로 검사되고 `<link rel="manifest">` 도 Next 가 넣는다. `layout.tsx` 에는
  매니페스트가 못 덮는 것만 뒀다 — iOS 는 홈 화면 추가에 `apple-*` 메타와 apple-touch-icon 을 본다
- **서비스워커는 캐싱 없음.** `src/lib/service-worker.js` 는 install/activate 와 빈 fetch 핸들러뿐이다.
  오프라인 전략을 붙일 때 이 파일부터 채운다
- **매니페스트에 `orientation` 을 두지 않는다.** 한때 `landscape` 를 넣었다가 뺐다 — 이 필드는 선호가
  아니라 방향 **고정**이고, 잠그면 PRD A0-2 · 비기능 접근성의 MUST 「모바일 세로」를 어긴다.
  Android 홈 화면 추가 시에만 걸리고 iOS 는 이 필드를 무시하므로 **iPad 로 테스트하면 안 잡힌다**.
  「태블릿 가로 우선」은 다음 하위 항목(기준 레이아웃)에서 CSS 로 한다
- **색 토큰의 SSOT 는 `docs/캐릭터/도우미캐릭터설명.md` 의 색상코드 표**다. `globals.css` 의 `@theme` 은
  그 표 6행 + 부속 2색을 옮긴 것이고 **여기서 색을 지어내지 않는다.** 새 색이 필요하면 PM 에게 말한다
- **`@theme` 이 아니라 `@theme static` 이다.** 기본 `@theme` 은 안 쓰인 변수를 산출물에서 털어낸다 —
  브라우저에서 확인해 보니 색 8개 중 5개(`fur`·`vest`·`scarf`·`brass`·`glow`)가 **정의되지 않은 상태**였다.
  `bg-scarf` 같은 유틸리티로 쓰면 빌드가 생성해 주지만 커스텀 CSS·인라인의 `var(--color-scarf)` 는
  조용히 빈 값이 된다. 색 SSOT 라 항상 있어야 해서 `static` 으로 고정했다
- **상태바 색을 배경에 맞췄다.** `themeColor` 가 SCARF(`#457B9D`) 였는데 실제 배경은 크림/짙은 남색이라
  홈 화면에서 띄우면 상태바만 파랗게 떴다. 모드별 배열로 바꾸고 매니페스트도 같이 맞췄다
- **명암비 실측** 밝을 때 7.66:1 · 어두울 때 6.99:1 — 둘 다 WCAG AA(4.5:1) 통과
- **한글 웹폰트가 없다.** Geist 는 `subsets: ["latin"]` 이라 한글은 OS 시스템 글꼴로 떨어지고
  기기마다 본문 인상이 다르다. 용량·디자인 결정이라 **C-2(W2) 캐릭터 확정 때 같이 볼 것**
- **`src/app/page.tsx` 는 아직 create-next-app 기본 화면**이다 (`bg-zinc-50`·영문 문구).
  A0-2 입력 UI(W2)에서 갈아엎을 자리라 손대지 않았다
- **아이콘은 임시본**이다 (`public/icons/`, 색상코드 표의 SCARF·BRASS·GLOW 로 그린 나침반 마크).
  캐릭터 정본이 C-2(W2)에서 확정되면 교체 대상
- 계획에 없어 체크리스트에 넣지 않은 것 2건 — **답이 왔다** (아래 「PM에게 물은 것 — 둘 다 닫혔다」)

- **`make contracts` 에는 api 가 로컬에 떠 있어야 한다.** Makefile 이 `curl localhost:8000/openapi.json` 이라
  프론트도 `uv` 가 필요하다 — `작업흐름.md` 도구 표는 `uv` 를 「백엔드」로 적어놨다. **문서의 빈틈**
- **Docker 는 필요 없었다.** `app_env` 기본값이 `dev` 라 필수 키 검사를 안 타고 startup 훅도 없어서
  Postgres·Redis 없이 뜬다. `uv sync` → `uv run uvicorn app.main:app --port 8000` 이면 끝
- **백엔드 3번의 마지막 미완 항목이 이걸로 풀린다** — `api/tasks/W1.md` 의
  「`make contracts` 성공 확인 — 프론트 대기」. **전달 완료 (2026-09-06). 백엔드 3번은 닫혔다**

- **11-2 조사에서 11-5 결정 위에 얹어야 할 게 셋 나왔다** (`web/notes/미결11-2_토큰저장_프론트조사.md`).
  ① Safari 16.4+ 가 **IP 를 따로 봐서** 같은 등록가능 도메인이어도 30일을 7일로 깎을 수 있다
  ② iOS 홈 화면 앱은 Safari 와 쿠키를 공유하지 않아 **온보딩 순서**를 바꿔야 한다
  ③ **Cloudflare Pages 프리뷰(`*.pages.dev`)는 cross-site** 라 인증이 아예 안 된다

  **셋 다 닫혔다 (2026-09-06 · `docs/api/공통규약.md` 「인증 쿠키」).**
  ① 쿠키만 슬라이딩(JWT 는 절대 30일)으로 완화했다. **다만 보장이 아니다** — `app.`/`api.` 의 IP 대역이
     실제로 붙는지는 **배포 후 `dig` 실측**이 있어야 안다
  ② **자녀 인증 화면은 standalone 에서만 연다.** 브라우저 탭이면 설치 안내를 먼저 띄우고 코드 입력을
     열지 않는다 — 접속 코드가 **1회 사용**이라 탭에서 써버리면 재발급 없이는 홈 화면 앱으로 못 들어간다.
     불편이 아니라 **막힘**이다
  ③ **프리뷰는 인증이 안 되는 채로 둔다.** 커스텀 프리뷰 서브도메인을 붙이지 않고 CORS 오리진에도 넣지 않는다

### 프론트에 남은 결정 — 0007 이 넘긴 것

- **서비스워커를 어디에 둘 것인가** (`adr/0007` 결정 5, 명시적으로 프론트 몫).
  ① Pages `_headers` 로 `Service-Worker-Allowed: /` 를 직접 넣거나
  ② `public/sw.js` 로 옮겨 **오리진 루트에서 서빙해 헤더 의존을 아예 없앤다**
  지금은 `src/lib/service-worker.js` 가 `/_next/static/…` 로 나가고 Next 가 헤더를 붙여준다 —
  **정적 export 로 넘어가는 순간 깨진다.** 배포를 실제로 붙일 때 정한다. ②가 배포처를 옮겨도 안 깨진다
- **개발 환경을 `.test` https(mkcert)로 옮긴다** — `https://app.geulmoheom.test` ↔ `https://api.geulmoheom.test`.
  **W2 E-3/E-4 착수와 동시**이고 그전까지는 `localhost` 그대로다. `__Host-` 로컬 실측은 이걸로 필요 없어졌다
- **인증 코드는 아직 쓰지 않는다.** 목 서버·`/openapi.json`·`types.gen.ts` 가 전부 옛 형태(토큰이 응답 body 에 있음)다.
  W2 E-3/E-4 에서 백엔드가 맞춘 뒤 `make contracts` 를 다시 돌리는 것이 착수 신호다.
  착수 목록은 조사서 「프론트가 할 일」 9개 (`credentials: 'include'` 강제, 3상태 관리 등)
