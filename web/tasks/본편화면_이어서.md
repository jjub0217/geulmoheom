# 본편 글쓰기 화면 — 이어서 할 것

세션이 바뀔 때 넘기는 메모다. **끝나면 이 파일을 지운다.**
계획이나 결정은 여기 두지 않는다 — 오래 남아야 하는 것은 `docs/문구.md`·`docs/미룬것.md` 에 있다.

## 지금 화면이 어떻게 도나

**한 턴이 세 단계다.** 같은 `/chapter` 안의 화면 상태이고 주소를 안 나눴다.

```
글쓰기   대응할 장면 서사 · 「이제 어떻게 할까?」 · 입력칸 · 「이야기 이어가기」
  ↓
결과     「네가 쓴 글」 · (새 삽화가 있을 때만) 그 삽화 · 짧은 반응 · 「그다음 이야기 보기」
  ↓
새장면   새 서사가 중심 · 「다음 행동 쓰기」
  ↓
글쓰기   서사는 남고 입력칸이 열린다
```

**삽화 상태는 넷이고 그중 하나는 「아무 말도 안 함」이다.**
새로 왔으면 **「새 그림이 완성됐어!」**, 만드는 중이면 **「네 글을 그림에 담고 있어.」**,
**기본 그림이면 아무 말도 안 한다.** 앞 턴 그림은 **결과 단계에 아예 안 보인다.**

## ⛔ 오늘 뒤집힌 결정 둘 — 되돌리기 전에 읽는다

**둘 다 사용자가 근거를 알고 뒤집은 것**이다. 코드 주석에 종전 근거를 남겨 뒀다.

**① 읽는 칸의 고정 높이와 내부 스크롤을 걷었다.**
종전 근거는 **「늘리면 쓰는 칸이 첫 화면에서 밀린다 — W6 에서 아이 셋이 다 못 찾았다」**였다.
그 사고는 실제로 있었다. 뒤집은 근거는 **서사가 `MVP_PRD.md` 규정으로 한 턴 150~300자**인데
그 칸이 **1280×800 에서 176px · 320×568 에서 114px** 이라 **어느 크기에서도 다 안 들어갔다**는 것이다.
**입력창이 첫 화면 아래로 내려가는 것 자체는 문제가 아니라고 사용자가 못 박았다.**

**② 새 삽화가 없는 턴에 앞 그림을 결과에 안 보인다.**
종전 근거는 **「액자를 비우지 않는다 — 여덟 턴 중 일곱에서 보상이 사라진다」**였다.
뒤집은 근거는 **아이가 「내가 방금 쓴 글로 이 그림이 나왔다」로 읽는다**는 것이다.

**⚠ ②의 대가를 적어 둔다** — 그림이 보이는 자리가 **1턴·9턴의 결과 단계와 첫 입장**으로 줄었다.
**「썼더니 그림이 나왔다」가 덜 자주 보인다.** 사용자가 실제 화면을 보고 **너무 줄었다고 하면
그때 다시 본다.** 지금 임의로 되돌리지 않는다.

## ⛔ 아직 눈으로 못 본 것 — 다음 세션이 먼저 할 것

- **9턴 새 삽화와 10턴 이후** — 목 서버로 1~2턴만 밟았다. 판단이 **턴 번호가 아니라 삽화
  식별자 기준**이라 같게 돌아야 하지만 **실제로는 안 밟았다**
- **G0 되묻기** — 결과 단계로 안 넘어가는 것은 검사로 봤고 눈으로는 안 봤다
- **챕터 완결 · 네트워크 실패** — 기존 검사가 덮고 통과했으나 눈으로는 안 봤다
- **실기기** — 창 크기 에뮬레이션만 했다. 실제 휴대폰 키보드가 올라올 때의 높이는 못 쟀다
- **키보드만 사용 · 화면 읽기 도구** — 초점이 입력칸으로 안 가는 것은 쟀지만
  읽어 주는 순서는 안 들어 봤다
- **다크 모드**

## ⛔ 서버 주인이 사용자로 바뀌었다 (2026-09-22)

**종전에는 백엔드가 띄우고 프론트가 얹혔는데, 지금은 사용자가 자기 터미널에서 쥐고 Ctrl+C 로 끈다.**
**그래서 서버가 죽거나 멈추면 백엔드에 말해도 못 띄운다 — 사용자께 직접 말씀드린다.**
**⛔ 프론트가 따로 띄우지 않는다.** 포트가 물려 둘 중 하나만 산다.

**⚠ 사용자가 끄셔도 우리는 모른다.** 그래서 **브라우저 검사 전에 `curl` 로 응답을 먼저 본다.**

```
curl -s -o /dev/null -w "%{http_code}\n" --max-time 8 http://localhost:3004/
```

**⛔ 죽은 것과 멈춘 것이 다르다** (2026-09-22 실측). **포트는 잡고 있는데 응답이 없는** 상태가 있다 —
`lsof` 로는 정상으로 보이고 CPU 가 0% 다. **그때도 재시작이 필요하다.**
**원인은 메모리다** — 스왑 21.5GB 중 20GB 가 차 있다. **검사를 나눠 돌린다.**

## ⛔ 오늘 내가 두 번 밟은 자리

**① 남의 애니메이션을 한 줄로 덮었다.** 단계 등장 연출을 `[data-단계] > *` 에 걸었더니
**래서판다가 투명해졌다.** 그 요소들이 **이미 자기 애니메이션을 갖고 있었고**, 덮으면서
**「보이게 만드는 일」까지 같이 사라졌다.** **연출은 있어도 되는 것이고 래서판다는 있어야
하는 것**이라 연출을 버렸다.

**② 「그 안에 있을 때」의 전제를 안 보고 옮겼다.** 삽화를 읽는 묶음 밖으로 빼자
**액자가 0×0 으로 사라졌다** — 그 컴포넌트는 **폭을 부모에게서 받는데** 종전에는 그리드 칸이 줬다.
영역 자체도 `height: 100%` 와 컨테이너 질의를 쓰고 있어 **높이가 0** 이었다.

**⭐ 둘 다 화면을 재서 잡았다.** 그리고 **기준선과 대조**해서 **내가 만든 회귀**임을 확인했다 —
`git stash push -- <내 파일들>` 로 잠시 치우고 같은 측정을 돌리면 된다.
**작업 트리에 남의 파일이 없을 때만 그렇게 한다.**

## 검사 돌리는 법 (⚠ 함정 넷)

```
NODE_OPTIONS="" pnpm typecheck && NODE_OPTIONS="" pnpm lint && NODE_OPTIONS="" pnpm test
NODE_OPTIONS="" pnpm build
node infra/check-copy.mjs          # 저장소 루트에서
git diff --check
```

**⛔ 모든 node·pnpm 앞에 `NODE_OPTIONS=""` 를 붙인다** — 이 환경에서 그 변수가 깨져 있다.
**⚠ `pnpm` 이 「모듈을 못 찾는다」로 한 번 죽는 일이 있다.** 그냥 다시 돌리면 된다.

**브라우저 검사는 떠 있는 3004 에 붙어 돈다.** 붙는 설정은 세션 스크래치패드에 있고,
없으면 `playwright.config.ts` 를 베껴 `webServer` 를 빼고 `baseURL` 만 3004 로 바꾼다.

**⛔ 브라우저 검사가 도는 동안 `pnpm build` 를 같이 돌리지 않는다** (2026-09-21 실측).
빌드가 개발 서버를 다시 만들게 해서 **화면을 처음 여는 검사가 요청을 두 번 세고 실패한다.**

**⛔ 화면을 찍을 때는 기다렸다 찍는다** (2026-09-22 실측). 말풍선이 **한 글자씩 쓰이고**
서사도 그렇다. **1.5초쯤 기다리지 않으면 비어 있거나 투명한 화면을 찍는다** —
그걸 보고 **없는 결함을 두 번 쫓았다.**

## 문구를 바꿀 때

**⛔ 코드가 아니라 `docs/문구.md` 가 먼저다.** `check-copy` 가 **코드 → 문서** 한 방향이라
코드를 먼저 바꾸면 빨간불이고, 그 순서가 맞다. **PM 세션에 청한다.**

**⚠ 다만 코드가 맞고 문서가 뒤처진 경우도 있다** (2026-09-21 실측). **사용자가 화면에서
직접 정한 것이면 문서가 따라온다.** 「고치는 것은 코드다」를 기계적으로 적용하지 않는다.

**⭐ 문구 검사 목록을 두 번 넓혔고 두 번 다 넣자마자 값을 했다.** 넣은 파일은
