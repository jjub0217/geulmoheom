# api-requests — 프론트·백엔드 계약 작업 폴더

두 사람이 API 계약에 관해 **직접 적는 곳**. `docs/`와 달리 **양쪽 다 쓸 수 있다**
(CODEOWNERS: `@jinioh88 @jjub0217`). **GitHub 이슈를 쓰지 않는다** — 요청·논의·결정이
전부 이 폴더와 PR 안에서 끝난다.

| 종류 | 무엇 | 누가 연다 |
|---|---|---|
| `요청` | 프론트가 필요한 API 변경 | 프론트 |
| `합의` | 양쪽이 같이 정해야 할 것 (통지 방식, 토큰 저장 등) | 둘 중 누구나 |
| `작업` | 한쪽이 내놓기로 한 산출물 (목 서버 등) | 담당자 |

```
api-requests/
  open/   미결 — 여기에 새 항목을 만든다
  done/   완료·거절·보류 — 처리한 사람이 옮긴다
```

**`open/`이 비어 있으면 계약 쪽에 걸린 것이 없다.** 폴더 목록 자체가 현황판이다.

## 흐름

| 순서 | 누가 | 무엇을 |
|---|---|---|
| 1 | 여는 사람 | `_TEMPLATE.md`를 복사해 `open/NNN-slug.md` 작성 → PR |
| 2 | 상대 | 그 PR을 **승인 = 접수**. 이견이 있으면 승인 전에 PR 코멘트로 협의한다 |
| 3 | 담당 | 처리 PR에서 파일을 `done/`으로 옮기고 **완료 기록** 채움 |
| 4 | 프론트 | `main` pull → `make contracts` → 타입이 생성되면 **바로 착수** |

**논의는 PR 코멘트에서 한다.** 이슈가 없으므로 그 PR이 스레드 역할을 한다.
결론이 길어지면 파일 본문에 옮겨 적는다 — PR 코멘트는 나중에 아무도 찾지 않는다.

## 프론트가 착수해도 되는 시점

파일이 `done/`에 있다는 것만으로 착수하지 않는다. **아래 두 가지가 실제 신호다.**

1. `make contracts`가 성공하고 `web/src/api/types.gen.ts`에 해당 타입이 생긴다
2. 목 서버 또는 스테이징에서 그 엔드포인트가 응답한다

파일은 사람이 옮기는 것이라 틀릴 수 있지만, 위 둘은 기계가 보증한다. **어긋나면 코드가 맞다.**

## 백엔드가 `done/`으로 옮기는 조건

- [ ] 엔드포인트가 목 서버 또는 실제 서버에서 응답한다
- [ ] `/openapi.json`에 반영되어 프론트가 `make contracts`를 돌릴 수 있다
- [ ] 명세가 바뀌었다면 PR 본문에 「명세 변경 요약」을 적었다 (`docs/`는 PM이 반영)
- [ ] 요청 파일의 **완료 기록**에 PR 번호·머지 커밋을 적었다

## 규칙

- **항목 하나에 파일 하나.** 여러 엔드포인트를 한 파일에 묶지 않는다 — 절반만 끝났을 때 상태를 표현할 수 없다
- 번호는 이어서 증가. 재사용하지 않는다
- 거절·보류도 `done/`으로 옮기고 **사유를 남긴다.** `open/`에 남겨두면 현황판이 거짓말을 한다
- 이 폴더는 **미결 항목과 그 처리 상태**만 담는다. 확정된 계약은 `docs/Stage0_API명세.md`와 `/openapi.json`이 진실이다
