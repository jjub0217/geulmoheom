대상 주차: **$ARGUMENTS** (비어 있으면 `docs/주차계획/`에서 가장 최근 것)

## 읽을 것

- !`git pull --rebase -q 2>&1 | head -3; echo "---"; ls docs/주차계획/`
- `api/tasks/$ARGUMENTS.md` — 백엔드 체크 상태
- `web/tasks/$ARGUMENTS.md` — 프론트 체크 상태
- `docs/주차계획/$ARGUMENTS.md` — 「작업 쪼갬 · PM」의 체크 상태와 「완료 판정」

## 할 일

**0. `tasks/` 파일이 없으면 그렇다고 보고한다.**
`api/tasks/$ARGUMENTS.md` 또는 `web/tasks/$ARGUMENTS.md` 가 없으면 **그 모자로 아직 `/my-week $ARGUMENTS` 를 돌리지 않았다는 뜻**이다. 해당 역할을 "미착수"로 표시한다. **PM 세션에서 대신 만들지 않는다** — 그 패키지 세션에서 만든다. 실무는 1인이지만 모자가 셋이라(`adr/0008`) 세션과 파일은 그대로 갈린다.

**1. 세 곳의 체크 상태를 모은다.** `- [x]` 는 완료, `- [ ]` 는 미완. 하위 체크박스는 상위 항목의 진척으로만 쓰고 표에는 상위 항목만 싣는다.

**2. `docs/주차계획/$ARGUMENTS.md` 의 `## 진행 현황` 절만 통째로 갱신한다.** 다른 절은 건드리지 않는다.

```markdown
## 진행 현황

`/progress-week $ARGUMENTS` 로 갱신 · 마지막 갱신 YYYY-MM-DD
**출처는 `api/tasks/` · `web/tasks/` · 아래 「작업 쪼갬 · PM」이다. 이 표를 손으로 고치지 않는다.**

**백엔드 n/7 · 프론트 n/5 · PM n/4**

| | 담당 | 항목 |
|---|---|---|
| ✅ | 백엔드 | 1. api 스캐폴딩 |
| ⬜ | 백엔드 | 3. 목 응답 서버 ← 최우선 |
```

**3. 막힌 것을 짚는다.** 표 아래에 필요할 때만 한두 줄.

- **선행이 안 끝난 채 후속이 대기 중인 것** — 특히 목 서버가 미완이면 프론트 3번이 막혀 있다
- **주 절반이 지났는데 최우선 항목이 미완**이면 그 사실을 말한다
- 아무 문제 없으면 아무 말도 쓰지 않는다. 없는 문제를 만들지 않는다

**4. 계획과 어긋난 것을 보고한다.** (문서를 고치지는 말고 사용자에게 알린다)

- `tasks/` 에 계획에 없는 항목이 생겼다 → 범위가 조용히 늘었다는 뜻
- 계획 항목이 `tasks/` 에 없다 → 누락
- **「범위」 표의 담당이 `공동`인 항목이 한쪽 `tasks/` 에만 있다** → 나머지 쪽 몫에 담당자가 없다. 계획의 「작업 쪼갬」을 고쳐야 한다
- 완료 판정 중 기계로 확인 가능한 것(`make contracts`, CI)은 체크 상태와 실제가 맞는지 의심해 볼 것을 권한다

**5. 커밋은 사용자에게 맡긴다.** 제안만 한다 — `git add docs/주차계획/ && git commit -m "$ARGUMENTS 진행 현황 갱신"`
