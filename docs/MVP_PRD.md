## 1. 개요

### 1.1 한 줄 정의
만 10~12세 아동이 **직접 쓴 묘사 문장으로만** 진행되는 텍스트 판타지 TRPG. 묘사가 구체적일수록 더 좋은 삽화와 스킬 보너스가 열리고, 1챕터(15~20분)가 끝나면 그날의 모험은 반드시 종료된다. **모험의 매 장은 아이의 책이 되어 쌓이고, 완성된 책은 안전한 울타리 안에서 모든 사용자에게 공유된다** (비전 2장. 공유 서재는 P1).

### 1.1b 아이 원문의 지위 (v4)
아이가 쓴 문장은 **로그가 아니라 아이의 창작물**이다. 네 가지를 구분한다.
- **책 콘텐츠**: `card_attempts.text`, `book_pages` — 아이의 책이므로 **보관**. 계정 삭제 시에만 파기
- **로그·APM**: 원문 절대 미기록. 수치·등급·태그만 (F-1)
- **Evaluator 라벨링 활용**: 보관된 원문을 운영자가 라벨링에 쓰는 것은 **학부모 동의 항목**. 미동의 시 책에는 남되 라벨링 셋에서 제외
- **LLM 프로바이더 전송** (v4, 2026-09-01 추가): Evaluator·GM 처리를 위해 **원문이 Google Gemini API로 나간다.** 유료 티어라 학습·제품 개선에는 쓰이지 않지만, **남용 탐지 목적의 제한 기간 로깅은 약관상 거부할 수 없다** (`adr/0005`).
  위 「로그·APM 미기록」은 **우리 시스템 기준**이며 제3자 처리 위탁을 다루지 않는다 — 헷갈리지 않도록 명시한다.
  완화: **PII 검사가 LLM 호출보다 앞이다** (`api/Stage0.md` 9절 순서 3 → 5). 실명·학교명·연락처는 도달하지 않는다. 그래도 창작 문장 자체는 나가므로 **E-4 동의 화면에서 고지한다**
- GM 서사 원문은 Redis 턴 히스토리에서만 유지, 챕터 완결 시 요약·책 페이지로 압축 후 파기

### 1.2 두 단계로 만든다

| 단계 | 이름 | 무엇 | 증명할 것 | 기간 |
|---|---|---|---|---|
| **Stage 0** | 나침반 퀘스트 | GM 캐릭터가 가져온 **모험 장면 카드**에 탐험가의 행동을 쓰면, 묘사 등급에 따라 삽화가 해금되는 단일 턴 루프. 서사 연결 없음 | **H2** — 시각 보상만으로 아이가 더 구체적으로 쓰는가 | 2~3주 + 파일럿 2주 |
| **Stage 1** | TRPG | Stage 0 위에 GM 서사·상태·챕터·하드 피니시를 얹은 본편 | **H1·H3·H5** — 몰입·재방문·결제 | 3~4주 + 파일럿 2주 |

Stage 0을 먼저 두는 이유는 `백로그.md` 0장 참조. Stage 0은 **"연습"이 아니라 퀘스트**다 — 점수·채점·연습이라는 단어는 UI 어디에도 쓰지 않는다.

**Stage 0 루프의 세 가지 쓰임** — 같은 코드, 다른 설정:

| 시점 | 이름 | 카드 | 잠금 | 역할 |
|---|---|---|---|---|
| 파일럿 1 | 나침반 퀘스트 | 20장, 하루 5장 | A0-5 | H2 검증 슬라이스 |
| Stage 1 이후 · 신규 사용자 | **나침반 깨우기 (튜토리얼, A-6)** | 전용 3장 | 없음 | 모든 사용자의 첫 5~7분. 규칙 체득 후 챕터 1 진입 |

### 1.3 MVP가 아닌 것 (명시적 제외)

## 2. 핵심 사용자 흐름

### 2.1 학부모 온보딩 (최초 1회)
```
학부모 가입(이메일) → 서비스·안전 정책 고지 → 보호자 동의 체크 → 자녀 계정 생성(닉네임만) → 자녀용 접속 코드 발급
```
- 학부모는 이메일 1개만 제공. 자녀 정보는 닉네임과 연령대(만 10/11/12) 외 수집하지 않음
- 접속 코드는 6자리, 자녀 기기에서 입력하면 로그인 유지(쿠키 30일)

### 2.2 [Stage 0] 나침반 퀘스트 루프 (매 세션)
```
접속 → [오늘 카드 잔여 확인] → GM 캐릭터가 장면 카드 제시 → 입력 → 안전검사 → 평가 → (G0이면 되묻기) → 결과 연출(삽화 티어 해금 + 캐릭터 반응 + 묘사어 하이라이트) → [다시 써보기 | 다음 카드] → 5장 소진 → "내일 또 보자"
```
- 카드 = 스케치 삽화 1장 + 한 줄 상황 ("안개 낀 숲에서 거대한 그림자가 다가온다. 탐험가는 어떻게 할까?")
- "다시 써보기"는 같은 카드를 재입력해 더 높은 티어를 노리는 것. 카드 소진 수에 포함되지 않음, 횟수 제한 없음 (`card_retry` 로그)
- 결과 연출에서 Evaluator가 감지한 묘사어를 입력문 위에 **하이라이트** — "이 단어들이 나침반을 움직였어" (점수 없음)
- 내 책: 카드별 최고 티어 삽화 + 아이 문장이 책 페이지로 쌓임 (A0-4)

### 2.3 [Stage 1] 학생 플레이 루프 (매 세션)
```
접속 → [잠금 확인] → 챕터 선택/이어하기 → GM 도입 서사 → (턴 반복: 상황 제시 → 입력 → 안전검사 → 평가 → 서사 진행 → [핵심 씬이면 삽화]) → 시련 → 완결 → 하드 피니시 화면 → 잠금
```
- 잠금 상태(오늘 챕터 완료 또는 턴 상한)면 GM 캐릭터의 "내일 또 보자" 화면만 표시
- 한 챕터는 **8~12턴** 목표 (턴당 1~2분 → 15~20분)

### 2.4 [Stage 1] 턴 상세 — Stage 0 루프에 서사·상태가 붙은 형태
```
[GM 상황 제시 + 선택지 2~3개 + 자유 입력창]
        │
        ▼ 아이 입력 (선택지 클릭 or 자유 묘사)
        │
        ▼ ① PII 마스킹 (클라이언트 1차 → 서버 2차)
        ▼ ② 입력 Moderation
        │     └─ 차단 시: GM 캐릭터가 부드럽게 다른 표현 요청 (턴 소모 안 함)
        ▼ ③ Evaluator 등급 판정 (G0~G3)
        │     └─ G0(단답/대행 요청) 시: 스캐폴딩 되묻기 (턴 소모 안 함, 최대 2회 후 진행)
        ▼ ④ GM 서사 생성 (등급 → 스킬 보너스 반영, 상태 갱신)
        ▼ ⑤ 출력 Moderation
        ▼ ⑥ 핵심 씬이면 삽화 생성 큐 (등급 → 품질 티어), 비동기
        │
        ▼ [서사 텍스트 스트리밍 표시 → 삽화 도착 시 교체]
```

## 3. 기능 요구사항 (P0 EPIC별)

표기: **MUST** 없으면 MVP 무효 / **SHOULD** 파일럿 품질에 필요 / **MAY** 여유 시 · 각 EPIC 제목에 **[S0]** / **[S1]** 로 단계 표시

### EPIC A0 — [S0] 나침반 퀘스트 루프

**A0-1 장면 카드 세트**
- MUST: 카드 **20장 이상**, 각 카드 = 스케치 스타일 삽화(플레이스홀더 겸용) + 한 줄 상황 + 상황 명사 태그(스캐폴딩 질문 생성용)
- MUST: 상황은 "행동을 요구하는 열린 장면" — 위기·발견·만남 유형 균등. 정답 있는 퀴즈 형태 금지
- MUST: 카드 순서는 아이별 랜덤, 같은 카드 하루 1회 (재시도 제외)

**A0-2 단일 턴 입력 UI**
- MUST: 카드 + GM 캐릭터(기본 표정) + "탐험가는 어떻게 할까?" 자유 입력창. **선택지 없음** (Stage 0은 자유 입력만 검증)
- MUST: 글자 수 격려 표시 — 30자 넘으면 나침반 아이콘 밝아짐. 숫자 목표 표시 금지
  - **⚠ 「30자에서 가득 찬다」가 아니다** (2026-09-09 명확화 — **실제로 그렇게 읽혀 구현됐다**). **이 줄이 정하는 것은 문턱 하나다: 30자를 넘으면 확실히 밝아 보인다.** **그 앞뒤의 곡선 모양은 여기서 안 정한다** — 프론트가 정한다
  - **왜 적어 두나** — W2 구현이 **「가득 = 30」**으로 잡았고 **두 구간이 다 죽었다.** 초반 몇 글자에서 거의 안 변해 **아이가 「글자가 늘면 밝아진다」를 배울 기회를 놓치고**, **H2 합격선이 회당 150자인데 30 에서 멈춰** 우리가 실제로 원하는 구간(30~150)에 **신호가 없었다.** 사용자가 실기기에서 **「뭔지 모르겠다」**로 잡았다
  - **고친 뒤** — 30자 **0.65** · 150자에서 가득. **문턱은 지켜지고 두 구간이 산다.** **PRD 를 안 고쳐도 되는 것이 이 줄의 뜻이다**
- MUST: 태블릿 가로 / 모바일 세로

**A0-3 결과 연출**
- MUST: 등급별 삽화 티어 해금 (B-3) — 기본/희귀/전설. 플레이스홀더(스케치) → 생성 삽화로 전환 애니메이션
- MUST: GM 캐릭터 반응 표정 (C-2: G2 이상 "나침반 반응", G1 "기본", G0은 A-5 스캐폴딩)
- MUST: 입력문 위에 Evaluator가 감지한 묘사어 하이라이트 + 캐릭터 한 마디 ("'살금살금'이 나침반을 움직였어!")
- MUST: "다시 써보기" / "다음 카드" 버튼. 점수·등급 문자(G1 등)는 **절대 노출 금지** — 티어 이름과 삽화로만 표현

**A0-4 내 책 (앨범)**
- MUST: 카드별 최고 티어 삽화 + 그때 쓴 문장을 **책 페이지 프레임**(삽화 위·문장 아래, 페이지 번호)으로 보관·재열람. 화면 이름은 "내 책"
- MUST: 문장은 아이 원문 그대로. 맞춤법 교정·AI 보정 없음 (비전 ②)
- SHOULD: 티어별 획득 수 배지
- Stage 1에서 A-7로 확장 — 챕터가 책의 장이 되고, PDF로 내보낸다

**A0-5 일일 카드 제한**
- MUST: 하루 **5장** (재시도 제외). 소진 시 GM 세션 종료 컷 + "내일 또 보자" + 오늘 쌓인 책 페이지 미리보기
- MUST: 자정(기기 로컬) 해제. Stage 1에서는 D-2 일일 턴 상한과 **카운터를 공유** — 연습 모드 카드도 그날의 턴을 소모

### EPIC A — [S1] 핵심 플레이 루프

**A-1 GM 스토리 엔진**
- MUST: 판타지 장르 챕터 3개 (도입-위기-시련-완결 구조), 각 챕터는 사전 작성된 **뼈대(Beat Sheet)** 위에서 GM이 아이 입력에 맞춰 서사를 생성
- MUST: 서사 출력은 아동 눈높이 — 한 턴 150~300자, 문장은 짧게, 초5 교과 수준 어휘 + 판타지 고유명사
- MUST: 매 턴 끝에 선택지 2~3개 + "직접 쓰기" 유도 문구
- MUST: 아이의 입력 내용이 다음 서사에 **구체적으로 반영**됨 (아이가 쓴 명사·형용사를 되받아 씀)
- SHOULD: 텍스트 스트리밍
- 뼈대 위에서 생성하는 이유: 완전 자유 생성은 15턴 안에 시련까지 못 가고, 챕터 길이 통제(H1)가 불가능

**A-2 세션 상태 관리**
- MUST: 상태 스키마(4.2절)를 Redis에 유지, 턴마다 갱신, 챕터 완결 시 Postgres에 스냅샷
- MUST: 서사 요약기 — 최근 3턴은 원문, 그 이전은 3~4문장 요약으로 압축해 GM 컨텍스트 구성

- MUST: 중도 이탈 시 진행 상태 저장, 재접속하면 이어하기 (같은 날 1챕터 완결까지는 허용)

**D-2 일일 턴 상한**
- MUST: 기본 **15턴/일** (1챕터 12턴 + 스캐폴딩 여유). 상한 도달 시 하드 피니시와 동일 화면
- SHOULD: 학부모 설정에서 10~20턴 조정

### EPIC E — [S0] 안전 & 프라이버시 (E-5만 S1)

**E-1 입출력 양방향 Moderation**
- MUST: 입력 — 비속어·폭력·선정·자해 카테고리 감지. 차단 시 턴 미소모, GM 캐릭터가 다른 표현 요청 (오탐 시 아이가 다시 쓰면 됨)
- MUST: 출력 — GM 서사와 이미지 프롬프트 모두 검사. 차단 시 서사 재생성 (최대 2회, 실패 시 안전한 기본 서사로 대체)
- MUST: 판타지 전투 허용 범위 정의 — "물리친다·쓰러뜨린다" 허용, 유혈·고문·신체 훼손 묘사 금지. 화이트리스트 어휘로 오탐 완화
- MUST: 차단 이벤트 전량 로그 (`moderation_blocked`), 원문은 카테고리·해시만 저장
- **구조 미결 (W2 판정, `adr/0005`)**: LLM 프로바이더가 Gemini로 바뀌면서 안전 필터가 API 호출에 내장된다. 위 「입력/출력 별도 검사」 구조를 유지할지 내장 필터로 대체할지는 W2에 판정한다. 판정 기준은 `안전_어휘_기준.md` 2장 화이트리스트를 필터 임계값으로 재현할 수 있는가 — **미탐 0건을 유지하면서 오탐이 허용 범위**여야 한다. 못 넘기면 별도 단계를 유지한다

**자해·자살 신호 처리** (2026-09-07 대표 판정. `adr/0009` 가 열어 둔 자리다)

- **막는다.** 다른 차단과 같이 **카드 미소모 · 입력창 유지 · 아이가 쓴 문장을 지우지 않는다**
- **아이에게는 한 줄만 말한다** — 「지금 마음이 많이 힘들면, 옆에 있는 어른한테 꼭 말해줘.」 **설득하지 않고 더 대화하지 않는다.** 가이드는 상담자가 아니라 게임 마스터이고(C-1 「퀘스트 밖 자유 대화 없음」), 캐릭터가 아이의 실제 마음에 개입하면 **「가상 페르소나 의존」**(페르소나 4.4)이 정면으로 발생한다. **문안은 2026-09-07 에 확정됐다 — `docs/문구.md` 1.2.** 화면을 봐도 달라질 것이 없어(대표 판정 문장 그대로다) 나머지 대사보다 먼저 닫았다. **바꾸는 것은 「대표 몫」이다**
- **기록한다.** `moderation_blocked` 에 `category: self_harm`. **원문은 남기지 않는다 — 카테고리·해시만**(위 MUST 그대로). 차단된 문장은 책 콘텐츠가 되지 않는다
- **보호자에게 알린다 — 주간 리포트에 담는다.** 푸시 알림은 하지 않는다. 리포트 안에서 **어휘·글자 수 같은 성장 항목 사이에 묻히지 않게 별도 자리**에 놓는다. **원문은 보호자에게도 보여주지 않는다** — 아이가 그 사실을 알면 신뢰가 통째로 깨진다

**이유가 겹쳐 올 때 — 아이 쪽과 보호자 쪽을 가른다** (2026-09-07 대표 판정 ③)

검사가 돌려주는 이유는 **3장 이름 그대로 오지 않는다.** 「죽음 직접 묘사 및 자해·자살」처럼 **합쳐진 이름**이 온다 (W3 실측, `안전_어휘_기준.md` 6장). 자해가 뒤에 오면 묻혀서 아이가 일반 차단 문구를 받는다.

- **아이에게 나가는 한 줄은 자해가 이긴다.** 이름 안에 자해가 들어 있으면 순서와 무관하게 자해 문구다. **놓치지 않는 쪽을 택했다**
- **기록의 `category: self_harm` 과 보호자 주간 리포트는 자해가 단독일 때만 한다.** 합쳐져 온 것은 **다른 카테고리로 기록되고 보호자에게 가지 않는다**
- **왜 갈랐나** — 두 결과의 값이 다르다. 아이에게 한 줄 더 가는 것은 가볍지만, **보호자에게 잘못 알리는 것은 무겁다.** 원문을 보호자에게 보여주지 않기로 했으므로 **부모가 확인할 방법이 없다.** 하나의 스위치로 묶여 있던 것을 둘로 나눈 것이다
- **「자해가 섞였지만 단독이 아니라 안 셌다」를 로그에서 볼 수 있어야 한다** (PM 추가, 2026-09-07). 안 남기면 그 건이 **파일럿 전수 검토에서 아예 안 보인다** — 판정을 좁히거나 넓히는 것이 아니라 **판정대로 하면서 잃는 신호를 되살리는 것**이다
  - **모델이 돌려준 문자열을 그대로 싣지 않는다.** `category` 는 **모델이 자유롭게 채우는 필드**라 3장 이름을 적으라고 지시할 뿐 강제할 수단이 없다 — **아이 원문이 섞여 들어오면 그대로 로그 유출**이다 (1.1b). 「라벨이니 원문이 아니다」는 **모델이 늘 라벨만 돌려준다는 전제**인데 그 전제를 걸 수 없다 (2026-09-07 정정)
  - **우리 슬러그 표에서 만든다** — 알아본 것을 이어 붙여 `gore+self_harm` 꼴로 남긴다(`category_label`). 신호는 그대로 보이고, 잃는 것은 **표에 아예 없는 이름이 왔을 때의 원문**인데 그건 `unknown` 으로 남는다. **`SAFE_EXTRA_KEYS` 에 등록해야 나간다**

**한계 둘 — 알고 택한 것이다**

- **주간 리포트는 P1이라 파일럿 1(W6~7) 때는 없다.** 그 기간에는 **운영자가 기록을 직접 확인하고 보호자에게 연락한다** — 아이 10~30명 규모라 가능하다. 리포트를 P0 으로 당기면 파일럿이 또 밀린다
- **리포트 오픈율 목표가 70%다.** 정식 출시 후에도 **열지 않는 3할에게는 이 신호가 닿지 않는다.** 파일럿 뒤 재검토 항목으로 둔다


**E-2 PII 실시간 마스킹**
- MUST: 클라이언트 정규식 1차 (전화번호·이메일·**주소 패턴 — 번지·호수·숫자가 붙었을 때만**·**학교명 전체 꼴 `○○초등학교/중학교/고등학교`**) → 입력창에서 즉시 `○○○` 치환 + 안내 (**가림 글자·안내 문구는 `docs/문구.md` 1.1 이 SSOT**)
  - **「우리 학교는 ○○」 패턴과 학교명 줄임꼴(`○○초`)은 클라이언트에서 뺀다** (2026-09-07 정정, 프론트 구현 중 발견). 전자는 **「우리 학교는 마법학교야」**를, 후자는 **「마법약초」·「기초」**를 실시간으로 막는다 — 아이가 판타지 설정으로 쓸 말이 입력창에서 걸리는 것은 **「검을 휘두른다」가 막히는 것과 같은 급의 사고**다. 숫자 없는 지명(「은하시 별빛동」)도 같은 이유로 통과시킨다
  - **안전 수준은 내려가지 않는다.** **학교명은 서버 정규식이, 실명은 서버 2차(NER)가 잡는다** (2026-09-08 정정, 미결 11-6. 종전 「학교명·실명은 서버 2차(NER)가」). 클라이언트는 최종 판정이 아니라 **즉시 피드백**이고, 그 경계는 `공통규약.md` 「클라이언트 PII 패턴은 빌드 타임 상수다」에 있다
- MUST: 서버 2차 검사, 감지 시 **마스킹 후 처리** — **막지 않는다** (2026-09-08 대표 판정, 미결 11-5)
  - **NER(LLM 호출)이 맡는 것은 실명뿐이다** (2026-09-08 대표 판정, 미결 11-6). **종전 「NER 기반 실명·학교명」에서 학교명을 뺐다.** 학교명은 **서버 정규식이 결정적으로 잡는데 NER 은 같은 문장을 두 번 중 한 번 놓쳤다**(`api/benchmarks/W3-ner-cost.md`) — **중복이면서 더 불안정하다.** 안전 수준은 안 내려간다: 잡는 주체가 바뀐 것이지 안 잡는 것이 아니다
  - **자녀 닉네임·가이드 이름은 화이트리스트로 뺀다.** 서버가 이미 아는 값이라 **호출 없이 오탐을 줄인다**
  - **정확도는 아직 안 쟀다.** 단가 실측 12회는 정확도 표본이 아니다 — **E-1 처럼 시나리오를 만들어 따로 잰다**
- MUST: 마스킹 전 원문은 어디에도 저장하지 않음

**E-3 익명 가입 & 난수화 ID**
- MUST: 자녀 계정 = UUID + 닉네임 + 연령대. 그 외 필드 없음
- MUST: 닉네임도 PII 검사 통과 필수

**E-4 학부모 계정 연동**

- MUST: **동의 화면에 LLM 처리 위탁을 고지한다** (1.1b v4) — 아이가 쓴 문장이 평가를 위해 Google Gemini API로 전송되며, 학습에는 쓰이지 않으나 남용 탐지 목적으로 제한 기간 보관된다는 사실. 실명·학교명 등 개인정보는 전송 전에 걸러진다는 점도 함께. **`labeling_consent`(선택)와 구분한다** — 이건 서비스 제공에 필수라 거부 시 이용 불가이고, 라벨링 동의는 거부해도 이용 가능하다
- MUST: 학부모 화면 — 자녀 계정 목록, 오늘 플레이 여부, 일일 턴 상한 설정(SHOULD), 계정 삭제
- MUST: 계정 삭제 시 자녀 데이터 즉시 파기
- 대시보드·성장 데이터는 **표시하지 않음** (P1)

**E-5 [S1] 데이터 보관·파기** (1.1b 원칙 적용)
- MUST: **아이 입력 원문은 책 콘텐츠로 보관** (`card_attempts.text`, `book_pages`). 파기 시점은 계정 삭제 또는 90일 비활성뿐

- MUST: 90일 비활성 계정 자동 파기 배치 (일 1회) — 책 포함 전량. 파기 7일 전 학부모 이메일 고지 + PDF 내보내기 안내
- MUST: 라벨링(B-2) 목적의 원문 활용은 학부모 동의 항목. 미동의 계정은 라벨링 셋에서 제외. 라벨링 사본은 파일럿 종료 후 파기
- Stage 0: 90일 배치 없음. 파일럿 1 종료 시 라벨링 사본만 수동 파기, 책 콘텐츠는 유지 (파일럿 2 재참여 코호트의 베이스라인)

### 4.0 Stage 0 캐릭터 대사 생성 (경량)

  "key_scenes_done": ["intro"]

### 4.3 Evaluator 루브릭 (G0~G3)

| 등급 | 정의 | 판정 신호 | 예시 |
|---|---|---|---|
| **G0** 대행/단답 | 행동이 없거나 AI에게 떠넘김 | 10자 미만, "알아서 해줘/써줘", "응/몰라", 선택지 번호만 | "공격", "그냥 가", "네가 정해" |
| **G1** 기본 행동 | 행동 동사 1개, 대상 있음, 묘사 없음 | 주어/동사/목적어 수준, 형용사·부사 0개 | "괴물을 검으로 공격한다", "문을 연다" |
| **G2** 구체 묘사 | 행동 + 방법·도구·감각 중 1~2개 | 형용사·부사 1~2개 또는 "~하면서/~하게" 절 | "은빛 검을 들고 괴물의 다리를 재빨리 벤다" |
| **G3** 풍부한 묘사 | 행동 + 방법 + 감각/감정/의도 중 2개 이상, 장면이 그려짐 | 묘사어 3개 이상, 복문, 이유·감정 포함 | "은빛 갑옷이 달빛에 번쩍이는 걸 보고, 나는 숨을 죽인 채 괴물 뒤로 살금살금 돌아가 무거운 검을 힘껏 휘두른다" |

규칙
- 길이는 보조 신호. 긴 단답("공격공격공격…")은 G0
- 맞춤법·띄어쓰기 무시. 초5 수준 오타는 정상 입력으로 처리
- 창의적이지만 뼈대를 벗어난 입력(예: "갑자기 우주선을 탄다")은 등급대로 판정하되 GM이 서사로 흡수
- 출력: `{grade, signals: ["adj:은빛","adv:재빨리","clause:방법"], descriptors: [...]}`

### 4.4 스캐폴딩 질문 템플릿 (G0 시)
캐릭터가 나침반을 보며 **질문 1개**만. 상황의 명사를 넣어 생성.
- 도구/방법: "나침반이 안 움직이네. **{대상}**을 어떻게 할 건지 조금만 더 말해줄래?"
- 감각: "{장소}에서 뭐가 보이고 들리는지 나침반한테 알려줘!"
- 감정/의도: "탐험가는 지금 어떤 기분이야? 왜 그렇게 하려는 거야?"
- 대행 요청 시: "이건 탐험가의 모험이라 나침반은 네 말만 들어. 딱 한 문장만 써볼래?"
금지: "부족해", "다시 써", "틀렸어", "더 길게"

### 4.5 LLM 역할별 요구사항 (모델 결정은 9장)
| 역할 | 요구 | 우선순위 |
|---|---|---|
| GM | 긴 컨텍스트(요약+최근 3턴+뼈대), 롤플레이 일관성, 한국어 아동 어휘, JSON 출력, 스트리밍 | 품질 > 속도 |
| Evaluator | 1.5초 이내, 저비용, few-shot 분류, 구조화 출력. **thinking budget 최소, few-shot 예시셋은 context caching** | 속도·비용 > 품질 |
| 상태 추출기 | 구조화 출력, 저비용 | 비용 |
| Safety | 카테고리 분류, 매우 저지연 | 속도. **구조 미결** — Gemini 내장 안전 필터로 대체할지 별도 단계를 둘지 W2 검증 (`adr/0005`) |
| 이미지 | 고정 스타일 태그·시드 지원, 10초 내 | 일관성 > 화질 |

**모델 선정 시 확인할 것** (W1 스모크에서 드러난 것, `adr/0005`)
- **`thinking_budget` 설정을 모든 모델이 받지 않는다.** 400으로 거부하는 모델이 있고, 0을 줘도 출력 토큰이 요동쳐 사실상 추론을 계속하는 모델이 있다. **「최소」는 목표이지 보장이 아니다** — 실측 지연으로 판단한다
- **context caching 미지원 모델이 있다.** 예시셋 40개가 붙는 실사용 조건에서는 이 하나가 비용 순위를 뒤집는다

**`moderation_blocked` 의 해시 필드는 `text_hash` 다** (2026-09-08 확정. 종전 `hash`). 코드·로그·테스트가 이미 `text_hash` 를 쓰고 있어 갈렸고, **백엔드가 고치지 않고 알려 와 여기서 골랐다.**
**코드에 맞춘 것이 아니라 이 문서 안의 두 표기 중 다수를 택한 것이다** — 6장 데이터 모델이 `access_code_hash` 를 쓴다. **`<대상>_hash` 가 이 문서의 관례이고 맨 `hash` 가 예외였다.**
**무엇을 해싱했는지가 이름에 있어야 하는 이유는 그 대상이 아이 원문이기 때문이다.** 「원문은 남기지 않고 카테고리·해시만」(4.4절 MUST)을 나중에 감사할 때, **그 필드가 정확히 무엇의 해시인지가 이름에서 보여야** 한다.
**계약(`/openapi.json`)이 아니라 집계 쿼리가 보는 이름**이라 바꾸는 값이 싸다 — **그래서 지금 고르는 것이 가장 싸다. 두 이름이 살아 있는 동안 쓴 쿼리가 나중에 조용히 빈 결과를 낸다.**

**`[S1]` 마커를 둘에 붙였다** (2026-09-08). `chapter_start`·`chapter_complete` 는 **챕터가 있어야 남는 값**이라 Stage 0 에서는 담을 것이 없는데 **이 표에서만 마커가 빠져 있었다.** 그래서 W3 의 F-1 완료 조건이 **「10종」으로 서 있었고 Stage 0 에서 달성 불가능한 숫자**였다 — **백엔드가 8종으로 닫은 것이 범위를 좁힌 것이 아니라 계획의 숫자가 틀렸던 것**이다. **마커가 빠진 자리가 곧 그 오류의 뿌리다.**

**`char_len` 의 정의 — 공백 포함 원문 길이** (2026-09-07 확정). 아이가 친 문자를 그대로 센다. **여기서 「원문」은 PII 마스킹 뒤 텍스트다** — 서버가 책 콘텐츠로 저장하는 것이 그것이므로 **화면의 30자·로그의 `char_len`·책의 문장이 같은 문자열을 세야 한다**. 공백·줄바꿈을 걷어낸 값은 **아이가 쓴 문장이 아닌 것을 재는 값**이고, H2 합격선(150자 · 2주차 80자)이 그 정의 위에 서 있다. **입력 화면의 「30자에서 나침반이 가득 찬다」도 같은 정의를 쓴다** — 화면이 세는 수와 로그가 세는 수가 갈리면 아이가 채운 감각과 우리가 재는 숫자가 달라진다. `tutorial_complete` 의 `char_lens[3]` · `scaffold_triggered` 의 `next_char_len` 도 같다.

- **추정이 크게 빗나갔다. 5일치로 잡은 개발이 하루에 끝났다** (백엔드 6 · 프론트 8). 그래서 **W3를 09-14 → 09-07로 앞당겼다.** 주차 범위 변경이라 대표에게 사후 보고했다. **다만 W3는 인증·안전이라 같은 속도가 안 난다** — 개발 환경 전환과 대표 판단 대기가 벽이다
- **C-2가 완료 조건을 못 넘긴 채 닫혔다.** 「아동 3명에게 신규 선호 확인」인데 1차 6:6, 2차 2:2다. **기존 세트가 네 상태를 표현하지 못해 애초에 후보가 아니었으므로**(「조용할 때」와 「흐려질 때」의 픽셀 평균 차이 2.6/255) 판정 근거를 **선호에서 기능으로 바꿔** 확정했다. 남은 얼굴 축은 W4 화풍(B-5)으로 이관 (`docs/캐릭터/비교_결과.md`)

- **하루에 「조용히 어긋나는」 사고가 여섯 번 났다** — 한글 토큰 · env 이름 · Makefile 배관 · 계약 드리프트 · vitest 별칭 · `make certs` 절반 실행. **여섯 다 화면이나 오류 메시지가 원인을 안 가리켰다.** 넷은 그 자리에서 장치를 붙였다(브라우저 검증 · 원인 구분 · 계약 CI · 스크립트 자기검사). **W4에서 「확인 장치가 없는 자리」를 훑는다**
- **계획 문서 안에서도 같은 부류가 셋 났다** — 범위 표와 작업 쪼갬과 진행 현황이 서로 어긋났고 셋 다 개발자가 잡았다. **한 문서 안에서 같은 사실을 세 곳에 적는 구조 자체**를 W4에 손본다

**W1 실제와의 차이** (2026-09-06 갱신)
