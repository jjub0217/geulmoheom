# 글모험 — 시스템 아키텍처 및 구현 난이도 (v2)

갱신일: 2026-08-29 · 기준: `MVP_PRD.md` 1.5 확정 스택 및 Stage 0/1 구조 · v1의 모델명·병기 스택은 PRD 결정에 맞춰 정리함

---

## 1. 구현 가능성 (Feasibility): 매우 높음

* **기술적 성숙도**: LLM의 롤플레잉·구조화 출력 능력과 고속 이미지 생성 API의 발전으로, 텍스트 기반 분기형 서사와 등급 연동 삽화 생성은 즉시 구현 가능하다.
* **비용 통제 가능성**: Stage 0은 LLM 호출이 **Evaluator 1회 + 이미지 1장/카드**로 고정되어 세션당 비용 예측이 정확하다. Stage 1도 이미지를 챕터당 핵심 씬 4곳으로 제한하고 캐시 에셋을 재사용해 통제한다 (PRD 7장 세션당 비용 상한).
* **단계적 리스크 축소**: 가장 비싼 컴포넌트(GM 엔진·상태 관리)는 Stage 0에서 Evaluator·보상 루프가 검증된 뒤에만 구축한다. Stage 0에서 만든 컴포넌트는 Stage 1에 전량 재사용된다.
* **시장 확장성**: 웹(Next.js PWA) 기반으로 출시 후 앱 패키징이 용이하며(P2 H-8), 완결 스토리의 PDF 렌더링(P1 G-3)으로 오프라인 부가가치 창출이 가능하다.

## 2. 시스템 아키텍처 (확정 스택)

### 2.1 구성

| 층 | 선택 | 역할 |
|---|---|---|
| **클라이언트** | Next.js (App Router) PWA, TailwindCSS, Zustand | 태블릿 가로 우선 반응형 UI, 타이핑 애니메이션, 클라이언트 1차 PII 마스킹, 서사 스트리밍 수신 |
| **백엔드** | **FastAPI** (Python) | API, 세션·잠금 로직, 이벤트 로깅, 학부모 계정·동의 |
| **에이전트 오케스트레이션** | LangGraph 상태 머신 | Evaluator → GM → 상태 추출기 → Safety 노드 체인. Stage 0은 Evaluator 단일 노드 |
| **LLM** | 역할별 요구사항으로 정의, 모델명은 구현 시 벤치 후 확정 (PRD 4.5) | GM / Evaluator / 상태 추출기 / Safety |
| **이미지** | Replicate / Fal.ai 계열 API | 고정 스타일 태그·시드 지원, 티어별 프롬프트 접미어, 10초 내 생성 |
| **Safety** | 전용 Moderation API 우선, 필요 시 LLM 분류 보조 | 입출력 양방향 검사, 판타지 전투 화이트리스트 |
| **DB** | PostgreSQL (SQLAlchemy) | parents / children / cards / card_attempts / chapters / sessions / artworks / events (PRD 6장) |
| **캐시** | Redis | `state:{session_id}` 게임 상태 (TTL 24h), 일일 카드·턴 카운터 |
| **스토리지** | Cloudflare R2 | 삽화, 카드 스케치 |
| **배포** | 단일 컨테이너 (Fly.io / Railway 급), dev/pilot 환경 분리 | 파일럿 규모. API 키 서버 보관, 일 비용 알람 |

### 2.2 요청 흐름

**Stage 0 — 나침반 퀘스트 (LLM 1회 호출)**
```
클라이언트 ── 입력(1차 PII 마스킹) ──> FastAPI
  ├─ 2차 PII 검사 (NER)
  ├─ 입력 Moderation
  ├─ Evaluator (등급 + 묘사어 태그)          ← 유일한 LLM 호출
  │     └─ G0 → 스캐폴딩 템플릿 조립 (LLM 없음) → 응답
  ├─ 캐릭터 대사 템플릿 치환 (LLM 없음)
  ├─ 이미지 생성 큐 (비동기, 티어별 프롬프트) → R2
  ├─ 이벤트 로깅 → Postgres
  └─ 응답 (등급 → 티어, 하이라이트, 대사) ── 삽화는 완료 시 푸시
```

**Stage 1 — TRPG (LangGraph 체인)**
```
입력 → PII → 입력 Moderation → Evaluator → GM 서사 생성(스트리밍)
     → 상태 추출기(구조화 출력) → 출력 Moderation → [핵심 씬] 이미지 큐
     → Redis 상태 갱신 → 로깅 → 응답
GM 컨텍스트 = 시스템 프롬프트 + 챕터 뼈대 + 상태 JSON + 서사 요약(3~4문장) + 최근 3턴 원문
```

### 2.3 데이터 보관 원칙 (`페르소나정의.md` 7.4)

* 아동 입력 원문은 **로그에 저장하지 않는다**. `events`는 수치·등급·태그만
* Stage 0 `card_attempts` 원문은 파일럿 동의 하에 별도 보관, 파일럿 종료 시 파기
* Stage 1 턴 원문은 챕터 완결 시 요약 스냅샷만 남기고 Redis에서 파기
* 90일 비활성 계정 자동 파기 배치 (Stage 1 E-5)

## 3. 영역별 구현 난이도

| 영역 | Stage | 난이도 | 핵심 과제 및 해결 방안 |
|---|---|---|---|
| **Evaluator 등급 판정의 신뢰성** | 0 | **중상** | 만 10~12세 눈높이에서 G0~G3 경계를 일관되게 긋는 것. 코드보다 **루브릭·few-shot 예시셋 튜닝**이 병목. 파일럿 1주차 실제 입력 50개 이상 수동 라벨링 → 일치율 80% 목표 (PRD B-2) |
| **스캐폴딩 톤 제어** | 0 | **중** | 되묻기가 "꾸중"으로 읽히면 글쓰기 울렁증 페인포인트를 건드림. 부정어 금지 템플릿 + 캐릭터 표정으로 통제 (PRD 4.4). 아동 프리테스트 필수 |
| **비주얼(화풍) 일관성 유지** | 0 | **중** | 씬마다 캐릭터 외형이 바뀌는 문제. 캐릭터 색상코드·외형 태그를 시스템 레벨에서 강제 주입 + 동일 시드 계열 (PRD B-5). 이미지 모델 교체 실험 시간 필요 |
| **이미지 지연·실패 처리** | 0 | **하** | 15초 초과 시 스케치 플레이스홀더 유지, 캐시 기본 에셋 폴백. 플레이 중단 없음 |
| **아동 안전 및 필터링** | 0 | **중** | 아이들의 돌발 입력("똥", 게임 은어)에 대한 오탐과 유해 서사 미탐 사이의 균형. 판타지 전투 허용 어휘 화이트리스트 + 입출력 양단 검사. 실사용 로그 없이는 조정 불가 |
| **스토리 일관성 및 상태 관리** | 1 | **중상** | 세션이 길어질수록 GM이 앞선 설정을 잊는 문제. 서사 요약기와 상태 JSON 추출기를 **별도 호출로 분리**, 챕터 뼈대(Beat Sheet)로 진행을 고정. 완전 자유 생성은 15턴 내 보스 도달을 보장하지 못함 |
| **챕터 길이 통제 (15~20분)** | 1 | **중** | 턴 12 도달 시 `force_resolution` 플래그로 강제 완결 국면 전환 (PRD 4.6). 뼈대 없이는 불가능 |
| **하드 피니시·일일 상한** | 1 | **하** | Redis 카운터 + 자정 해제. 기술 난도는 낮지만 "다음 챕터 제목만 예고" 등 이탈 설계가 중요 |
| **PDF 전자책 렌더링** | P1 | **하** | Puppeteer 또는 React-PDF로 텍스트·삽화를 템플릿에 조립 |

**난이도 총평** — 기술적으로 어려운 부분은 없다. 시간을 먹는 것은 **프롬프트 튜닝과 아동 실사용 테스트**(Evaluator 루브릭, 스캐폴딩 톤, Moderation 경계)이며, 이 세 가지가 모두 Stage 0에 있다. Stage 0을 먼저 두는 이유가 여기 있다.

## 4. v1 대비 변경 사항

| 항목 | v1 | v2 |
|---|---|---|
| 백엔드 | FastAPI 또는 NestJS 병기 | **FastAPI 확정** (에이전트 체인과 동일 언어) |
| LLM | GPT-4o-mini / Claude 3.5 Sonnet 명시 | 모델명 제거, 역할별 요구사항으로 정의 (PRD 4.5) |
| 구조 | 단일 MVP | **Stage 0 (Evaluator 단일 호출) → Stage 1 (LangGraph 체인)** |
| ORM | Prisma | SQLAlchemy (Python 스택 통일) |
| 스토리지 | AWS S3 / Cloudflare R2 병기 | Cloudflare R2 확정 |
| Safety | NeMo Guardrails 또는 자체 | 전용 Moderation API 우선 |
| 난이도 표 | 4개 영역 | Stage별 9개 영역, 튜닝 병목 명시 |
