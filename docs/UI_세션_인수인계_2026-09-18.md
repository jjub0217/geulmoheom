# 글모험 UI 작업 — 새 세션 인수인계

작성: 2026-09-18. 이 문서는 장기간의 UI 대화에서 확정한 요구, 구현 상태, 검증 근거를 정리한 작업 기록이다. 대화 원문 전체를 복사한 것은 아니다. 이후 사용자 지시와 실제 파일 상태가 우선한다.

**최신 상태는 32절이다.** 사용자가 원하는 책 외관의 기준은 `book-kraft-desktop-2026-09-18.png`라고 명시했다. 아래로 여러 장이 겹친 종이층은 원하지 않는다. 14절의 갈색 외곽과 15절의 3·5·7px 종이층을 다시 적용하지 않는다. 현재 큰 삽화·글 배치에는 지정 캡처의 얇은 경계·부드러운 그림자·좁고 은은한 접힘을 적용했다. 17절에서는 삽화의 8px 종이 여백을 없애고 양쪽 면의 쪽 번호를 복원했으며, 아래의 위치·전체 쪽 수 문구는 화면에서 제거했다. 18절에서는 삽화에 가려지던 가운데 음영을 두 면 위로 이어 접힘이 보이도록 보강했다. 19절에서는 사용자 피드백에 따라 그 음영의 폭과 농도를 더 높였다. 20절에서는 귀환·인쇄 버튼을 모두 책 아래로 옮겼다. 1~19절 캡처는 당시 기록이다.

## 1. 새 세션에서 바로 이어갈 일

프로젝트: `/Users/osejin/Documents/geulmoheom`

실제 확인 주소: `https://app.geulmoheom.test:3005/book`

사용자는 이 파일을 읽고, **2절의 7개 개선 기준에 맞춰 `/book`의 실제 화면을 확인하고 부족한 부분을 이어서 수정·검증**하기를 원한다. 이 방향은 이미 승인됐다. 기존 구현을 지우고 처음부터 다시 만들거나, 이미 반영한 항목을 미완료로 오인하지 않는다.

시작 순서:

1. 이 문서, 현재 `git status`, 관련 소스, 최신 검증 캡처를 읽는다.
2. `/book`을 실제 3005 주소의 새 브라우저 컨텍스트에서 확인한다. 브라우저 검사에서는 API를 모의 처리한다.
3. 현재 구현과 2절의 개선 기준을 대조한다. 새 사용자 스크린샷이 있으면 그것을 우선 비교한다.
4. 재현되는 부족한 부분을 승인된 방향 안에서 수정하고, 관련 기능과 화면을 확인한다. 제안만 남기고 끝내지 않는다.
5. 이미 만족하는 부분은 보존한다. 문제가 없으면 억지로 다시 바꾸지 않고 확인 결과를 알린다.

사용자는 해커톤에 출품할 실제 서비스 수준의 UI를 원한다. 시각적 완성도뿐 아니라 아이가 무엇을 읽고 무엇을 눌러야 하는지 이해할 수 있어야 한다. 사용자는 반복 승인 요청과 추상적 제안만 받는 것을 원하지 않는다.

## 2. 사용자가 특별히 이어가 달라고 한 `/book` 개선 기준

사용자는 이전 답변의 다음 문장 **뒤에 제시된 개선 방향**을 계속 적용할 수 있도록 요청했다.

> 이번 메시지에는 스크린샷이 아직 첨부되지 않아, 현재 코드와 직전에 확인한 화면을 기준으로 분석했습니다. 아이의 실제 사용을 관찰한 결과가 아닌 디자인 판단입니다.

그 뒤 분석은 아래의 **일곱 요소**에 관한 것이었다. 이후 사용자가 스크린샷을 보내고 “좋아요. 그렇게 해주세요 … 같이 참고해서 수정해주세요”라고 승인했으며, 1차 반영과 검증을 마쳤다.

| 요소 | 승인된 개선 방향 | 현재 반영 상태 / 계속 확인할 점 |
|---|---|---|
| **책 이름 — 예: 지니의 모험** | 서비스 화면 제목보다 **아이의 책 이름**으로 읽혀야 한다. 펼친 책 바로 위에 지은이와 묶고, 중앙 정렬하되 상단이 너무 높아 본문을 밀어내지 않게 한다. | 중앙 배치, 28~36px 범위, 굵기 700. 서버의 `book.title` 그대로. 긴 책 이름에서도 겹침·잘림 없이 자연스럽게 줄바꿈되는지 확인한다. |
| **지은이 지니** | 책 이름 바로 아래 가까이 둔다. 제목과 같은 무게로 과하게 강조할 필요는 없다. | 같은 중앙 묶음, 기본 18px / 좁은 화면 16px. **`book.author`를 사용**하며 `/child/me` 별명으로 대체하지 않는다. |
| **책 이름 바꾸기** | 오른쪽 멀리 떨어진 밑줄 링크 대신 책 이름 가까이에 **연필 아이콘이 있는 작은 버튼**을 둔다. | 지은이 바로 아래에 배치. 기존 `PATCH /book`, 서버 응답값 반영, 개인정보 마스킹, 빈 이름 방지 유지. 편집을 열면 입력칸에 포커스가 간다. 책 전체 이름을 바꾸는 기능이며 페이지의 글을 고치는 기능이 아니다. |
| **부모님께 보내기** | 실제 기능과 이름을 맞춘다. 현재는 부모에게 전송하지 않고 인쇄 창을 열므로 **책 인쇄하기**가 정확하다. 상단의 도구와 마지막 쪽 아래에서 찾을 수 있게 한다. | **책 인쇄하기**로 변경, 프린터 아이콘, 상단 오른쪽과 하단에 동일 기능. `window.print()` 유지. 빈 책에는 인쇄 버튼이 없다. 실제 메시지 전송·공유 기능을 추가한 것이 아니다. |
| **쓰러 가기** | 일일 모험 종료 후 누르면 글쓰기 대신 배웅 화면으로 돌아갈 수 있다. 즉시 쓰기를 약속하는 이름보다 **모험으로 돌아가기**가 정확하다. 상단에서도 바로 찾을 수 있어야 한다. | **모험으로 돌아가기**로 변경, 왼쪽 화살표, 상단 왼쪽과 하단. 경로는 `/` 그대로. 빈 책에도 상단과 안내 안에 있다. 일일 제한을 해제하거나 자동으로 새 모험을 시작하지 않는다. |
| **아이가 쓴 글** | 삽화 밑의 작은 설명문으로 느껴지지 않도록 존재감을 높인다. 일반 한글 글꼴을 유지하고, 과한 굵기 대신 크기·줄폭·간격으로 읽기 좋게 한다. | 20~24px, 굵기 400, 행간 1.8. 본문 너비 최대 28rem. 종이 자체에 **짙은 파란색 `#2b4a6f`**을 지정해 다크모드의 밝은 글자를 물려받지 않는다. 원문·줄바꿈 그대로, 요약/교정/칭찬 문구 추가 없음. |
| **삽화의 크기와 비율** | 원본 비율과 전체 그림을 보존한다. 세로 삽화가 좁게 보여 여백이 과했던 점을 개선하되, 그림만 키워 아이 글을 화면 아래로 밀어내지 않는다. | 책 최대 폭을 72rem으로 정리하고, 그림 높이와 페이지 여백을 함께 조정했다. 원본 URL·실제 비율·`object-contain` 유지. 세로 그림과 정사각형/가로 그림, 그림이 없는 페이지가 섞여도 확인해야 한다. |

우선순위: **문구와 실제 동작 일치 → 제목과 편집 도구의 연결 → 글과 삽화의 크기 균형**.

UI 검사 통과가 “실제 아이들이 즉시 이해했다”는 증거는 아니다. 지금까지의 분석은 디자인 판단과 기능 확인이다. 아이 사용 관찰을 했다고 말하지 않는다.

## 3. 최신 `/book` 구현 상세

### 구조와 파일

- `web/src/app/book/page.tsx`: `.book-shell` → `.book-library`, 상단 귀환/중앙 표지·편집/우측 인쇄, 책 페이지, 하단 도구.
- `web/src/styles/book.css`: 크래프트 배경, 밝은 펼친 책, 명시적인 밝은 테마와 글자색, 반응형 배치, 인쇄 스타일.
- `web/src/components/book-actions.tsx`: 새 공통 버튼 컴포넌트. `책인쇄라벨`, `모험복귀라벨`을 export한다. 위아래에서 재사용한다.
- `web/src/components/book-title.tsx`: 기존 책 이름 편집에 연필 아이콘과 편집 시작 포커스를 더했다.
- `web/src/components/book-page.tsx`: `page.artwork_url`, `page.text`, `page.page_no`, `page.tier`를 그대로 사용한다. 이미지 로드 후 실제 비율로 액자를 맞춘다.
- `web/e2e/book.spec.ts`: 새 버튼 이름과 중복 배치, 두 인쇄 버튼의 실제 호출, 귀환 경로, 빈 책, 편집 포커스 검사를 기존 검사에 반영했다.
- `docs/문구.md` 1.13·1.17: 사용자 승인에 맞춰 귀환/인쇄 라벨과 의미를 갱신했다.

### 현재 값

- 책 전체 최대 너비: `72rem` (1152px, 바깥 패딩 포함).
- 넓은 화면: 펼친 책 두 쪽. 좁은 화면: 한 쪽씩 세로 읽기.
- 그림 높이 상한: `clamp(18rem, calc(100svh - 24rem), 32rem)`.
- 560px 이하: 그림 높이 `min(26rem, 48svh)`, 페이지 패딩 20px, 화면 위 패딩 16px.
- 본문: `clamp(1.25rem, 2vw, 1.5rem)` = 20~24px. 1024px 화면에서는 20.48px이며 의도한 반응형 값이다.
- 종이 본문 원문을 바꾸지 않는다. 페이지 번호도 배열 인덱스가 아니라 서버의 `page_no`다.
- 인쇄: 배경 질감, 제목 편집, 이동/인쇄 버튼을 숨긴다. 책 이름·지은이·삽화·아이 글 등 책 내용은 남긴다. 이미지 전체를 보존한다.

### 최신 검증 결과

- 격리 프로덕션 빌드 + TypeScript 검사 통과.
- 변경 TSX 및 책 E2E lint 통과.
- 기존 unit 107개 통과.
- 핵심 책 E2E 16개: 8개 시나리오 × 태블릿/모바일 통과. 상단/하단 인쇄 호출, 귀환 2개, 빈 책 인쇄 0개, 편집 포커스 포함.
- 실제 **3005 주소**에서 API를 모두 모의 처리한 시각 검사 8사례 통과: 1280×800, 2524×1286, 360×640, WebKit 1024×748, 빈 책, 긴 제목/본문 등.
- 시각 검사 전부 다크모드 환경에서도 밝은 종이 + 짙은 글자 유지. 측정 대비 약 6.21~8.93:1.
- 1280×800: 첫 문단 y≈658~744px로 전체 노출.
- 마지막 모바일 조정 후 360×640: 첫 원문 y≈573px, 첫 줄 전체가 보임. 세로 삽화 높이 약 307px, 원본 비율 유지.
- **매우 긴 무공백 3줄 제목**의 모바일 사례는 본문이 y≈651px부터 시작하므로 세로 스크롤이 필요하다. 잘림이나 가로 넘침은 없다. 모든 긴 내용을 첫 화면에 강제로 압축하려고 글자를 과하게 줄이지 않는다.

현재 미커밋 상태다. 이 검증은 현재 워킹 트리의 로컬 검증이며 운영에 배포됐다는 뜻이 아니다.

## 4. 스크린샷과 실행 화면이 달랐던 문제

사용자가 15:01경 보낸 화면에는 네이비 배경 + 밝은 책 종이 + 거의 보이지 않는 밝은 글자가 있었다. 당시 최신 코드의 `.book-shell`과 엠블럼도 보이지 않아, 새 JSX 대신 이전 화면 상태에 CSS 일부만 반영된 모습과 비슷했다.

다만 **브라우저 캐시가 원인이라고 확정하지 않았다.** 같은 실제 3005 주소를 새 Chromium 컨텍스트와 다크모드로 열었을 때는 크래프트 배경과 짙은 글자가 정상이고 런타임 오류가 없었다. 서버 이상이나 전역 CSS 덮어쓰기는 재현되지 않았다.

최신 변경은 `.book-library`에도 밝은 테마 변수를 지정하고, `.book-page` 자체에 글자색을 명시해 밝은 종이가 외부의 밝은 글자를 상속하지 않게 했다. 최종 UI에서는 책 엠블럼을 제거하고 제목·지은이·편집을 중앙에 묶었다.

새 세션에서도 사용자 스크린샷과 다르면 **같은 주소의 새 탭/새 컨텍스트에서 먼저 비교**한다. 확인 없이 서버를 재시작하거나 CSS 값을 계속 덧대지 않는다.

## 5. 왜 책의 그림이 모두 같았는가

확인한 사실:

- 현재 로컬 서버는 `web/e2e/_서버하네스.mjs`의 **`E2E_SHOW=1` 보여주기 모드**였다.
- 하네스가 시작할 때 샘플 이미지 한 파일을 읽고, 가짜 Gemini가 모든 이미지 요청에 동일 이미지 바이트를 반환한다.
- 관련 코드: 하네스의 `보여줄그림고르기` 및 가짜 앞단 시작 부분, `api/tests/fake_gemini.py`.
- 책 UI는 각 페이지의 `artwork_url`을 그대로 사용한다. 같은 URL을 강제로 붙이는 코드가 원인이 아니다.
- 현재 설정은 프로세스의 비밀값을 출력하지 않고 확인했다. 실제 책의 DB와 각 기존 이미지의 생성 이력을 조회한 것은 아니다.

**같은 샘플 그림이 보인다고 임의로 다른 그림으로 바꾸거나, 유료 생성으로 전환하거나, 저장된 책을 다시 생성하지 않는다.** 사용자는 삽화를 바꾸지 말라고 명시했다. 실제 생성 모드 전환은 UI 수정에 포함하지 않는다.

검사용 세로 샘플: `.artworks/artworks/c01_legendary-df4827e79bbad031.jpg`. 이는 기존 사전 제작 샘플이며, 최신 모의 화면에서도 이 파일을 사용했다.

## 6. 이전 대화에서 확정한 전체 UI 방향

### 글쓰기 화면

- 초기 네이비 화면의 큰 카드/입력칸 위주 구성은 사용자가 거부했다.
- 포켓몬과 육성 시뮬레이션 화면은 **장면을 화면 가득 보여주고 캐릭터·대화·응답이 이어지는 배치**를 설명한 예다. 게임 화면이나 캐릭터를 복제해 달라는 요청이 아니다.
- 브라우저를 채운 숲 배경, 투명 배경의 레서판다, 가까이 붙은 말풍선, 화면 아래의 중앙 글쓰기 패널을 사용한다.

## 12. 한 장면을 삽화 면·글 면으로 펼치기 — 2026-09-18 사용자 승인

사용자가 실제 그림책 참고 사진 두 장을 주고, 한쪽 면에 삽화·다른 면에 해당하는 글과 배지를 두는 방향을 승인했다. 동시에 **사전 안내 없는 배지가 아이에게 충분한 설명인지 의견**을 물었다. 책 배치 변경은 구현 요청이고, 배지의 의미·설명 방식은 의견 요청이다.

### 현재 책 화면

- **한 서버 레코드 = 한 장면 = 한 펼침**이다. 896px 이상에서 같은 장면의 삽화를 왼쪽, 원문과 배지를 오른쪽에 둔다. 모바일은 같은 장면의 삽화 아래에 원문을 둔다. 모든 화면에서 한 번에 한 장면씩 이동하며 폭을 바꿔도 같은 장면을 유지한다.
- 오른쪽 글은 충분한 여백을 두고 가운데 높이 부근에 왼쪽 정렬한다. 배지는 오른쪽 아래, 서버 쪽 번호는 왼쪽 아래다. 본문은 20~26px/400·행간 1.8·최대 26rem이다. 원문과 줄바꿈은 그대로다.
- 왼쪽 면을 삽화에 내주되 **원본 전체 비율·URL·`object-contain`을 유지**한다. 정사각 삽화는 면을 거의 채우고 세로·가로 삽화의 남는 자리는 크래프트 종이로 둔다. 삽화가 없으면 글이 펼침 전체를 사용한다.
- 화면의 모든 장면은 같은 높이를 유지한다. 가장 긴 장면이 공통 높이를 결정하며 짧은 글에는 여백이 남는다. 대표 여섯 장면은 1280px에서 모두 약 578px, 360px에서 모두 약 570px였다.
- 쪽 번호와 총수는 서버 그대로다. 양면으로 보인다고 `page_no`나 `pages.length`를 두 배로 만들지 않는다. 현재 위치는 항상 「⟨번호⟩쪽 · 모두 ⟨쪽 수⟩쪽」이다.
- 크래프트 종이·공통 배지색·상단 도구 각 하나·제목 직접 편집·단순 로딩을 보존했다. 인쇄는 모든 장면을 서버 순서대로 삽화 위·원문 아래의 자연 높이로 출력하며, 화면의 숨김과 동일 높이를 해제한다.

### 배지 설명에 관한 의견과 확인 사실

**현재는 설명이 부족하다는 디자인 판단**을 전달했다. 실제 아이가 무엇으로 이해했는지는 이번 작업에서 관찰하지 않았다. 이름·색만으로 글의 성적, 그림의 희소도, 모험 보상 중 무엇인지 구분하기 어렵다.

코드상 배지는 실제 묘사 평가에서 온다. 카드 결과는 그 시도, 카드 책장은 해당 카드의 최고 단계 시도, 챕터 책장은 시련의 최고 평가에 연결된다(`evaluator.py`, `book_store.py`, `chapter_run.py`). 따라서 책 전체 글을 한 번에 평가한 성적처럼 설명하면 틀린다. 튜토리얼에는 자세히 쓰기와 나침반 밝기의 간접 안내가 있지만 기본·희귀·전설의 의미를 직접 설명하는 안내는 없다. 삽화 대체 경로도 있어 배지와 눈에 보이는 그림의 화려함이 항상 일치하지는 않는다.

권고는 첫 결과의 배지 옆에서 **무엇에 대한 보상인지와 구체적인 묘사와의 관계를 짧게 알리고**, 이후에는 결과·책 어디서든 눌러 뜻을 다시 확인하게 하는 것이다. 단순히 이름의 순서를 나열하는 것만으로 충분하다고 보지 않는다. **이 설명 기능이나 배지 의미·등급 기준 변경은 이번에 구현하지 않았다.** 후속 요청 시 현재 실제 동작에 맞는 문구를 정하고 관찰로 이해 여부를 확인한다.


## 13. 원본 비율로 면 채우기·배지 설명 — 2026-09-18 후속 사용자 요청

사용자가 배지 설명 기능을 추가하도록 승인했고, 결과와 책에서 삽화를 자르지 않으면서 최대한 여백 없이 보여 달라고 요청했다. 후속 답변에서도 빈틈없는 표시를 우선한다고 확인했다. 원본의 픽셀 수를 키우는 것만으로 비율 차이가 해결되지는 않는다. 기존 파일을 보존하고 화면의 액자·삽화 면을 원본 비율에 맞추는 방향으로 반영했다.

### 삽화와 책

- **결과 화면**: 기존 정사각형 `object-cover`를 제거했다. 실제 이미지의 `naturalWidth / naturalHeight`에 맞춰 액자 자체의 비율을 바꾸고 `object-contain`으로 전체를 표시한다. 긴 변에는 기존 화면 크기 상한을 적용한다. 아직 그림을 받기 전 대기 자리는 1:1이다. 테두리는 바깥 outline으로 두고 모서리는 자르지 않아 네 귀퉁이까지 남긴다.
- **책**: 삽화 면 안쪽의 패딩·높이 제한을 제거하고 면 전체를 원본 비율로 채운다. 896px 이상에서는 같은 장면의 삽화 왼쪽·글 오른쪽을 유지하되, 세로 삽화는 세로로 긴 책이 되고 가로 삽화는 가로로 넓은 책이 된다. 모바일에서는 그림 전체 다음에 원문을 읽으며, 긴 세로 그림은 화면 스크롤이 필요할 수 있다.
- **높이 우선순위 변경**: 모든 장면을 같은 그리드 행에 겹쳐 높이를 맞추던 방식은 해제했다. 같은 원본 비율과 보통 길이의 글은 같은 크기를 유지한다. 비율이 다르거나 글이 매우 길면 장면 높이·쪽 넘김 위치가 달라질 수 있다. 긴 원문을 맞추려고 자르거나 작은 글씨로 압축하지 않는다. 데스크톱에서 글이 아주 길면 글 면이 삽화 면보다 길어질 수 있다.
- 지금의 화면 규칙은 원본 내부에 이미 그려진 여백까지 제거하는 기능은 아니다. 향후 모든 책 면의 모양까지 통일하려면 새 삽화의 제작 비율을 통일해야 한다. 이번에는 생성 설정이나 기존 삽화 파일을 바꾸지 않았다.
- 책 이름·지은이·원문·URL·서버 쪽 번호와 한 장면씩 이동은 보존했다. 인쇄는 모든 장면을 원래 순서대로 출력하고 삽화 전체를 담는다.

### 배지 설명

- 결과에서 아직 안내를 확인하지 않은 브라우저에는 배지 아래에 「네가 쓴 묘사로 얻은 배지야. 배지를 누르면 뜻을 볼 수 있어.」와 「알겠어」를 표시한다. 그림 대기 중에는 배지·첫 안내가 나타나지 않는다.
- 결과·책의 배지는 같은 색과 크기의 버튼이다. 물음표 표식이 있고 누르면 「배지 알아보기」를 연다. 행동·방법·느낌의 구체성과의 관계, 기본→희귀→전설 순서, 길이만으로 정해지지 않는다는 점, 책에는 모험에서 얻은 배지를 남긴다는 설명을 담았다. 실제 평가 기준이나 배지 이름을 바꾸지 않았다.
- 「알겠어」 또는 열린 설명의 닫기/Escape로 확인했을 때만 `localStorage`에 확인 여부 하나를 저장한다. 단순 노출만으로 사라지지 않는다. 이 상태는 계정별이 아니라 해당 브라우저 기준이며, 아이 정보·글·계정 식별자는 저장하지 않는다. 저장소 사용이 막혀도 현재 탭에서 확인 상태를 유지한다.
- 설명은 native dialog로 열어 배경 조작을 막고, 제목부터 읽도록 포커스를 준다. 키보드 Tab으로 닫기에 접근하고 Escape/닫기 후에는 원래 배지로 돌아온다. 인쇄에는 도움말 창·첫 안내·물음표를 빼고 배지 이름은 남긴다.
- 문구의 기준은 `docs/문구.md` 1.8이며 `copy.ts`·`*-copy.ts`는 열거나 수정하지 않았다. 이 구현의 기능 검사는 아이가 설명을 이해했다는 관찰 결과가 아니다.

## 21. 정사각 그림책·쓰기 전 배지 안내·직접 쓰기 전용 본편 — 2026-09-19

### 사용자 확정과 설계 정정

- 실물 그림책 사진을 참고하여 **한 면 1:1 정사각형** 판형을 사용자가 직접 선택했다. 이전의 긴 세로 비율 유지보다 이 요청이 우선한다. 원본 파일 변경도 앞선 대화에서 허용했다.
- 사용자가 본편 선택지가 문해력 목적에 맞는지 물었고 실제 11:15 스크린샷을 제공했다. 감사 결과, 종전 구현은 선택만으로 12턴 완결이 가능했고 책에는 선택지 라벨을 빼므로 본문이 빈 책 페이지도 만들 수 있었다. 이번 UI 작업에서 생긴 기능은 아니었다.
- 사용자는 **「선택지를 없애고 직접 쓰기만 제공」**이라고 확정했다. [ADR 0017](adr/0017-direct-writing-only.md)에 종전 PRD·API·문구의 선택지 허용 규칙을 대체하는 결정을 기록했다. 선택지를 힌트로 바꾸거나 입력창에 자동으로 채우지 않는다.
- 배지 이름은 아직 기본·희귀·전설이다. 사용자는 이해도를 질문했으며 새 이름을 확정하지 않았다. 단어를 안다고 쓰기와의 관계까지 이해한다고 단정하지 않는다. 새 이름 후보 제안과 실제 이름 변경은 구분한다.

### 정사각 삽화 적용 범위

- 기존 c01 세로 숲 삽화를 imagegen으로 좌우 확장하여 **1254×1254** 이미지를 만들었다. 세로 그림을 1:1로 찌그러뜨리거나 위아래를 잘라 맞춘 것이 아니다. 생성 편집이므로 픽셀 단위로 원본과 동일하다는 주장은 하지 않는다.
- 생성 PNG: `web/assets/illustrations/c01-square-2026-09-19.png`. 설치용 JPEG: `api/out/정사각_2026-09-19/c01.jpg`. `docs/삽화_legendary_선정.md`의 c01 경로를 갱신했다. 형식 변환 외 그림 편집은 imagegen이 수행했다.
- 로컬 `.artworks`의 c01 preset 한 파일과 **원래 그 파일과 SHA256이 완전히 같았던 시도 이미지 7개**에 정사각 판을 적용했다. 개별 아이의 서로 다른 삽화를 일괄 덮어쓴 것이 아니다. 대상과 이전 바이트는 `/private/tmp/geulmoheom-ui/square-artwork-before-2026-09-19/`의 manifest·백업으로 남겼다. 아이 원문·책 이름·저자·DB의 이미지 참조는 수정하지 않았다.
- 공통 카드·챕터 생성과 기본 삽화 생성에 SDK `ImageConfig(aspect_ratio="1:1")`를 명시했다. 실제 유료 Gemini 생성 호출은 하지 않았다. `web/e2e/_서버하네스.mjs`의 보여주기 기본 샘플도 새 PNG를 우선한다. 명시적 `E2E_SHOW_ARTWORK`가 있으면 그것이 우선한다.
- **범위 한계:** 다른 17개 세로 preset은 변환하지 않았다. ADR 0015 이후 이들은 기존 생성 실패 때 쓰는 폴백이다. 임의로 전부 같은 그림으로 바꾸지 않는다. 기존 세로·가로 이미지가 오면 화면은 여전히 원래 비율을 보존한다. 모든 과거/폴백 삽화까지 변환했다고 말하지 않는다.

### 쓰기 전 배지 안내

- 새 `TierBadgeWritingIntroduction`을 카드와 `/chapter` 입력창 앞에 연결했다. 카드에서는 기존 장면→동료→입력 순서가 끝난 뒤 보인다. 본편에 바로 들어가도 안내가 있다.
- 「글을 쓰면 만나는 배지」와 「행동에 방법이나 느낌을 담으면 배지가 달라질 수 있어. 길게 쓰지 않아도 괜찮아.」를 먼저 보여 준다. 접힌 예시에서는 「문을 연다.」와 「문 너머가 궁금해서 손잡이를 천천히 돌린다.」를 비교한다. 예시에 특정 배지를 보장하지 않는다.
- 확인 전에도 입력·제출할 수 있다. 「알겠어」 후 입력칸으로 초점이 돌아간다. `geulmoheom:tier-badge-prewriting-v1`에 확인 여부만 저장하고, 저장소가 막히면 탭 메모리에 유지한다. 기존 결과 안내의 확인 키와 분리했다. 이름·아이 ID·원문은 저장하지 않는다.
- 결과·책의 기존 배지 버튼과 설명 모달은 유지한다. 기존 결과 확인 여부와 상관없이 새 사전 안내를 볼 수 있다. 색·크기·평가 기준은 변경하지 않았다. `docs/문구.md` 1.8에 등록했다.

## 22. 배지 이름과 본편의 레서판다·나침반 — 2026-09-19 후속 요청

사용자가 배지 이름 변경을 이어서 요청하고, 「모험 떠나기」 이후 본편에서도 레서판다와 나침반이 역할을 가져야 한다고 지적했다. 21절의 「배지 이름 미확정」은 당시 기록이다. 최신 표시 이름은 아래와 같으며 앞 절의 옛 캡처와 혼동하지 않는다.

### 배지 이름

| `basic` | 장면 |

### 본편 동료의 역할

- 본편 입력 곁에 판다·말풍선·나침반 하나를 묶었다. 기존 입력창의 별도 나침반은 숨겨 두 개가 겹치지 않는다. 처음·이어하기에는 「여기 이 나침반, 네가 이야기를 쓰면 반짝여. 탐험가는 이제 어떻게 할까?」를 보여 준다.
- 소개 때 잠깐 빛나고, 입력을 시작하면 소개 연출이 끝난다. 이후 밝기는 기존 글자 수 함수에 따라 변한다. 쓰기를 기다리게 하는 연출이나 최소 글자 수 허들은 없다. 움직임 줄이기 설정에서는 회전·반복 반짝임을 멈추고 정적인 빛으로 안내한다.
- 보내는 동안 판다 자리에서 「네 이야기를 읽고 있어.」를 한 번만 표시한다. 입력 길이로 `compass_bright` 표정을 예측하지 않는다. 정상 진행·시련·완결·되묻기·차단에는 서버가 준 대사와 표정이 우선한다.
- 정상 진행에는 「네가 쓴 이야기로 다음 장면이 열렸어. 이번에는 어떻게 할까?」를, 실제 시련 진입·진행·통과에는 기존 1.19의 대사를 내려준다. 완결은 `session_end`와 1.20의 인사를 사용한다. G0·차단 응답을 소개 문구로 덮지 않는다.
- `ChapterView.guide`를 선택 필드로 추가했다. 구형 서버에서 필드가 없으면 프론트는 고정 소개·일반 진행 안내만 보완한다. 생성된 TypeScript 타입은 실제 OpenAPI로 재생성했다.
- 기존 `429 TURN_LIMIT`와 정확한 `409 CHAPTER_DONE_TODAY` 종료 응답의 `detail.guide`도 배웅 화면으로 연결했다. 안내가 없는 구형 종료 응답은 해당 서버 문구를 사용한다. 종료 뒤 다시 제출할 수 있게 만들지 않는다.
- 다음 응답을 받으면 서사와 말풍선의 스크롤을 첫 줄로 돌린다. 긴 안내는 키보드로도 읽을 수 있다. 아이 원문·직접 쓰기 전용 흐름·안전 처리·인증·일일 상한·삽화·책 외관은 유지했다.

### 현재 디자인

- 새 `AccountEntry`는 기존 숲 배경과 레서판다 자산, 밝은 종이와 짙은 파란 글자를 세 입구에 함께 쓴다. 데스크톱은 왼쪽 소개·숲 그림과 오른쪽 입력 영역, 모바일은 작은 로고·판다 아래 한 열의 폼이다. 부모 화면의 브랜드는 링크가 아닌 표기로 두어 아이 모험으로 잘못 이동하지 않는다.

## 26. 본편 레이아웃을 튜토리얼과 통일 — 2026-09-19
