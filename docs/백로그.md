## 0. 우선순위 기준

모든 항목은 아래 **단일 질문**으로 분류한다.

> **"학부모가 결제할 만큼, 아이가 스스로 문장을 쓰는가"** — 이 핵심 가설을 검증하는 데 없으면 안 되는가?

| 등급 | 정의 | PRD 대상 |
|---|---|---|
| **P0-a · Stage 0 「그림이 되는 이야기」** | 서사 없는 단일 턴 슬라이스. Evaluator + 시각 보상만으로 **H2(노력)**를 분리 검증. 2~3주 | **O** (1차 PRD) |
| **P0-b · Stage 1 「TRPG」** | Stage 0 통과 후 서사·상태·챕터를 얹어 **H1·H3**(몰입·재방문) 검증 | **O** (Stage 0 통과 후) |
| **P1 · Next Phase** | MVP 로그·사용자가 쌓인 뒤에야 의미가 생기는 기능. MVP 검증 직후 착수 | X (2차 PRD) |
| **P2 · Later** | 시장 확장·수익 고도화 단계. PMF 확보 후 | X |

규모: **S** (1~3일) · **M** (1~2주) · **L** (2주 이상). 1인 + Claude Code 풀타임 기준.

**Stage 0을 먼저 두는 이유** — 가장 비싼 부분(GM 엔진·상태 관리·챕터 집필)을 짓기 전에 가장 불확실한 부분(아이가 시각 보상 때문에 더 구체적으로 쓰는가)을 확인한다. Stage 0에서 만든 Evaluator·스캐폴딩·안전·로깅·캐릭터는 Stage 1에 전부 재사용된다. 단, Stage 0은 "연습"이 아니라 **GM 캐릭터가 가져온 모험 장면 카드에 탐험가의 행동을 쓰는 퀘스트**로 포장한다 — 학습지처럼 보이면 글쓰기 울렁증 페인포인트를 정면으로 건드려 잘못된 실패 판정이 나온다.

## 6. 분류 시 내린 판단 (기록용)

- **대시보드(G-1)를 P1로 내린 이유** — 학부모 킬러 기능이지만 MVP 시점엔 보여줄 데이터가 없다. 대신 **로깅(F-1)은 P0**로 올려 MVP 첫날부터 데이터를 쌓는다. Fake Door(F-2)의 대시보드 목업이 MVP 기간 동안 학부모 기대치를 대신 채운다.
- **책 빌드를 Stage 1(A-7)로 올린 이유 (v3)** — 비전 2장 확정: 아이가 쓰는 이유는 "내 책을 보여주고 싶어서"다. 책이 P1이면 Stage 0·1 사용자에게 "왜 쓰지?"의 답이 없다. 규모 S라 부담도 작다. 구 G-3 흡수.
- **공유 서재를 P2 → P1 1순위로 올린 이유 (v3)** — 공유 대상이 전체 사용자로 확정되어 핵심 기능이 됨. 그래도 P0가 아닌 이유: ① 초기 10~30명 규모에선 서재가 비어 검증이 안 되고 ② 안전망(S-0)이 먼저 서야 하며 ③ Stage 0·1에서 "쓰게 만드는 엔진"이 검증되지 않으면 공유할 책이 AI 대필본이 된다(비전 ②). 구 H-1/H-2를 S-1/S-2로 재번호, 안전망 S-0 신설.
- **Stage 0 앨범을 "내 책" 프레임으로 바꾼 이유 (v3)** — 공유는 P1이지만 "책이 쌓인다"는 감각은 첫날부터 있어야 한다.
- **학부모 연동(E-4)을 P0에 넣은 이유** — 만 13세 미만 타깃이라 보호자 동의 없이는 테스트 자체가 불가하다. 최소 플로우만 구현한다.
- **Stage 0을 신설한 이유 (v2)** — 사용자 제안. GM 엔진·챕터 집필 없이 Evaluator+시각 보상만으로 H2를 2~3주 만에 분리 검증한다. 단 H1·H3는 Stage 0에서 판정하지 않는다 (서사 없는 슬라이스의 재방문율은 제품 실패의 근거가 아님).
- **캐릭터 리디자인(C-2)을 P0 선행으로 둔 이유** — 현재 이미지는 만 7~9세 톤. 첫 화면 인상이 초6 이탈을 부를 수 있어 MVP 테스트 전 교체가 필요하다. 규모 S.
