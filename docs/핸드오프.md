# 핸드오프 — PM 세션 인계

> **휘발성 문서다.** 세션이 바뀔 때 덮어쓴다. **결정과 계획은 여기 없다** — 여기 있는 것은 「지금 무엇이 돌고 있고 다음에 무엇을 집는가」뿐이다. 오래 남아야 하면 `주차계획/` · `adr/` · `api/` 로 옮기고 여기서 지운다.

**작성 2026-09-21 밤 · 전체를 새로 썼다** (같은 날 앞 판은 **판정 대기 셋을 적어 뒀는데 셋 다 풀렸다**)

## 0. ⛔ 지금 세션이 `gm-pm2` 라면 먼저 읽는다

**`gm-pm2` 는 「사용자 질문에 답하는 세션」이다. 문서를 고치지 않는다.**
- **`docs/` 를 고치는 것은 `gm-pm` 하나뿐이다**
- 고칠 것이 나오면 **「어느 문서의 어디를 이렇게」까지 짚어서 사용자에게 말한다.** 커밋·push 하지 않는다
- **⭐ 답하기 전에 SSOT 를 연다.** 이 문서도 낡는다

---

## 1. ⛔ 지금 당장 — **사용자가 AWS 권한을 붙이는 것을 기다린다**

**push 를 멈춰 둔 것은 사용자 판정이다.** 「AWS 권한 먼저, 그 다음 push」로 정했다 — 그 순서면 **운영에서 자녀 삭제가 막히는 시간이 아예 없다.**

**사용자가 붙였다고 알려 오면 그때 네 커밋을 한 번에 올린다.**

```
4b40f61  접속 코드 안내와 삭제 본문을 확정 문구로        (프론트)
1e96aa3  프라이버시: 자녀를 지우면 삽화 파일도 지운다    (PM)
510c69f  진척 파일이 코드보다 뒤에 있었다                (백엔드)
21cd9f1  문구.md 3.4·3.9 확정값                          (PM)
```

**⛔ 넷을 한 번에 올린다** — 나누면 **문서와 코드가 어긋나는 순간**이 생긴다. `git fetch` 로 봤을 때 가져올 것은 없었다.

**⛔ 올리면 Render 가 api 를 자동 배포한다.** 배포 직후 첫 접속이 느릴 수 있다.

## 2. ⛔ 삽화 파일 파기 — **코드는 섰고 운영에서는 아직 안 돈다**

**이게 이 국면에서 제일 큰 것이다.** 자세한 것은 **`docs/미룬것.md`** 에 있다.

- **판정한 방향** — **파일을 먼저 지우고, 다 지워진 경우에만 DB 를 지운다.** 하나라도 못 지우면 **아무것도 안 지우고** `INTERNAL_ERROR` 를 낸다. 부모는 다시 누를 수 있다
- **가르는 기준은 `artworks/시도/` 경로다** — **행이 아니다.** 캐시가 맞으면 **공용 키가 그 아이 행에 그대로 적히기** 때문에, 행 기준으로 지우면 **공용 18장이 딸려 간다**
- **⛔ IAM 에 `s3:DeleteObject` 가 없다.** 정책은 작성해 올렸고 **사용자가 콘솔에서 직접 붙인다.** 붙기 전까지 **운영에서 자녀 삭제가 500 으로 막힌다** — 의도된 동작이다
- **⛔ 「검증했다」고 말하지 않는다.** 검사는 전부 **개발용 로컬 폴더**에서 돌았다. **실제 AWS 에서 파일이 지워지는 것을 한 번도 못 봤다** — 사용자 지시다
- **⏳ 검증된 뒤에 할 것 둘** — **정책 문서**(`MVP_PRD.md` 324 · `페인_가이드라인정책.md` 31)와 **`문구.md` 3.9 의 「파일이 안 지워진다」 근거**를 실제 동작에 맞춘다. **지금 고치면 안 된다**
- **⏳ 한글 경로가 걸릴 수 있다** — 권한 규칙의 `artworks/시도/` 에 한글이 있다. **틀리는 방향은 안전하다**(삭제가 전부 거부될 뿐). 안 되면 **경로를 영어로 바꾸는 방법**을 따로 올린다

**후속 작업 셋은 `미룬것.md` 에 갈라 적었다** — ① 이미 쌓인 주인 없는 파일 정리 ② 삭제 확인서 발급 ③ **없는 `adr/0013`**(S3 전환 기록 · PM 몫).

**⚠ 이번에 역할 경계를 한 번 넘었다** — **사용자가 삽화 파기를 PM 세션에 직접 지시해서 PM 이 `api/` 넷을 직접 고쳤다.** 착수 전에 백엔드에 알려 겹치지 않게 했다. **다음에도 그러라는 뜻이 아니다** — 사용자가 어느 세션에 말했는지가 기준이다.

## 4. ⛔ 돌릴 때마다 결과가 갈리는 검사가 둘 있다

**같은 코드로 한 번은 실패하고 한 번은 통과한다. 제품 결함이 아니다.**

- **api** — `test_artwork.py` 세 건이 **「relation cards does not exist」**로 실패했다가, 다시 돌리니 **783 전부 통과**했다. 검사용 DB 준비의 경쟁 상태로 보인다
- **web** — `book-journey.spec.ts:474` 한 건. 검사 도중에 빌드를 같이 돌려 화면이 다시 만들어진 탓이었다. 그 파일만 다시 돌리니 18건 통과

**⭐ 다음에 누가 빨간불을 보면 먼저 다시 돌려 본다.** 쫓을 일은 지금 국면이 아니지만, **모르면 없는 결함을 쫓는다.**

## 4-1. ⛔ 로컬 데이터로 등급·품질을 재지 않는다

**로컬 api 는 진짜 Gemini 에 안 붙어 있다** — `GEMINI_API_KEY=fake-key-not-valid-anywhere` 이고 `GEMINI_BASE_URL` 이 **127.0.0.1 의 목 서버**를 가리킨다. **거기서 나온 등급은 평가 모델이 매긴 것이 아니라 목 서버가 정해 준 값**이다.

**실측 (2026-09-21)** — 튜토리얼 20건 중 **19건이 전설**, 일반 카드 14건은 **전부 전설**. **거의 전부 전설인 것 자체가 목 서버라는 증거**다. 게다가 **쓴 사람이 아이가 아니라 개발 중의 우리**다.

**⛔ 2026-09-21 에 PM 이 이 함정에 빠져 프론트에게 헛일을 시켰다.** 「아이가 보통 어느 등급을 받나」를 물었는데, **답이 결정을 안 바꾸는 질문**이기도 했다 — 그 건(튜토리얼 대사가 「책에 남아」라고 거짓말하는 것)은 **빈도가 높든 낮든 고치는 것도 급한 정도도 같았다.** **오히려 드물수록 나쁘다** — **아이가 가장 크게 칭찬받은 그 순간에만 거짓말을 듣고, 그 순간이 책을 열어 보고 싶은 때**다.

**⭐ 물어볼 것을 정하기 전에 「그 답이 무엇을 바꾸나」를 먼저 본다.** 안 바뀌면 안 묻는다.

## 5. 오늘 밤 무엇이 바뀌었나

- **접속 코드 안내가 넷으로 확정됐다** — 제목 · 코드 · **쓰는 법** · 제한. **「아이가 쓸 기기에서 같은 주소를 열고 넣어주세요.」는 걷혔다**(사용자가 하루 전 판단을 물렸다). 코드는 **화면에서만 세 자리씩** 끊고 **값에는 공백이 없다**
- **삭제 확인창에 「그림」이 돌아왔다** — 「쓴 글과 **그림**, 만든 책을 더 이상 볼 수 없으며」. 낮춘 것은 **동사**이지 목록이 아니었다
- **삽화 파일 파기 코드가 섰다** (2장)
- **해커톤 마감 날짜는 더 보지 않는다** (사용자 지시). 루트 `CLAUDE.md` 5행과 `주차계획/해커톤_제출전_고칠것.md` 4행이 **09-18 로 낡은 채 남아 있다** — 고칠지는 안 정했다
