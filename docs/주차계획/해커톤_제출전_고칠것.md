# 해커톤 제출 전에 고칠 것

> **W7 계획이 아니다.** W7 은 19/19 로 닫혔다. **이 문서는 그 뒤에 선 것**이고,
> **AI 해커톤 제출(마감 2026-09-18) 전에 고치기로 한 것만** 담는다.
> **다 고치면 이 문서는 `미룬것.md` 와 `핸드오프.md` 로 흩어지고 닫힌다.**

**작성 2026-09-17 · 사용자 판정으로 세웠다**

## 0. ⛔ 왜 세웠나 — 판정이 뒤집힌 자리다

**PM 은 「고칠 시간이 없으니 결함 셋을 아신 채로 내시라」고 올렸다. 사용자가 물렸다.**

> **「뭔가 생략하거나 하면, 부족한 프로젝트라고 생각해서 안 뽑힐 거야. 고칠 시간 없다고 하지 마. 고치자.」**

**⭐ PM 이 크기를 안 재고 「없다」고 했다.** 재고 나니 **셋 중 둘은 오늘 밤 안에 들어가고**, 하나는 **진단이 0원**이었다. **「시간이 없다」는 측정이 아니라 추측이었다.**

**⛔ 잣대가 바뀐다** — 여기서 재는 것은 **「아이가 막히나」가 아니라 「심사자가 부족하다고 볼 것인가」**다. 둘은 다르다. **아이는 안 막히는데 심사자에게는 허술해 보이는 것**이 실제로 있었다(아래 ②).

## 1. 고치는 것 셋

### ① 맨 주소로 들어오면 갇힌다 — **제일 싸고 제일 확실하다**

**무슨 일인가** — 서비스 주소를 그냥 열면 자동으로 아이 인증 화면으로 간다(`page.tsx` 261행 `router.replace("/child/auth")`). 그 화면은 **「접속 코드를 넣어주세요 · 부모님이 알려주신 6자리 숫자예요」**라고 말한다.

**심사자에게는 그 6자리가 없다. 그리고 그 화면에 부모 가입으로 가는 길이 하나도 없다** — `child/auth/page.tsx` 에 링크가 **0건**이다(PM 이 파일에서 확인했다).

**⛔ 코드를 뒤져서 찾았다. 걸어봤으면 1분이었다** — 아래 3장이 그래서 있다.

**고치는 법** — 아이 인증 화면 아래에 **부모 가입으로 가는 길 한 줄**을 둔다.

**✅ 안전한 것을 확인했다** — 그 링크로 간 심사자는 **쿠키가 없어 401 이고, 401 은 가입 폼을 띄운다**(`signup/page.tsx` 96행). **알려진 「가입 무한 고리」는 아이 코드를 이미 넣은 뒤에만 난다** — 주 경로에서는 안 만난다.

| | |
|---|---|
| **담당** | **문구는 PM**(`문구.md` 3장에 등록) → **링크는 프론트** |
| **완료 조건** | 맨 주소로 들어와 **부모 가입까지 손으로 닿는다** |
| **위험** | 거의 없다. 다만 **문구를 코드에서 지어내지 않는다** — `문구.md` 가 SSOT |

**⛔ 문구를 새로 지을 때 지킬 것** — 학부모 화면 목소리는 **존댓말**이고, **「튜토리얼」·「온보딩」 같은 내부 용어를 쓰지 않는다**(`용어사전.md`).

### ② 이야기가 앞뒤가 안 맞는다 — **원인이 「잊는 것」이 아니었다**

**무슨 일인가** — 09-17 한 판에서 **4번째 턴이 밝힌 사건의 원인(수정 구슬 지팡이)이 그 뒤 한 번도 안 나온 채 완결**했다(`W7.md` 완료 판정 회차).

**⛔ 원인 — GM 이 말한 것이 어디에도 저장되지 않는다.** 이것이 종전 진단(**15번 「요약에 GM 서사가 없다」**)보다 한 겹 아래다.

- GM 에게 되먹이는 요약의 재료는 **아이가 쓴 글 · 등급 · 비트**뿐이다(`chapter_state.py` 78행 `요약재료()`)
- `chapter_turns` 에 **GM 서사 칸이 없다**(`models.py` 289~308행). `text` 는 **아이가 쓴 것**이다
- **그러니 「잊는다」가 아니라 기억할 방법이 없다.** 요약기가 아무리 잘해도 **없는 것을 요약할 수는 없다**

**⭐ 이것이 심사자 눈에 제일 크게 보인다** — 이야기가 앞뒤가 안 맞으면 **「AI 가 대충 짓는다」**로 읽힌다. **그건 이 제품의 핵심 주장을 정면으로 깎는다.**

**고치는 법** — `chapter_turns` 에 **GM 서사 칸 하나**를 더하고, **턴마다 저장**하고, **요약 재료에 넣는다.** 구조는 이미 다 있고 **칸만 없다.**

| | |
|---|---|
| **담당** | **백엔드** |
| **크기** | 마이그레이션 1개(11번째) + 저장 + 요약 재료 + 테스트 |
| **완료 조건** | **한 판을 돌려 「앞 턴이 밝힌 것이 뒤 턴에 이어지나」를 눈으로 본다** |
| **돈** | **한 판 약 121원.** 돈이 나가는 것이라 **사용자 판정이 앞에 있다** |
| **⚠ 위험** | **요약이 길어지면 GM 프롬프트가 커지고 지연이 는다 — ③ 과 부딪힌다.** 서사를 통째로 넣지 말고 **요약기가 접게** 둔다 |

**⛔ 아이 원문과 같은 칸이 아니다.** GM 서사는 **AI 가 쓴 글**이라 `api/CLAUDE.md` 8~9행의 「책 콘텐츠」 예외와 **다른 성격**이다. **칸을 나누고 주석에 그 갈림을 적는다** — 안 적으면 다음 사람이 아이 원문 규칙을 여기 적용한다.

### ③ 첫 턴이 8.2초 걸린다 — **진단이 먼저고 그건 0원이다**

**무슨 일인가** — 09-17 한 판에서 **1턴 8.2초**, 합격선(8초 · PRD 7장) 초과. 평균은 4.96초다.

**⛔ 후보 원인** — **핵심 씬 턴(1턴·9턴)만 그림 굽기 앞에서 안전 검사를 동기로 기다린다**(`stage1.py` 459행 `내보내도되나(프롬프트문)`). **굽는 것 자체는 백그라운드라 안 막는데 그 검사는 요청 경로 안에 있다.**

**✅ 0원으로 갈린다** — **9턴도 느렸으면 구조다**(핵심 씬 턴이라서). **9턴이 평범하면 1턴만 튄 것**이고 분산 문제다.
**⛔ 그런데 그 기록(`회차.json`)이 저장소에 없다** — PM 이 찾았고 **0건**이다. **프론트 세션이 들고 있는지 먼저 본다.**

**고치는 법(구조였을 때)** — 그 검사를 **백그라운드 안으로 옮긴다.** 검사를 없애는 것이 아니라 **아이를 기다리게 하지 않는 것**이다.

| | |
|---|---|
| **담당** | **진단은 프론트**(기록 찾기) → **고치는 것은 백엔드** |
| **완료 조건** | 1턴이 **8초 아래** |
| **⛔ 안전 경로다** | 옮기는 것이지 없애는 것이 아니어도 **커밋 메시지 첫 줄에 드러낸다**(루트 `CLAUDE.md`) |
| **⚠ 위험** | 검사 결과가 응답보다 늦게 나오므로 **막혔을 때 기본 그림으로 가는 흐름**을 다시 봐야 한다. **진단에서 구조가 아니면 손대지 않는다** |

## 2. 안 고치는 것 하나 — **딴소리 대응**

**무슨 일인가** — 아이가 **「오늘 급식 뭐야?」** 같은 것을 넣으면, 설계한 복귀 문구(`문구.md` 1.23) 대신 **되묻기 문장**이 나간다. 처리 순서가 되묻기에서 반환해서다(`stage1.py` 296행).

**✅ 그런데 실제로 나가는 문장이 「탐험가는 지금 어떤 기분이야?」다.** **이야기 쪽으로 되돌리는 말로 읽힌다** — 심사자가 어색하다고 느낄 가능성이 셋 중 제일 낮다.

**⛔ 고치는 값이 나쁘다** — 문장이 딴소리인지 가리는 장치가 필요한데, **평가 정확도 97.5%(`W2-evaluator-bench`)를 흔들거나 매 턴 호출이 하나 는다.** **얻는 것보다 깨질 위험이 크다.**

**⏳ `미룬것.md` 에 이미 있고 16번(`t3_path`)과 같이 본다.** **낱개로 고르면 두 번 고른다.**

## 3. ⛔ 그 전에 — 한 판을 걸어본다

**우리는 운영에서 「부모 가입부터 끝까지」를 한 번도 안 해봤다.** 09-17 완료 판정 회차는 **모험 안쪽만** 봤다.

**① 이 그 증거다 — 코드를 뒤져서 찾았고, 걸어봤으면 1분이었다.**

**순서**
1. **20~30분 서버를 놀린다** — 요금제가 먹었는지가 같이 확인된다(`adr/0016`)
2. 부모 가입 → 자녀 만들기 → 6자리 코드
3. 코드로 아이 화면 → 세 장 → 「모험 떠나기」 → 10턴 → 완결 → 책
4. **보는 것은 「되나」가 아니라 「처음 보는 사람이 막히나」** — 말·시간·그림·끝·**되돌아갈 길 없이 갇히는 데**

**⛔ 가입 쪽에서 더 나올 가능성이 높다. 아무도 안 걸어봤다.**

## 4. 제출 링크 — **하나로 낸다**

**부모 화면과 아이 화면은 같은 앱의 다른 경로**라 링크가 둘이 아니다.

| | |
|---|---|
| **대표 링크** | `https://geulmoheom-web-six.vercel.app/parents/signup` |
| **설명란** | 부모로 가입 → 자녀 계정과 **6자리 접속 코드** → 그 코드를 아이 화면에 넣는다 |
| **아이 화면** | `https://geulmoheom-web-six.vercel.app/child/auth` — **설명 안에만 적는다** |

**⛔ 맨 주소나 아이 주소를 앞에 두지 않는다** — 심사자가 거기부터 열고 ① 에 걸린다.
**⚠ 주소는 사용자가 Vercel 에서 확인한다** — 위 값은 `adr/0012`(09-14)에 적힌 것이고 **그때 한 번 바뀐 적이 있다.**

## 5. ⛔ 이 기간에만 다른 규칙 둘

**① `main` push 를 다시 연다.** 핸드오프 0-3 이 심사 기간 push 를 막았는데, **그 규칙이 막으려던 것은 「심사 중에 배포가 돌아 첫 요청이 느려지는 것」**이다. **지금 고치는 것은 심사 전이다** — 0-3 자신이 **「지금이 심사 중보다 낫다」**고 적어 뒀다.
**⛔ 대신 「올렸다」를 그 자리에서 알린다.** 안 그러면 느린 것이 배포 때문인지 요금제 때문인지 못 가른다.

**② 코드는 `api/`·`web/` 세션에서 한다.** 루트 세션은 PM 모자라 `docs/` 만 고친다.
