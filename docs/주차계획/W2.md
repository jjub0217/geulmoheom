### W3 으로 넘어가는 것 (2026-09-07 기록)

W2 안에서 처리하지 않기로 하고 **자리만 잡아둔 것들**이다. `/plan-week W3` 이 여기서 읽어간다.

- **서버까지 붙는 진짜 E2E + CI.** 이번 주 브라우저 검증은 응답을 **브라우저에서 가로채** 만든 것이라 서버를 안 탄다. W3 에 실제 api 를 붙이고 `ci.yml` 92행 **계약 검증 job 과 같이** 넣는다. 그때 `X-Mock-Outcome`·`X-Mock-Error` 를 쓴다
  - **CI 설계에 전제가 하나 늘어난다 — api 기동.** 지금은 `NEXT_PUBLIC_API_BASE=/api/v1` 로 같은 오리진을 만들어 우회했다. `Authorization` 헤더가 붙으면 브라우저가 preflight(OPTIONS)를 먼저 보내는데 **Playwright 가 그건 못 가로채서** cross-origin 으로는 가로채기 자체가 안 걸린다. 진짜 서버를 붙이면 이 우회는 필요 없어지지만 **대신 api 를 띄워야 한다**
- **임시 `mockAuthHeader` 삭제** (`web/src/lib/api.ts`). 인증 계약 재맞춤(E-3/E-4)으로 서버가 쿠키를 받으면 그 함수만 지운다. **운영 빌드에는 이미 안 들어가지만, 조용히 살아남는 것이 유일한 위험**이다
- **결과 연출 대사를 문서로 옮긴다.** `api/app/api/v1/attempts.py` 의 `_결과대사` 가 **코드에 잠정으로** 들어가 있다. PRD 4.0 템플릿 치환인데 확정 문안이 문서에 없어서 구현이 자리를 메웠다 — `app/errors.py` 의 `CHILD_MESSAGE` 와 같은 상황이다. **W3 대사 세트(C-1)에서 PM 이 확정하면 그쪽이 SSOT 이고 코드가 따라온다.** 잊으면 아이가 보는 문구가 코드에만 남는다
- **헤더·쿠키 값은 ASCII 로 둔다.** 2026-09-07 에 개발용 목 토큰에 한글이 들어가 **브라우저 `fetch` 가 요청을 보내지도 못하고 죽었다** (헤더 값은 ISO-8859-1). curl 은 통과해서 안 보였고 화면에는 「서버에 못 닿음」으로만 나왔다. **`api/app/api/v1/_fixtures.py` 의 `TOKEN` 도 아직 한글이다** — E-3/E-4 에서 토큰·쿠키 값이 실제로 브라우저를 타기 전에 ASCII 로 바꾼다
