안 일어났다」를 쓴 것**이다. **⑥ 과 다른 축이다** — ⑥ 은 **입력이 이상한 것**이고 이건 **검사가 재는 대상이 틀린 것**이라, ⑥ 은 곁에서 튀어나오지만 이건 **일부러 뒤집어야만** 나온다. **뒤집기 자체도 틀릴 수 있다** — `return` 만 지웠더니 다른 고장이 나 「가드가 안 문다」로 판정할 뻔했다. **심으려는 버그가 실제로 심겼는지를 먼저 본다**까지가 이 축이다. ⑧ **「없다」와 「못 물어봤다」를 한 값으로 뭉개지 않는다** (2026-09-08, 백엔드 자기 정정). `docker ps ... 2>/dev/null || echo` 에서 **`command not found` 를 `2>/dev/null` 이 삼키고 파이프 때문에 `||` 도 안 걸려** 아무것도 안 찍혔는데, 그걸 **「컨테이너가 없다」**로 읽었다. 실제로는 **14시간째 떠 있었다.** 그 오독 위에 「`pytest` 가 전부 빨개진다」까지 얹혀 **다음 세션에 틀린 경고를 남길 뻔했다.** **⑦ 과 같은 모양이고 프론트의 「서버에 못 닿음」이 셋을 뭉갠 것과도 같다** — 다른 점은 **이번엔 장치가 아니라 사람이 쓴 셸 한 줄**이었다는 것이다. **조회가 실패한 것과 대상이 없는 것은 다른 값이다.** **같은 날 세 번째가 났다** — `make contracts-check | tail -1 && git commit` 에서 **파이프라인 종료코드가 `tail` 것이라 검사가 실패했는데 `&&` 가 그냥 넘어갔고, 계약이 어긋난 채로 `main` 에 올라갔다**(`8f29dc0` → `10a610f` 수리). **장치는 멀쩡했고 그 결과를 안 본 것**이다. **검사를 부르는 한 줄이 검사를 무력화한다** — `2>/dev/null` 과 `| tail` 이 같은 일을 한다. **검사 명령을 파이프에 태우지 않는다.** ⑨ **문서가 SSOT 여도 코드에 두 군데 박혀 있으면 한쪽만 고쳐진다** (2026-09-08, 프론트). 「확인하는 중…」이 세 화면에 각각, 앱 이름·설명이 `layout.tsx`·`manifest.ts` 에 각각 박혀 있었다 — **한쪽만 고치면 홈 화면 아이콘 밑 이름과 탭 제목이 갈린다.** `문구.md` 가 SSOT 라는 것은 **어느 문장이 옳은가**를 정할 뿐 **코드가 한 곳에서 읽는가**는 안 정한다. **등록을 옮기는 작업이 이 중복을 드러냈다** — 훑기의 부산물이지 훑기의 목표가 아니었다. **같은 문장이 두 번 나오면 상수로 모은다**까지가 등록의 끝이다. ⑩ **계약에서 값이 빠질 때 화면만 훑으면 놓친다 — 픽스처가 계약보다 오래 산다** (2026-09-08, 프론트). 차단 응답의 `reason` 에서 `pii` 를 뺐을 때 **그리는 자리는 없었는데 E2E 픽스처가 `reason: "pii"` 인 응답을 지어내 쓰고 있었다.** 화면이 `reason` 을 안 읽어 **동작은 멀쩡했고 타입 검사도 드리프트 0 이었다** — **서버가 절대 안 보내는 응답을 테스트가 만들고 있었을 뿐이다.** ⑨ 의 변종이지만 손댈 곳이 다르다: **계약에서 값을 뺄 때는 제품 코드가 아니라 픽스처·목·시드를 먼저 훑는다.** **한 겹 더** (2026-09-08 저녁, 프론트가 미리 훑다가 찾음) — **픽스처가 계약보다 오래 사는 이유는 사람이 안 봐서가 아니라 기계가 볼 수 없게 돼 있어서다.** `placeholder_url` 을 뺐을 때 픽스처 하나가 남았는데, **같은 파일의 다른 픽스처는 계약 타입에 물려 있어 멀쩡했고 그것만 맨 객체였다.** **타입 없는 목·픽스처는 드리프트 검사가 초록이어도 안 걸린다** — 그날 `contracts-check` 가 통과인 채로 살아 있었다. **그러니 규칙은 「훑는다」가 아니라 「픽스처에 계약 타입을 붙인다」다** — 훑기는 사람이 기억해야 하지만 타입은 기계가 매번 본다. ⑪ **먼저 있던 코드가 아는 것을 새 코드가 모른다** (2026-09-08, 백엔드 자기 발견). `app/pii.py` 가 **전각 숫자(`０１０…`)로 뚫렸는데**, `app/accounts.py` 는 닉네임 검사에서 **이미 알고 NFKC 로 눕혀 두고 있었다.** **같은 종류의 입력을 다루는 코드가 저장소에 이미 있으면 그것이 무엇을 방어하는지 먼저 본다** — 새로 짜는 쪽이 항상 나중이라 **아는 것이 적다.** 다만 **구현을 합치는 것과는 다르다**: 닉네임은 넓게 잡아도 되지만 **같은 패턴을 아이 문장에 걸면 「3층으로 올라갔다」가 가려진다.** **아는 것은 옮기고 규칙은 자리마다 정한다.** **2026-09-08 저녁 두 번째 사례로 승격한다** — W5 에서 ⓪·⑧·⑬ 과 함께 본다. `app/artwork.py` 가 **자르지 않은 레퍼런스**를 넣어 삽화 20% 가 망가졌는데, **`scripts/gen_character.py` 가 하루 먼저 같은 것을 겪고 대책까지 적어 뒀다.** **첫 사례(전각 숫자)와 형태가 같다 — 저장소 안에 답이 있는데 새 코드가 안 본다.** 다른 점은 **이번엔 그 답이 주석으로 여덟 줄이나 쓰여 있었다는 것**이다. **읽히지 않는 자리에 있으면 길게 적어도 소용없다** — `gen_character.py` 는 **스크립트**고 `app/artwork.py` 는 **제품**이라, 제품을 짜는 사람이 스크립트를 열 이유가 없었다. ⑫ **지표를 확인 없이 해석하지 않는다 — 숫자는 맞고 뜻이 틀릴 수 있다** (2026-09-08, 사용자가 잡음). `top` 의 **`131M unused`** 를 보고 「메모리가 빡빡하다」고 판단했는데, **macOS 는 남는 RAM 을 전부 캐시로 쓰므로 free 가 0 에 가까운 것이 정상**이다. 봐야 할 값은 **메모리 압력**이었고 실제로는 **60% free** 였다. 스왑 4.45G 도 **누적치**라 「지금 부족하다」가 아니다. **⑧ 과 다르다** — ⑧ 은 **도구가 실패를 감춘 것**이고 이건 **읽은 값이 맞는데 뜻을 잘못 고른 것**이다. **값이 아니라 「이 값이 무엇을 뜻하나」를 한 번 확인한다.** **오늘 이 부류의 값은 사람이 헛일을 한다는 것이다** — PM 이 사용자에게 **「다른 앱을 닫으라」**고 두 번 올렸고 닫을 것이 없었다. **오늘 실수를 잡은 것이 거의 전부 상대 세션이었는데 이건 사용자가 잡았다** — 「무거운 앱을 연 게 없는데 확인해 보라」. ⑬ **요약이 확인을 대신하지 않는다** (2026-09-08, 사용자가 잡음 — 오늘 두 번째다). **「W3 7/7」이라는 다섯 글자가 셋을 덮었다** — ① 하위 체크 셋이 `[ ]` 인 채였고 ② `F-1` 을 8종으로 닫은 것이 **판단인데 판단으로 안 올라갔고** ③ **CI 가 초록인지 하루 종일 한 번도 안 봤다**(보니 초록이었다 —
