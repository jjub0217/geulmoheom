## 1. 학부모 (Parent)

### POST `/parents/signup`
```json
// req
{ "email": "a@b.c", "password": "...", "consent": true }
// res 201
{ "parent_id": "...", "consent_at": "2026-09-01T00:00:00Z" }
```
- **⛔ 가입은 전부 되거나 전부 안 된다** (2026-09-12). **행이 남았는데 못 들어오는 상태를 만들지 않는다.**
  - **2026-09-10~12 에 실제로 그랬다** — `JWT_SECRET` 이 비어 토큰 발급이 터졌는데 **학부모 행은 이미 저장돼 있었다**(`commit()` 이 `issue()` 앞이었다). 화면에는 **「잠깐 문제가 생겼어요」**만 보이고, **다시 가입하면 「이미 가입된 이메일」로 막혀 자기가 만든 계정에 못 들어갔다**
  - **고쳤다** — `flush()` → `issue()` → `commit()`. 토큰 발급이 터지면 **롤백돼 계정이 안 남는다.** **원인이 무엇이든 같은 일이 안 난다**
  - **응답도 상태 코드도 안 바뀐다.** 바뀐 것은 **실패했을 때 남는 것**뿐이다 — 그래서 계약 변경이 아니라 **불변식을 적는 것**이다
- **토큰은 body에 없다.** `Set-Cookie: __Host-gm_parent=...`로 내려간다 (`공통규약.md` 「인증 쿠키」)
- `consent: true`가 아니면 422. 동의 문구 버전은 서버가 `consent_version`으로 기록
- 라벨링 동의(아이 문장을 Evaluator 개선용 라벨링에 활용, 파일럿 종료 시 사본 파기)는 **별도 체크박스** → `labeling_consent: bool`. 거부해도 서비스 이용 가능, 책에는 원문이 그대로 남음

### POST `/parents/login` → `{ "parent_id": "..." }` + `Set-Cookie: __Host-gm_parent`
- **없는 이메일과 틀린 비밀번호를 같은 401 로 준다** (2026-09-07 추가). 구분하면 로그인 화면이 **「이 이메일이 우리 서비스에 있는지」를 묻는 도구**가 된다 — 아동 서비스라 **가입 사실 자체가 알려지면 안 된다.** 응답 시간도 갈리지 않게 한다

### POST `/parents/logout` → 204
- `Set-Cookie: __Host-gm_parent=; Max-Age=0; Path=/; Secure; HttpOnly; SameSite=Lax` — **이름·`Path`·`Domain` 유무가 발급 때와 하나라도 다르면 안 지워진다**
- HttpOnly라 클라이언트가 스스로 지울 수 없다. 로컬 상태만 비우면 쿠키는 살아 있다
- **인증을 요구하지 않는다. 쿠키가 없어도 204** (2026-09-07). 만료·손상된 쿠키를 지우려는 것이 로그아웃인데 인증을 걸면 **정작 지워야 할 상태에서만 401 로 막힌다.** 지우는 것 말고 하는 일이 없어 열어 둬도 잃을 것이 없고, cross-site POST 는 `SameSite=Lax` 가 막는다
- **자녀 쿠키는 건드리지 않는다** — 가족 태블릿에 둘이 함께 앉아 있다

### GET `/parents/me`
```json
{ "parent_id": "...", "email": "...", "consent_at": "...", "children": [ { "child_id": "...", "nickname": "...", "age_band": 11, "daily_cap": 5, "played_today": true, "last_active_at": "..." } ] }
```
- **성장 데이터·등급·입력 내용은 반환하지 않음** (P1 대시보드 범위)

### POST `/parents/children`
```json
// req
{ "nickname": "불꽃탐험가", "age_band": 11 }
// res 201
{ "child_id": "...", "nickname": "...", "access_code": "482913", "access_code_expires_at": "..." }
```
- `nickname`은 PII 검사(E-2 서버 2차) 통과 필수. 실패 시 422 `detail.reason = "PII_DETECTED"`
- `age_band` ∈ {10, 11, 12}
- `access_code` 6자리, 24시간 유효, 1회 사용. 서버는 해시만 저장

> **`{child_id}` 가 붙는 모든 경로 공통 — 남의 자녀 ID 는 404 다** (2026-09-07 추가). 403 으로 가르면 **「그 ID 는 존재한다」가 샌다.** 자녀 ID 는 난수라 찍기 어렵지만, **존재 여부를 알려주는 순간 난수의 값이 절반으로 준다.** 없는 ID 와 남의 ID 를 구분하지 않는다

### POST `/parents/children/{child_id}/access-code` → 재발급 `{ access_code, access_code_expires_at }`
- **`children.token_version`을 1 올린다 → 이전 기기의 자녀 토큰이 즉시 401이 된다** (`공통규약.md` 「폐기」)

### PATCH `/parents/children/{child_id}` → `{ daily_cap }` (SHOULD, 10~20)

### DELETE `/parents/children/{child_id}` → 204. 자녀 데이터 즉시 파기 (attempts, books, artworks, events, Redis)
- 파기 대상에 **자녀 토큰도 포함**된다. `token_version`을 올려 남아 있는 기기를 끊는다

## 2. 자녀 인증 (Child Auth)

### POST `/child/auth`
```json
// req
{ "access_code": "482913" }
// res
{ "child": { "child_id": "...", "nickname": "...", "guide_name": null } }
```
- **토큰은 body에 없다.** `Set-Cookie: __Host-gm_child=...` (`공통규약.md` 「인증 쿠키」)
- 코드 소진 후 재사용 불가. JWT는 **절대 30일**이고 쿠키 만료만 슬라이딩한다
- **브라우저에서 연다. 실행 형태를 가리지 않는다** (2026-09-14, `adr/0014`). 쿠키 컨텍스트가 하나뿐이라 1회용 코드가 갈릴 데가 없다

### POST `/child/logout` → 204
- `Set-Cookie: __Host-gm_child=; Max-Age=0; ...` — 가족 공용 태블릿에서 아이가 내려오는 경로
- **인증을 요구하지 않는다. 쿠키가 없어도 204** — `/parents/logout` 과 같은 이유다
- **학부모 쿠키는 건드리지 않는다**
- **아이 화면의 「나가기」 버튼은 아직 없다** (2026-09-07). 접속 코드 화면(E-3)이 서기 전에 나갈 문만 만들면 **아이가 스스로를 가둔다** — 둘을 같이 세운다

### GET `/child/me`
```json
{ "child_id": "...", "nickname": "...", "guide_name": "나침이", "today": { "cards_done": 2, "cap": 5, "locked": false, "resets_at": "2026-09-02T00:00:00+09:00" } }
```
- `locked`가 true면 프론트는 세션 종료 화면만 표시 (A0-5)
- `resets_at`은 **기기 로컬 자정**. 클라이언트가 `X-Timezone: Asia/Seoul` 헤더를 보내고 서버가 계산

### PATCH `/child/guide` → `{ "guide_name": "나침이" }` (C-1 이름 짓기, 1회. PII 검사)

## 3. 카드 (Cards)

### GET `/cards/next`
오늘 아직 안 한 카드 중 하나를 아이별 랜덤 순서로 반환.
```json
{
  "card_id": "c01",
  "type": "crisis",
  "situation": "안개 낀 숲에서 나무 사이로 거대한 그림자가 천천히 다가온다. 그런데 그림자는 자꾸 같은 자리에서 넘어지고 있다.",
  "prompt_label": "탐험가는 어떻게 할까?",
  "guide": { "expression": "default", "line": "나침반이 조용하네. 네가 뭘 할지 말해주면 움직일 거야!" },
  "today": { "cards_done": 2, "cap": 5 }
}
```
- **`sketch_url` 은 2026-09-09 에 계약에서 빠졌다** (`b9d0652` · **명세 변경**). **카드 화면에 그림을 두지 않는다.**
  **값이 `https://r2.example/…` 라는 픽스처 주소였고 그 그림을 한 번도 만든 적이 없어 아이 화면 왼쪽 절반이 빈 액자였다** — 프론트가 「못 불러와도 안 무너지게」 처리해 둬서 조용히 남았다.
  **만들지 않기로 한 이유가 「안 만들어서」가 아니다** — **카드 스케치와 결과 삽화가 같은 장면 프롬프트에서 나온다**(`장면카드_초안.md` 설계 원칙). **쓰기 전에 그 장면을 보여주면 결과가 카드와 같은 그림이 되어 보상이 0 이고**, **아이가 묘사할 것을 그림이 대신 말해 준다** — Stage 0 이 재는 것이 H2(묘사 노력)다.
  **대가는 진입 장벽이고 프리테스트 관찰 신호 1·12번이 그것을 잰다.** 아이가 못 시작하면 **그때 스케치를 설계한다** — 「모르니까 안 넣는다」가 아니라 **「잴 수 있으니 재고 넣는다」**다.
  **되살아나면 걸린다** — `assert "sketch_url" not in body`. **죽은 픽스처를 남기면 계약보다 오래 산다**(`placeholder_url` 과 같은 자리, 축 ⑩)
- 소진 시 409 `DAILY_CAP_REACHED` + body에 `guide.line`("내일 또 보자") 포함
- `guide.line`은 서버 템플릿 치환 결과 (PRD 4.0). 프론트는 그대로 표시
- **표정 4종(`expression`)은 서버가 정한다. 프론트가 고르지 않는다.** 값은 `default` `compass_bright` `compass_dim` `session_end`
  - **`expression` 을 버리지 않는다** (2026-09-08 추가). **`session_end` 가 화면에 한 번도 안 나오고 있었다** — 오류 응답의 `detail.guide` 에서 **대사만 꺼내 쓰고 표정을 버렸다**. **네 얼굴 중 하나가 그 자리를 위해 만들어졌는데 그 자리에서만 안 떴다** (`docs/캐릭터/비교_결과.md` C-2 — 「기존 세트가 네 상태를 표현하지 못한다」가 확정 근거였다)
  - **모르는 값이 오면 얼굴만 빼고 대사는 세운다.** **파일명이 곧 `expression` 이라 그대로 넘기면 없는 PNG 를 불러 그림이 깨진다** — 값이 늘어나는 날 조용히 그렇게 된다. **다만 대사까지 함께 버리면 안 된다** — **얼굴이 낯선 것과 아이가 왜 못 들어가는지 못 듣는 것은 다르다**
- **제출 전(입력 중) 화면 상태는 서버 응답이 없으므로 프론트가 정한다. 단 표정 4종을 쓰지 않는다** (2026-09-07 추가).
  입력 중 캐릭터는 **`default` 고정**이고, 글자 수 격려 같은 제출 전 연출은 **표정이 아닌 다른 수단**(나침반 빛 등)으로 한다.
  `compass_bright`·`compass_dim` 은 **평가 결과**를 뜻하므로, 제출 전에 쓰면 서버가 아직 판정하지 않은 것을 그림이 먼저 약속하게 된다

### GET `/cards/{card_id}` → 단일 카드 (재시도 화면 복귀용)
- 응답 모양은 `/cards/next` 와 같다
- **모르는 카드와 튜토리얼 카드(T1~T3)는 404** (2026-09-07 추가). 튜토리얼은 노출 경로가 따로 있다 (Stage 1 A-6)
- **남은 카드가 없으면 409 `DAILY_CAP_REACHED`** (2026-09-08 추가). 소진 응답과 같은 `guide.line`. **일일 상한 5장이 먼저 걸려 실제로는 안 닿는다** — 그래도 정의해 두는 이유는 **상한을 올리는 날 여기가 빈 응답이나 500 이 되면 아이 화면이 멈추기 때문**이다

## 4. 시도 (Attempts) — 핵심 엔드포인트

### POST `/attempts`
```json
// req
{ "card_id": "c01", "text": "은빛 검을 들고 그림자 뒤로 살금살금 돌아간다", "retry_of": null, "prompted": false }
```
- `retry_of`: 같은 카드 재시도면 이전 `attempt_id`. 재시도는 일일 카운트 미소모
- `prompted`: 캐릭터 권유로 인한 재시도면 true (Stage 1 튜토리얼 T2용. Stage 0은 항상 false)
- `text` 1~500자. 클라이언트 1차 PII 마스킹 후 전송. 서버는 마스킹된 텍스트를 책 콘텐츠로 저장

**`retry_of` 를 언제 채우나 — 되묻기 뒤 재입력은 채우지 않는다** (2026-09-07 확정, 프론트 질문)

- **되묻기(`outcome=scaffold`) 뒤 고쳐 보낼 때 `retry_of: null`.** 되묻기는 **시도가 끝난 것이 아니라 같은 시도의 연장**이다
  - **일일 카운트가 이 값에 걸려 있다** (아래 「서버 처리 순서」 2·10). `retry_of` 를 채우면 카운트가 안 늘어, **되묻기를 거친 카드만 하루 5장에서 빠지지 않는다.** 카드를 하나 푼 것은 맞으므로 틀린 셈이 된다
  - **H2 도 갈린다.** 되묻기 전 짧은 입력을 별도 회차로 세면 **되묻기가 잘 작동할수록 「회당 평균 글자 수」가 내려간다** — 아이를 더 쓰게 만들려고 넣은 장치가 지표를 깎는다. 되묻기 전후는 `scaffold_triggered` 의 `next_char_len` 이 따로 잡는다
- **`retry_of` 는 결과(a)를 받은 뒤 같은 카드를 다시 풀 때만 채운다.** 그것이 `card_retry` 이벤트가 재는 재시도율이고, 그때는 일일 카운트를 다시 쓰지 않는다 (A0-3, W4)

**차단(`outcome=blocked`) 시 아이가 쓴 문장을 지우지 않는다** (2026-09-07 확정). 입력창에 그대로 남긴다 — 되묻기·전송 중과 같은 규칙이다. **이유도 모른 채 공들여 쓴 글이 사라지면 그것 자체가 벌로 읽힌다.** 같은 문장을 다시 보내면 서버가 다시 막으면 되고, PII 는 클라이언트 마스킹(E-2)이 붙으면 애초에 여기까지 오지 않는다.

**서버에 닿지 못했을 때도 같다** (2026-09-08 추가). **화면을 넘기지 않고 카드 자리에 머문다.** 위 규칙이 되묻기·차단·전송 중만 덮고 **못닿음이 빠져 있었다** — 실제로 화면을 넘기고 있었고, 넘어간 화면의 「다시 열기」는 **다른 카드**를 불러오므로 **입력칸에 남은 문장이 앞 장면에 쓴 글인 채로 새 장면에 붙는다.** 아이는 **자기 글을 잃고, 잃은 줄도 모른다.** 문구는 `문구.md` 2.4.

**오류 넷** (2026-09-08 명세 추가 — 응답 스키마는 안 바뀐다. 넷 다 `공통규약.md` 오류 표에 이미 있는 코드다)

- **오늘 이미 푼 카드 → 409 `CARD_ALREADY_DONE_TODAY`.** `/cards/next` 가 안 줘도 **클라이언트는 직접 부를 수 있다** — **주지 않는 것과 받지 않는 것은 다른 자리**라 둘 다 막는다.
  **`retry_of` 는 통과시킨다** — 막으면 **A0-3 의 「다시 써보기」가 통째로 안 돌고**, **H2 재시도율이 재는 것이 바로 그 동작**이다. 되묻기는 행을 안 만들어 애초에 안 걸린다 — **걸렸으면 아이가 그 카드에 갇혔다**

- **모르는 `card_id` → 404.** `card_attempts.card_id` 가 `cards` 를 FK 로 문다. **안 거르면 평가·검사 호출이 이미 나간 뒤 저장에서 터져 500 이 된다** — **돈은 나갔는데 아이는 「잠깐 문제가 생겼어요」를 본다.** 거르는 자리가 호출보다 앞이어야 하는 이유다
- **`retry_of` 가 이 아이의 시도가 아니면 → 422** (`detail.fields: ["retry_of"]`). **404 로 가르지 않는다** — 404 와 422 가 갈리면 **「그 시도는 존재한다」가 샌다.** `{child_id}` 규칙과 같은 자리다. **UUID 모양이 아닌 것도 같은 422** 로 걸린다(계약은 `retry_of` 를 문자열로 두지만 「ID 는 전부 UUID」가 공통규약이다)

**`attempt_id` 는 실제 행 id 다** (2026-09-08). 종전에는 픽스처라 **모든 아이의 모든 시도가 같은 id** 였다 — **새로고침 복구가 남의 것을 가리키던 이유가 이것**이다.

> **⚠ 위 두 예시는 2026-09-09 까지 낡아 있었다.** `https://r2/...` 와 `placeholder_url` 을 실은 채였는데 **둘 다 이 절 아래에서 폐기된 것**이다. **오늘만 이 부류가 세 번째다** — `sketch_url`(빈 액자) · `placeholder_url` · 이것. **규칙을 고칠 때 같은 문서의 예시가 안 따라온다.** 코드와 검사는 이미 맞았고 **문서만 틀렸다**.

  - **나갈 자리가 없는 값이었다.** **60초** 초과는 아래 표대로 **`ready` + `fallback = true`** 로 확정되고, **생성 실패·출력 검사 차단도 안전한 기본 삽화**로 간다 (PRD B-3 「플레이 중단 없음」). **모든 실패가 `ready` 로 수렴한다**
  - **그런데 프론트는 「`failed` 면 즉시 중단」을 구현하고 테스트까지 물고 있었다** — **영영 안 오는 값을 기다리는 분기**다. `BlockedReason` 에서 `pii` 를 뺀 것과 같은 자리이고, **거기서는 픽스처가 죽은 값을 살려 두고 있었다**
  - **아이가 그림을 못 받는 경우를 만들지 않는다는 것이 B-3 의 결정이다.** 그 결정이 참인 한 이 값은 되살아나지 않는다 — **되살리려면 그 결정을 먼저 뒤집어야 한다**

### 화면 비율 — **⛔ 한 값이 아니다. 두 모양이 공존한다** (2026-09-15 개정 · `adr/0015`)

**⛔ 종전 「전부 세로 0.58」은 2026-09-15 부로 거짓이다.** `adr/0015` 가 **삽화를 아이 문장으로 매번 굽게** 바꾸면서 **생성 경로가 갈렸고, 두 경로가 다른 모양을 낸다.**

| 어디서 온 그림 | 실측 | 비율 | 언제 |
|---|---|---|---|
| **갓 구운 것** (`adr/0015` 경로) | **`1024×1024`** | **1 : 1** | 아이 문장으로 구워졌을 때 — **평시** |
| **조합 파일 폴백** | `784×1353` | **0.58** | **못 구웠을 때** — `adr/0015` 가 정한 설계된 실패 경로 |

**출처** — 1:1 은 **2026-09-15 운영 실측**(프론트, 유료 한 판). 0.58 은 2026-09-08 실측(20/20 장).

**⛔ 그래서 한 상수로는 못 맞춘다.** **폴백은 버그가 아니라 설계된 경로다**(`adr/0015` 「못 구우면 조합 파일로 — 기본 에셋으로 바로 가면 오늘보다 나쁜 그림이다」). **1:1 로 상수만 갈면 폴백이 뜰 때마다 틀린 액자에 앉는다** — 지금 반대 방향으로 나 있는 그 결함이 **반대로 뒤집힐 뿐**이다.

**✅ 판정 (2026-09-15 PM) — 계약 값은 「오기 전에 자리를 비워 두는 값」이고, 온 뒤에는 실제 비율이 이긴다.**

1. **그림이 오기 전** — **`1 : 1` 로 자리를 비운다.** 평시 경로의 모양이다. **레이아웃이 안 튀는 원래 목적은 그대로 지켜진다**
2. **그림이 온 뒤** — **온 그림의 실제 비율로 액자를 잡는다.** 어느 경로로 왔는지 화면이 안 물어도 된다
3. **다음에 생성 모양이 또 바뀌어도 ②가 알아서 받는다.** ①만 계약을 따라온다

**⛔ 「1:1 을 박으라」가 아니다.** ① 은 **빈 자리의 모양**일 뿐이고 **그림이 오면 무효**다.

**⚠ 이 값을 정한 것은 화면 설계가 아니다.** **가이드 레퍼런스 크롭(`819×1413`)이 0.58 이고 모델이 그 비율을 따라간 것**이다. 즉 **`app/artwork.py` 의 `_정면` 사각형이 카드 삽화의 화면 비율을 정하고 있다.**

**적어 두는 것이 「0.58 로 굳힌다」는 뜻은 아니다.** **지금 값이 무엇이고 무엇이 그것을 정하고 있는지**를 적어, **바꿀 때 화면 설계가 정하게** 하려는 것이다. 지금은 아무도 안 정했고 **프론트는 이 값을 모른 채 두 화면을 세웠다** — **결과 연출(A0-3)과 내 책(A0-4)이 둘 다 이 그림을 놓는 자리**다.

**프론트가 할 것** — **오기 전에는 계약 값(`1:1`)으로 자리를 비우고, 온 뒤에는 그림의 실제 비율로 잡는다.** 비율이 바뀌어도 **레이아웃이 튀지 않게** 하는 것이 목적이지 **어떤 수도 박으라는 뜻이 아니다.**

**⚠ 종전 문장이 이 자리에서 애매했다** — 「**컨테이너에 비율을 걸어 둔다**」와 「**0.58 을 박으라는 뜻이 아니다**」가 한 문단에 같이 있었다. **프론트는 앞 문장대로 걸었고**(`web/src/lib/artwork-frame.ts`, 실측값을 출처와 함께) **그 파일은 「비율이 바뀌면 계약이 먼저 바뀌고 화면이 따라온다」까지 적어 뒀다.** **계약이 안 따라온 것이지 화면이 틀린 게 아니다.**

**⛔ 어떻게 드러났나** — **2026-09-15 운영 한 판에서 `1024×1024` 정사각형이 0.579 세로 상자에 `object-contain` 으로 들어가 폭에 갇히고 위아래로 빈 띠가 생겼다.** **자르지는 않지만 보상이 눈에 띄게 작아진다** — **그림이 보상 그 자체**인 자리다(`adr/0015`).

### GET `/artworks/{artwork_id}/image` → 이미지 바이트

**2026-09-08 대표 판정 (미결 11-7). 버킷은 공개하지 않는다 — api 가 프록시한다.**

- **쿠키 인증을 요구한다.** 아이 쿠키면 **자기 것만**, 학부모 쿠키면 **자기 자녀 것만**
- **남의 것은 404 다.** 403 으로 가르면 **「그 삽화는 존재한다」가 샌다** — `{child_id}` 규칙과 같다
- 위 폴링 응답의 **`url` 이 이 경로를 가리킨다.** 저장소 주소를 클라이언트에 내보내지 않는다
- **`Cache-Control: private, max-age=86400`** — Cloudflare 가 앞단이라 **`private` 이 아니면 공유 캐시에 아이 창작물이 남는다**
- **`<img>` 로 불린다.** cross-origin fetch 가 아니라 **서브리소스 요청**이라, 쿠키가 실리려면 **api 와 web 이 same-site 여야 한다** — `adr/0007` 이 그렇게 잡아 뒀다(같은 등록가능 도메인). **`SameSite=Lax` 로 실리는 것을 실기기에서 확인한다**
- **⛔ `url` 은 절대 주소이고, 그 절대 주소를 만드는 규칙이 배포 형태에 묶여 있다** (2026-09-09 프론트 지적 · 코드 실측).
  `api/app/api/v1/artworks.py` 의 `삽화주소()` 가 **`request.url_for()`** 로 만든다. 그 함수의 주석이 **「절대 주소여야 한다 — web 은 `app.` 이고 api 는 `api.` 라(`adr/0007`) 상대 경로면 `<img src>` 가 web 오리진에 붙어 그림이 통째로 안 뜬다」**고 적고 있다.
  **그 근거는 3단 호스트(`adr/0007`)를 전제한다.** **한 오리진에 프록시로 합치는 형태로 가면 근거가 뒤집힌다** — 그때는 **상대 경로가 맞고 절대 주소가 틀린다**. `request.url_for()` 는 api 컨테이너가 보는 호스트를 쓰므로 **공개 오리진이 아니라 api 호스트**를 내놓고, 그러면 `<img>` 가 cross-site 로 나가 **`__Host-` 쿠키가 안 실려 그림이 0%** 다.
  **`--proxy-headers` 로는 안 풀린다** — uvicorn 의 그 옵션은 `X-Forwarded-Proto`·`X-Forwarded-For` 를 보지 **`X-Forwarded-Host` 를 안 본다**. scheme 만 고쳐지고 **호스트는 안 고쳐진다**.
  **✅ 2026-09-10 확정 — 상대 경로로 간다.** `adr/0012` 가 **web=Vercel · api=Render · 한 오리진**으로 정했고, **`vercel.json` 의 `rewrites` 는 목적지 호스트로 `Host` 를 바꾼다.** 그래서 **`request.url_for()` 가 내놓는 절대 주소는 Render 호스트**가 되고 `<img>` 가 cross-site 로 나간다. **위 예시도 상대 경로로 고쳤다.**
  **⭐ 그래서 갈리는 것은 「앞단이 `Host` 를 보존하는가」다** (2026-09-09 백엔드 정정). `request.url_for()` 가 쓰는 것은 **들어온 요청의 `Host` 헤더**다 — **앞단이 그대로 넘기면 공개 오리진이 나오고 지금 코드가 그대로 산다.** 대부분의 리버스 프록시(Cloudflare 등)가 보존한다. **`vercel.json` 의 `rewrites` 만 목적지 호스트로 바꾼다.**
  **즉 이것은 「절대냐 상대냐」의 문제가 아니라 「앞단이 무엇이냐」의 문제다.** **배포 형태를 고를 때의 판단 재료로 쓴다** — 형태를 고르고 나서 이 줄을 읽으면 늦다.
  **배포 형태가 확정되는 순간 이 한 줄을 같이 정한다.** 형태를 정하고 이것을 안 정하면 **배포 후에야 드러나고, 드러나는 모습이 「그림이 안 뜬다」라서 원인이 안 보인다**
  - **왜 자동으로 실리나** — `__Host-` 접두사는 **`Domain` 속성이 없어 호스트 전용**이라, `api.` 가 발급한 쿠키가 **그 호스트로 가는 이미지 요청에 그대로 실린다.** `SameSite=Lax` 는 cross-site 만 막는데 `app.` 과 `api.` 는 **같은 등록가능 도메인이라 same-site** 다. **우연이 아니라 `adr/0007` 이 만들어 둔 조건이고, 배포처를 옮기면 같이 깨진다**
  - **⚠ `<img crossOrigin>` 을 붙이지 않는다** (2026-09-08 프론트 지적). **`crossOrigin="anonymous"` 를 붙이면 그 자동이 꺼진다** — 이미지 최적화·CDN 관례로 **습관적으로 붙이는 속성**이다. 붙는 순간 자격증명이 빠져 **그림이 통째로 안 뜨는데, 네트워크 탭을 안 열면 원인이 안 보인다**

**기본 에셋도 이 경로로 나간다** (2026-09-08). `r2_key` 가 비면 **프록시가 기본 이미지를 돌려준다.**
- **`url` 은 성공이든 폴백이든 늘 `/api/v1/artworks/{id}/image` 하나다.** **주소마저 안 갈리므로 네트워크 탭에도 차이가 안 남는다**
- **이것이 「`fallback` 이 참이어도 아이에게 알리지 않는다」를 말이 아니라 구조로 지키는 방법**이다 (`주차계획/W4.md` B-3 완료 조건). 주소가 갈리면 **언젠가 화면이 그 차이를 읽는다**

### `fallback` 의 뜻이 셋이 됐다 — **계약 표면에서는 안 갈린다** (2026-09-09)

**`fallback = true` 는 「요청한 `card+tier` 의 그림이 아니다」 하나만 뜻한다.** 실제 경우는 셋인데 **응답으로는 구분되지 않는다.**

**설정 이름도 바꾼다** — `r2_public_base_url` 은 **공개 버킷을 전제하는 이름**이다. **이름이 판단을 가린다**(2026-09-08 프론트가 `childMessage` 에서 같은 것을 겪었다).

### 저장소 키 — 난수에서 **비밀 유도**로 바뀌었다 (2026-09-09 · `9788265`)

**삽화를 미리 구워 두려면 「같은 조합 = 같은 키」여야 한다.** 그래서 종전의 **난수 꼬리표를 버리고 `JWT_SECRET` 에서 유도한 조각**을 붙인다.

- **난수를 붙였던 이유는 살아 있다** — 「`artwork_id` 를 아는 사람이 곧 그림을 볼 수 있는 사람이 되지 않게」. 카드 id·티어는 **사실상 공개값**이라 그냥 이으면 **조합만으로 키가 만들어진다**. 유도 조각은 **결정론적이면서 조합만으로는 못 만든다** — 그 성질을 지킨다
- **⚠ 대가 하나 — `JWT_SECRET` 을 갈면 키가 전부 바뀌어 캐시가 통째로 빈다.** **파일럿에서는 신규 생성을 하지 않으므로 「다시 굽는다」가 아니라 「그림이 전부 기본 에셋이 된다」가 된다** — 더 나쁘다. **파일럿이 도는 동안 비밀을 갈지 않는다.** 갈아야 할 사고가 나면 **그것이 돈이 나가는 일이라는 것까지 같이 안다**
- **찾을 때 DB 행이 아니라 파일을 본다.** 손으로 넣어 둔 파일은 **행 없이 파일만** 올라오므로 행으로 찾으면 통째로 안 걸린다. **못 물어보면 「없다」로 다뤄 한 번 더 굽는다** — 반대로 틀리면 **없는 파일을 가리키는 `ready`** 가 생겨 아이 화면에 **빈 액자**가 뜬다(`sketch_url` 과 같은 자리)

## 6. 내 책 (Book)

### GET `/book`
```json
{
  "book_id": "...",
  "title": "불꽃탐험가의 모험",
  "author": "이민준",
  "visibility": "private",
  "pages": [
    { "page_no": 1, "source": "card", "source_id": "c01", "tier": "legendary",
      "artwork_url": "...", "text": "은빛 검을 들고 그림자 뒤로 살금살금 돌아간다", "achieved_at": "..." }
  ],
  "counts": { "basic": 3, "rare": 5, "legendary": 2 }
}
```
- 자녀 1명 = 책 1권 (Stage 0). 카드별 **최고 티어 시도 1건**이 한 페이지. 재시도로 티어가 오르면 페이지 교체
- `text`는 항상 반환 (아이의 책 콘텐츠, PRD 1.1b). 맞춤법·AI 보정 없음
- `visibility`는 Stage 0에서 항상 `private`. 필드만 선반영 (P1 공유 서재)
- 프론트: 삽화 위·문장 아래·페이지 번호의 책 페이지 프레임으로 렌더

#### `author` — 2026-09-10 신설 (대표 판정)

**값은 `children.nickname` 을 그대로 싣는다.** 새 컬럼도 새 입력 자리도 만들지 않는다.

**왜 넣나** — **아이가 자기 책을 열어도 자기 이름이 어디에도 없었다.** 대표 판정의 근거가 **「자기가 쓴 글을 아이가 뿌듯해 하고 자존감도 많이 오른다」**인데, **뿌듯함이 나오는 자리가 「내 책에 내 이름이 지은이로 있다」**다. 화면 표기는 **「지은이」**(`용어사전.md`).

**⛔ 왜 `GET /child/me` 의 `nickname` 을 재사용하지 않나** — **지금은 되고 공유가 열리는 순간 깨진다.** `/child/me` 는 **보는 사람**의 이름이지 **그 책을 쓴 사람**의 이름이 아니다. P1 공유 서재에서 남의 책을 열면 **남의 책에 내 이름이 지은이로 찍힌다.** `visibility` 를 「필드만 선반영」으로 미리 넣어 둔 것과 같은 이유로, **지은이도 책에 속한 값이다.**

**중복을 막지 않는다** (2026-09-10 대표 판정). `nickname` 에 유니크 제약이 없고 **그대로 둔다** — 초등 5~6학년에 흔한 이름은 겹치는데, 막으면 **먼저 온 아이가 자기 이름을 가져가고 다음 아이는 자기 이름을 못 쓴다.** 비전 4장 질문 4(「어떤 아이는 이 기능을 못 즐기는가」)에 걸리는 자리였고 **중복 허용이 그것을 없앴다.**

**아이가 직접 짓는 것은 하지 않는다** — 09-20 뒤로 (`미룬것.md`). 지금은 **학부모가 자녀를 만들 때 지은 이름**이 그대로 지은이가 된다. **아이 첫 진입에 관문을 하나 더 놓는 일**이라 파일럿 전날에 넣지 않고, **그 관문이 아이를 막는지는 파일럿이 재준다.**

**PII 는 이미 지났다** — `nickname` 은 자녀 생성 때 검사를 지난다(422 `PII_DETECTED`). **여기서 다시 검사하지 않는다.**

### GET `/book/today` → 세션 종료 화면용. 오늘 추가·교체된 페이지만

**⛔ 여기에는 `author` 를 넣지 않는다** (2026-09-10 확정). **못 넣은 것이 아니라 안 넣기로 한 것이다** — 다음 세션이 「빠졌네」로 채우지 않게 적어 둔다.
- **`author` 는 표지의 것이다** (`문구.md` **1.15 「내 책 표지의 지은이」**). **뿌듯함이 나오는 자리가 「내 책에 내 이름이 지은이로 있다」**인데, **세션 종료 화면은 「오늘 뭘 했나」**지 표지가 아니다
- **두 자리에 같이 두면 그 한 번이 흔해진다.** 표지에서만 보이는 것이 그 값의 절반이다
- **⚠ PM 이 메시지로 「`GET /book` 과 `GET /book/today` 둘 다」라고 잘못 전했고 백엔드가 계약을 읽고 거절했다.** **문서가 스펙 층이라 이겼고, 메시지는 기록이 아니다**(축 ⑮). **필요해지면 여기 먼저 적는다 — 적히면 넣는다**

**계약에 없어서 서버가 정한 것 둘 — 화면을 만들 때 프론트가 뒤집을 수 있다**
- **빈 제목으로는 안 바꾼다.** 오류로 안 만든 이유가 있다 — `VALIDATION_ERROR` 문구가 **「잠깐 문제가 생겼어요」**라 **아이가 지운 것을 시스템 탓으로 말한다.** 다른 말이 필요하면 **`문구.md`(PM 몫)가 먼저**다
- **120자에서 자른다.** `books.title` 열 너비이고 **안 자르면 500** 이다. **화면 상한은 프론트·`문구.md` 몫**이고 이건 그 아래 바닥이다

## 7. 이벤트 (Events) — 클라이언트 발생분

서버 측 이벤트(`turn_input`, `eval_result`, `scaffold_triggered`, `moderation_blocked`, `pii_masked`, `daily_cap_reached`)는 백엔드가 자동 기록. 아래는 **클라이언트만 아는 이벤트**.

### POST `/events`
```json
{ "events": [
  { "event": "session_start", "ts": "...", "locked": false },
  { "event": "card_shown", "ts": "...", "card_id": "c01" },
  { "event": "pii_masked", "ts": "...", "layer": "client", "kind": "phone" }
] }
```
- 배치 전송 (최대 50건). 원문 필드 없음. 204

**서버 몫 이벤트는 거절한다** (2026-09-08 명세 추가). 받는 것은 `session_start` · `card_shown` · `pii_masked` **셋뿐**이다.

- 나머지(`turn_input` · `eval_result` · `scaffold_triggered` · `moderation_blocked` · `daily_cap_reached`)가 실려 오면 **버린다.** 받아 주면 **H2 가 통째로 위조된다** — **글자 수와 등급이 곧 합격선**이라, 클라이언트가 그 둘을 직접 써넣을 수 있으면 파일럿 판정이 성립하지 않는다
- **배치 전체를 물리지 않는다.** 어긋난 건만 버리고 **204** 를 준다. 한 건 때문에 되돌리면 **화면이 재전송을 반복한다**
- **`pii_masked` 의 `layer` 는 서버가 `client` 로 덮는다.** 클라이언트가 `server` 라고 보내도 그렇다 — **어느 층이 잡았는지를 클라이언트 말로 정하지 않는다.** 서버측 2차 마스킹(E-2)이 남기는 `layer: server` 와 섞이면 **두 층의 실측이 한 값으로 뭉개진다**
- 목록에 없는 키는 **화이트리스트(`EVENT_FIELDS`)에서 예외로 죽는다.** **목록에 없는 것이 곧 차단**이다

## 8. Fake Door (F-2) — 별도 정적 사이트, 이 API 사용 안 함

랜딩은 정적 호스팅 + 폼 서비스(예: 서버리스 함수 1개)로 분리. 이벤트 4종(`visit`, `signup`, `report_optin`, `pricing_click`)은 분석 툴로 직접 수집. 본 백엔드와 DB를 공유하지 않음.

## 9. 서버 내부 처리 순서 (POST /attempts)

```
1. 쿠키(`__Host-gm_child`)·역할 검증, **`token_version` DB 대조**(다르면 401), rate limit
2. 일일 카운트 확인 (retry_of 없으면) → 소진 시 409
3. PII 2차 검사 → **감지 시 마스킹 후 진행**(막지 않는다), `pii_masked`(`layer: server`) 로그
   - **2026-09-08 대표 판정** (미결 11-5). 종전 「`outcome=blocked(pii)`」를 뒤집은 것이 아니라 **어긋나 있던 한 줄을 맞춘 것**이다 — PRD E-2 는 처음부터 「감지 시 **마스킹 후 처리**」였고, 클라이언트 층은 **2026-09-07 대표 판정으로 이미 「가리되 막지 않는다」**였다
   - **막으면 아이에게 이유를 말해줄 수 없다.** 위 (c) 가 종류를 응답에 안 싣기 때문이다 — 아이는 영문을 모른 채 같은 문장을 다시 보낸다
   - **⛔ 잡는 것은 전화번호·이메일·주소·학교명 넷이다. 실명은 2026-09-09 대표 판정으로 뺐다** — 아래 「실명은 안 가린다」 참조. **`○○○` 가 책에 인쇄되는 것**은 이 넷에 대해서만 남는다
   - **마스킹된 텍스트가 그대로 아래 10번의 `card_attempts.text` 로 가고 책 콘텐츠가 된다**

   #### ⛔ 실명은 안 가린다 (2026-09-09 대표 판정 · 근거는 2026-09-10)

   **판정**: 「실명 검사 제거. 이름 노출해도 괜찮음.」 **근거는 안전이 아니라 아이 쪽이다** — **자기 이름이 든 자기 글을 아이가 뿌듯해하고 자존감이 오른다** (2026-09-10 대표).

   **범위를 좁게 읽는다 — 없애는 것은 `app/pii.py` 의 NER 갈래(130행~) 하나다.** 같은 파일의 **정규식 넷(전화번호·이메일·주소·학교명)은 판정 대상이 아니었고 그대로 간다.** **이 읽기가 틀리면 아이 전화번호가 책에 인쇄된다.**

   **⚠ 이것이 「덜 나가게」 하는 것이 아니다.** 실명은 **NER 이 있을 때도 프로바이더로 나갔다** — 실명을 찾는 일 자체를 같은 프로바이더에게 물어서 했기 때문이다(`adr/0009` 48행). NER 이 막던 것은 **전송이 아니라 우리 DB 에 저장되는 것**이고, **끄면 그 저장 차단이 없어진다.** 호출이 하나 줄어 **오히려 나가는 횟수는 준다.**

   **⏳ 코드는 아직 안 따라왔다 (2026-09-10 기준).** `attempts.py` 232행·`book.py` 131행이 여전히 `실명까지가리기()` 를 부른다. **문서가 코드보다 앞서 있는 상태이고, 백엔드 세션이 닫는다** — `주차계획/W5.md` 「작업 쪼갬 · 백엔드」.
   **코드를 지우지 말고 끌 수 있게 남긴다** — **Stage 1 가족 공유(A-7) 전에 되살린다** (`미룬것.md`). 지우면 두 번 만들고 `benchmarks/W5-ner-accuracy.md` 의 61/61 실측도 다시 재야 한다.
4·5. **입력 Moderation 과 Evaluator 를 동시에 던진다** (`adr/0009`, 2026-09-07 대표 판정)
   - **순차로 두면 +875ms 라 1.5초 예산을 깬다.** 동시면 +13ms 다. 검사 결과가 평가의 입력이 아니므로 순서를 강제할 이유가 없다
   - **차단이면 평가 결과를 버리고 `eval_result` 도 남기지 않는다.** 남기면 화면에 보여주지도 않은 판정이 **등급 분포·폴백 비율을 오염**시킨다. 차단 건의 평가 비용은 수용한다
   - **Moderation** — 별도 단계다(내장 필터 아님). 차단 시 outcome=blocked(moderation), moderation_blocked 로그
   - **자해·자살 카테고리만 뒤 처리가 다르다** — `category: self_harm` 으로 남기고, 아이에게는 「어른에게 말해줘」 한 줄만 준다. **더 대화하지 않는다.** 원문은 안 남긴다 (`MVP_PRD.md` E-1 「자해·자살 신호 처리」)
   - **Evaluator** — Gemini, thinking budget 최소, 예시셋 context caching (`adr/0005`) → grade, signals. 타임아웃 3초 → 재시도 1회 → 실패 시 grade=G1 폴백 + 로그 (아이를 막지 않음)
6. grade == G0 && scaffold_count < 2 → outcome=scaffold, scaffold_triggered 로그
7. grade → tier 매핑 (G0/G1 basic, G2 rare, G3 legendary)
8. 캐릭터 대사 템플릿 치환 (카드 명사 태그 + signals)
9. artworks 행 생성(pending) → 이미지 생성 큐 (티어별 프롬프트 + 고정 태그 + 시드)
10. card_attempts 저장(text 포함), 일일 카운트 증가 (retry_of 없을 때만), turn_input·eval_result 로그
10b. 해당 카드의 최고 티어면 book_pages upsert (삽화 ready 시 artwork_id 갱신)
11. outcome=result 응답
```
