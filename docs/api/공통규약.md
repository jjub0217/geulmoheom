**오류 형식**
```json
{ "error": { "code": "DAILY_CAP_REACHED", "message": "오늘 카드를 다 썼어요", "detail": {} } }
```

**`message` 는 아이 화면 계열이다** (2026-09-08 명시). `errors.py` 의 `CHILD_MESSAGE` 이고 **어미부터 아이 톤**이다(「해볼까요」). **학부모 화면에서 그대로 쓰지 않는다** — 학부모 화면은 **`code` 로 `docs/문구.md` 3.8 에서 고른다.**
**그래서 계약에 필드를 늘리지 않는다.** 서버가 계열별 문구를 내려주려면 **「누가 읽는지」를 알아야 하는데 그건 서버가 알 일이 아니다.** 같은 `code` 를 두 화면이 다르게 읽는 것이 맞다.

| code | HTTP | 의미 |
|---|---|---|
| `UNAUTHORIZED` | 401 | 토큰 없음/만료 |
| `FORBIDDEN_ROLE` | 403 | 역할 불일치 (자녀 토큰으로 학부모 API 등) |
| `NOT_FOUND` | 404 | |
| `VALIDATION_ERROR` | 422 | 필드 오류. `detail.fields` |
| `DAILY_CAP_REACHED` | 409 | 오늘 카드 소진 |
| `CARD_ALREADY_DONE_TODAY` | 409 | 같은 카드 당일 재시작 (재시도는 별도 경로) |
| `CONSENT_REQUIRED` | 403 | 보호자 동의 미완료 |
| `RATE_LIMITED` | 429 | |
| `UPSTREAM_TIMEOUT` | 504 | LLM/이미지 API 지연. 클라이언트는 재시도 안내 |
| `INTERNAL_ERROR` | 500 | 미처리 예외. **아이 원문·예외 메시지를 `detail`에 싣지 않는다** — 이 코드가 없으면 미처리 예외가 프레임워크 기본 형식으로 나가 응답 형식이 갈라진다 |

**`message`는 아이가 읽는 문구다.** **2026-09-07 에 10종 전부 확정됐다 — `docs/문구.md` 2.1 이 SSOT 이고 코드가 따라온다.** 아홉은 잠정본 그대로 확정했고 `VALIDATION_ERROR` 하나만 바꿨다.

**`message`는 「앱 목소리」(존댓말)이고 `guide.line`은 「가이드 목소리」(반말)다.** 한 응답에 둘이 함께 실리면(일일 상한 409) **화면은 `guide.line`만 보여준다** (`문구.md` 0장).

## 배포 형태와 오리진

`adr/0007` 확정 (2026-09-06). **`MVP_PRD.md` 1.5·`아키텍처 및 구현난의도.md` 2장의 「단일 컨테이너」를 대체한다** — 컨테이너에는 **api만** 들어간다.

| 호스트 | 무엇 | 배포 |
|---|---|---|
| `geulmoheom.app` | 랜딩 (F-2 Fake Door → 마케팅) | Cloudflare Pages |
| `app.geulmoheom.app` | web PWA — **정적 빌드**(`output: 'export'`), 프로덕션에 Node 서버 없음 | Cloudflare Pages |
| `api.geulmoheom.app` | api (FastAPI 컨테이너) | Fly.io / Railway 급 |

**도메인 문자열은 미등록이다.** 확정된 것은 *모양* — **셋이 같은 등록가능 도메인 아래 있다.** 이 성질이 계약에 걸린다.

- **web ↔ api는 same-site, cross-origin이다.** 등록가능 도메인이 같으므로 same-site이고(포트·서브도메인은 site 구분에 들어가지 않는다), 오리진은 다르다
- **따라서 CORS가 필요하다.** `Access-Control-Allow-Origin`에 web 오리진을 **명시**한다. `*`를 쓰지 않는다 — 쿠키 인증(미결 11-2)으로 가면 `*`와 `Allow-Credentials: true`는 함께 쓸 수 없다
- **로컬(`localhost:3000` ↔ `:8000`)도 same-site다.** 포트는 site 구분에 들어가지 않으므로 로컬에서 통과한 쿠키 설정이 운영에서도 같은 성질을 갖는다
- **iOS ITP의 3rd-party 제약을 받지 않는다.** cross-site였다면 자녀 토큰 30일이 성립하지 않는다 (`adr/0007` 근거)

**정적 빌드의 계약상 함의** — web에는 서버가 없다. 리다이렉트·헤더·미들웨어로 처리하던 것을 api나 배포처 설정(`_headers`)으로 내린다. **api가 web을 대신해 화면을 그려주는 엔드포인트를 만들지 않는다.**

`SameSite`·쿠키 이름·경로는 **아래 「인증 쿠키」**에서 정해졌다 (미결 11-2 확정, 2026-09-06). 이 절은 그 결정의 전제다.

### ✅ 확정됐다 — `adr/0012` (2026-09-10 대표 판정)

**위 3단 호스트는 더 이상 우리가 세우는 모양이 아니다.** `adr/0012` 가 **결정 2·3(호스트 배치·레지스트라)을 대체했다** — **web=Vercel · api=Render(무료) · 한 오리진 프록시.** 결정 1(정적 빌드)·4는 그대로 산다.

| | 확정 |
|---|---|
| 브라우저가 보는 호스트 | **Vercel 하나뿐이다.** `/api/*` 를 `vercel.json` 의 `rewrites` 가 Render 로 넘긴다 — **Render 주소는 노출되지 않는다** |
| **오리진 관계** | **same-origin 이다.** 종전 「same-site, cross-origin」이 아니다 |
| **CORS** | **운영에서는 필요 없다.** 브라우저가 cross-origin 요청을 아예 안 만든다. `CORS_ORIGINS` 는 **로컬 개발용으로만** 남긴다 |
| 도메인 | **안 산다.** 무료 서브도메인을 쓴다 |

**⛔ 한 오리진이 아니면 로그인이 안 된다.** `vercel.app` 도 `onrender.com` 도 **Public Suffix List** 에 있어 **서브도메인끼리도 남남(cross-site)** 이다. 그러면 **아래 「인증 쿠키」의 `SameSite=Lax` 가 fetch 에 안 실리고**, 삽화 `<img>` 에도 안 실려 **그림이 0%** 가 되며, iOS ITP 로 **30일이 무너진다.** **CORS 로는 안 풀린다 — CORS 는 「읽어도 되는가」이고 쿠키는 `SameSite` 가 정한다.**

**⭐ 그리고 「수명」 절의 미해결 위험이 없어졌다.** Safari 16.4+ IP 휴리스틱은 **응답 서버 IP 와 최상위 프레임 호스트 IP** 를 비교하는데, **한 오리진에서는 둘이 같다.** **`dig` 실측 후속 작업은 잴 대상이 사라졌다** (`미결.md` 후속 표에서 뺀다).

**⚠ 아래 「인증 쿠키」는 그대로 산다.** `__Host-` · `Lax` · `Path=/` · `Domain` 미부착이 **same-origin 에서도 그대로 맞다** — 오히려 **더 안전한 쪽**이다. **인증을 다시 짜지 않는다.**

**⭐ 아래 「`*.pages.dev`에서는 인증이 동작하지 않는다」가 그대로 `vercel.app` 이야기다.** **`vercel.app` 도 Public Suffix List 에 있다** — 즉 **버셀 기본 도메인으로는 3단 호스트를 흉내 낼 수 없다**(서브도메인끼리 cross-site 가 된다). **한 오리진이 그 문제를 우회하는 것이 아니라 없앤다.** **이 문서가 답을 이미 갖고 있었고, 다른 이름으로 적혀 있어서 안 보였다.**

**⛔ 같이 바뀌는 것 셋 — 안 고치면 배포가 서도 안 돈다** (`adr/0012` 「따라오는 작업」)
1. **CORS 를 운영에서 안 쓴다** — same-origin 이다. 다만 **목록을 지우지는 않는다**(로컬은 여전히 포트가 갈린다)
2. **⛔ 삽화 주소를 상대 경로로 고친다** — 지금 코드는 `request.url_for()` 로 **절대 주소**를 만들고 그 근거로 `adr/0007` 을 인용한다. **`vercel.json` 의 `rewrites` 는 목적지 호스트로 바꾸므로 그 근거가 뒤집힌다.** 안 고치면 `<img>` 가 Render 로 직접 나가 **쿠키가 안 실리고 그림이 0%** 다 (`Stage0.md` 5절)
3. **`--proxy-headers` 로는 호스트가 안 고쳐진다** — uvicorn 의 그 옵션은 `X-Forwarded-Proto`·`X-Forwarded-For` 만 본다. **scheme 이 https 로 잡히는지는 따로 확인한다** — 안 잡히면 **`Secure` 쿠키를 안 굽는다**

## 클라이언트 PII 패턴은 빌드 타임 상수다

**미결 11-3 확정 (2026-09-07).** 엔드포인트(`GET /config/pii-patterns`)를 만들지 않는다. 정규식은 **프론트 빌드에 박고**, 패턴이 바뀌면 재배포한다.

- **최종 판정은 항상 서버다.** 프론트 마스킹은 아이에게 주는 **즉시 피드백**일 뿐이고, 프론트를 우회해도 서버 2차에서 막힌다. 그래서 **패턴 갱신이 늦어도 안전이 깨지지 않는다**
- 엔드포인트를 만들면 **자녀 토큰 전 로드 · 캐시 정책 · PWA 오프라인** 셋이 딸려 오고, 프론트에 백엔드 선행이 생긴다
- web 은 정적 빌드(`adr/0007`)라 재배포가 싸다

**프론트가 잡는 것은 정규식으로 잡히는 것뿐이다** — 전화번호 · 이메일 · 주소 패턴 · 「우리 학교는 ○○」. **학교명은 서버 정규식이 잡는다** (2026-09-08 대표 판정, 미결 11-6). 한글 실명을 정규식으로 잡으려 들면 아이가 지은 가이드 이름·괴물 이름이 입력창에서 걸린다.

**⛔ 실명은 어느 층에서도 안 가린다** (2026-09-09 대표 판정). 종전 「실명은 서버 2차(NER)가 잡는다」를 걷어낸 것이다. **근거는 아이 쪽이다 — 자기 이름이 든 자기 글을 아이가 뿌듯해하고 자존감이 오른다** (2026-09-10 대표). 상세·범위·현재 코드 상태는 `Stage0.md` 9절 3번 「실명은 안 가린다」에 한 곳으로 적었다 — **여기서 두 번 적지 않는다.**

## 인증 쿠키

**미결 11-2 확정 (2026-09-06).** 재료: `api/notes/미결11-2_토큰저장_서버안.md`(서버 안) · `web/notes/미결11-2_토큰저장_프론트조사.md`(프론트 조사). 전제는 위 「배포 형태와 오리진」.

**토큰은 응답 body로 내려가지 않는다.** 서버가 `Set-Cookie`로 굽고 브라우저가 붙인다. JS는 토큰을 읽을 수도 보관할 수도 없다 — 로그인 상태는 `GET /child/me`·`GET /parents/me`로만 판별한다. **`Authorization: Bearer`를 쓰지 않는다.**

### 쿠키 속성

| | 값 |
|---|---|
| 이름 | `__Host-gm_parent` / `__Host-gm_child` |
| `HttpOnly` | ✓ |
| `Secure` | ✓ |
| `SameSite` | `Lax` |
| `Path` | `/` |
| `Domain` | **미부착**(host-only) |

- **이름을 나눈다.** 가족 태블릿에서 학부모가 가입하고 같은 기기를 아이가 쓰는 것이 정상 흐름이다. 이름이 같으면 나중에 발급된 쪽이 앞의 것을 덮어쓴다
- **`gm_` 접두사를 뺄 수 없다.** 쿠키는 포트를 구분하지 않아 같은 머신의 다른 로컬 프로젝트와 충돌한다. `__Host-`로도 안 막힌다
- **`__Host-`는 우리가 이미 고른 셋(`Secure`·`Path=/`·`Domain` 없음)을 브라우저가 강제하게 만든다.** 얻는 것은 cookie tossing 차단 — 하위 도메인 하나가 뚫려도 `Domain=geulmoheom.app`으로 같은 이름 쿠키를 덮어쓸 수 없다. `Cookie` 헤더에는 이름·값만 실려 **서버가 진짜를 구분할 방법이 없으므로** 브라우저 차원에서 막아야 한다
- **`Path`를 나누지 않는다.** 자녀 토큰이 필요한 엔드포인트가 `/cards` `/attempts` `/artworks` `/book` `/events`로 흩어져 있어, 경로로 가르려면 URL 구조를 인증 기준으로 다시 짜야 한다. 대신 **엔드포인트마다 어느 쿠키를 읽는지 서버가 명시한다**
- **`SameSite=None`을 쓰지 않는다.** web↔api는 **same-origin** 이라(`adr/0012`) `Lax`로 모든 메서드에 붙는다. **종전 근거는 「same-site」였고 `adr/0012` 가 그것을 더 강한 조건으로 바꿨다 — 결론은 같다.** `Lax`의 「top-level navigation + safe method」 조건은 **cross-site 요청을 예외적으로 허용하는 조건**이지 same-site 요청에 부과되는 요구가 아니다

### 세 번째 쿠키 — `__Host-gm_device` (2026-09-08)

**자격증명이 아니다.** 값은 난수 하나이고 **아무 권한도 열지 않는다.** `/child/auth` 속도 제한이 **「같은 기기」를 셀 손잡이로만** 쓴다 (아래 「`/child/auth` 속도 제한」 ①).

| | 값 |
|---|---|
| 이름 | `__Host-gm_device` |
| `HttpOnly` · `Secure` · `SameSite` · `Path` · `Domain` | **위 인증 쿠키와 완전히 같다** |
| `Max-Age` | **24시간** (인증 쿠키는 30일) |

- **인증 쿠키가 아닌데 `__Host-` 세 속성을 그대로 받는 이유는 「굽는 코드가 한 곳」이어야 하기 때문이다.** 속성을 다른 모듈로 복사하면 갈라지고, **갈라진 쪽이 조용히 약한 쿠키를 굽는다** (`app/auth.py` `_ATTRS`)
- **`HttpOnly` 를 붙인다.** JS 가 읽을 일이 없고, **읽을 수 있으면 화면 코드가 「기기 id」로 다른 일을 하기 시작한다**
- **수명이 하루인 것은 세는 창이 15분·1시간이라 그보다 길 이유가 없어서다.** **기기를 오래 따라다니는 값을 아이 브라우저에 남기지 않는다**
- **지우면 그 기기의 실패 카운터도 사라진다. 그것이 ②(IP)가 병행하는 이유다** — **계약이 아니라 설계다.** 기기 하나만으로는 ①이 완결되지 않는다

### 개발 환경도 https다

**`localhost`를 버리고 mkcert + `https://app.geulmoheom.test:3000` ↔ `https://api.geulmoheom.test:8000` 으로 간다.** **2026-09-07 에 옮겼다** — W3 인증 계약 재맞춤의 첫 항목이다 (계획에는 「W2 E-3/E-4 착수와 동시」로 적혀 있었으나 그 주차가 미뤄지면서 실제 시점이 갈렸다).

**포트도 오리진의 일부다.** 운영은 `https://app.geulmoheom.app`(443)이라 포트가 안 보이지만, **개발에서는 `:3000`·`:8000` 을 빼면 preflight 가 통과하지 않는다.** `cors_origins` 에 `https://app.geulmoheom.test:3000` 을 그대로 적는다 — 와일드카드를 쓰지 않는다.

- `Secure` 쿠키가 `http://localhost`에 붙는지가 **브라우저마다 갈린다** (Chromium 허용, Safari 불확실 — WebKit bug #281149 REOPENED). **파일럿이 태블릿이라 Safari를 건너뛸 수 없다**
- 대안이었던 「dev만 `__Host-` 제외」는 **쿠키 이름이 환경마다 달라져 환경별로만 재현되는 버그를 만든다.** 채택하지 않는다
- https로 옮기면 이 질문 자체가 사라진다. schemeful same-site·포트 혼동·`127.0.0.1` 대 `localhost` 함정도 같이 사라진다

### 역할이 안 맞으면 401 이 아니라 403 이다

**쿠키 이름이 둘이라 「인증은 됐는데 역할이 다른」 상태가 실재한다** (2026-09-07, 토큰 body 제거와 함께 실제 경로가 됨). 자녀 쿠키만 있는데 학부모 API 를 부르면 **`FORBIDDEN_ROLE` 403** 이다.

**401 로 주면 안 된다.** 프론트가 「로그인이 풀렸다」로 읽고 아이를 다시 로그인시킨다 — **역할 문제지 인증 문제가 아니다.** 프론트의 401 공통 처리는 **403 을 그 경로에 태우지 않는다.**

### 수명 — JWT는 절대 30일, 쿠키만 슬라이딩

| 무엇 | 값 |
|---|---|
| JWT `exp` | 발급 시각 + 30일. **절대 고정. 갱신하지 않는다** |
| 쿠키 `Max-Age` | 인증된 요청 처리 시 **절대 만료까지 남은 시간**으로 다시 굽는다 (재발급은 12시간에 최대 1회) |

서로 다른 두 위협에 각각 대응한다. **둘을 한 값으로 묶으면 하나는 반드시 진다.**

- 토큰이 영구화되면 탈취 영향이 커진다 → **30일이 지나면 접속 코드를 다시 받는다.** 한 달에 한 번 학부모가 개입하는 것은 이 제품에서 비용이 아니라 가드레일 쪽이다
- **Safari 16.4+는 서브리소스 응답의 `Set-Cookie`를 7일로 깎을 수 있다.** 응답을 준 서버의 IP가 최상위 프레임 호스트의 IP와 앞 절반(IPv4 16비트 / IPv6 64비트)이 다르면 걸린다. **이 검사는 등록가능 도메인을 아예 보지 않는다 — 도메인을 맞춘 것만으로 안 막힌다.** 쿠키를 다시 구우면 아이가 7일 안에 한 번 들어오는 한 만료가 계속 밀린다

> **구현 상태 (2026-09-07 저녁 갱신)** — **붙었다** (E-3, `5d3e0f6`). 발급 후 12시간이 지난 요청에서 **남은 수명으로 쿠키를 다시 굽는다.** `exp` 는 늘리지 않는다 — 재발급은 쿠키의 수명을 되살리는 것이지 세션을 연장하는 것이 아니다. **위 Safari 7일 완화가 이제 실제로 작동한다.**

**남는 위험**: 8일 이상 안 들어오면 30일 전에 끊길 수 있다. 완화는 **`api.`도 Cloudflare 프록시 뒤에 두어 두 호스트의 IP 대역을 붙이는 것**이며 — Cloudflare가 `104.21.x.x`와 `172.67.x.x`를 섞어 주므로 **배포 후 `dig`로 공통 접두 비트를 실측해야 확정된다.** 실측 전까지 30일은 보장이 아니라 목표다.

### 폐기

**JWT는 발급 후 서버가 회수할 수 없다.** `children.token_version`(정수)을 JWT payload에 담고 검증 시 DB 값과 대조해 다르면 401. **폐기는 값을 1 올리는 것**이고, 그것으로 그 자녀의 **모든 기기가 한 번에 끊긴다.**

| 언제 | 계약상 보이는 것 |
|---|---|
| `POST /parents/children/{child_id}/access-code` 재발급 | **이전 기기의 자녀 토큰이 즉시 죽는다** |
| `DELETE /parents/children/{child_id}` | 즉시 파기 대상에 토큰도 포함 |
| 학부모의 분실 신고 | 화면은 E-4 (W2) |

Redis 블랙리스트를 쓰지 않는다 — 어차피 매 요청 `children`을 읽고(닉네임·`daily_cap`·타임존), 블랙리스트는 TTL 관리와 유실 시 재로그인 폭주가 붙는다.

> **구현 상태 (2026-09-07 저녁 갱신)** — **다 붙었다** (E-3, `5d3e0f6`). 매 요청에서 대조하고, 재발급·삭제 경로가 올린다. **위 표의 「모든 기기가 한 번에 끊긴다」가 이제 참이다.** 마이그레이션도 **Docker 로 실측했다** — 오프라인 렌더로만 보던 잔여 diff 가 `alembic check` 에 걸려 하나 나왔고(`64e8a9c`) 닫혔다.

### 로그아웃은 서버 호출이다

HttpOnly라 클라이언트가 쿠키를 지울 수 없다. `POST /parents/logout` · `POST /child/logout` (`Stage0.md` 1·2절). **삭제 `Set-Cookie`의 이름·`Path`·`Domain` 유무가 발급 때와 하나라도 다르면 지워지지 않는다.**

- **로그아웃은 인증을 요구하지 않는다** (2026-09-07 추가). **만료·손상된 쿠키를 지우려는 것이 로그아웃인데, 인증을 걸면 정작 지워야 할 상태에서만 401 로 막힌다.** 쿠키가 없어도 **204**. 지우는 것 말고 하는 일이 없어 열어 둬도 잃을 것이 없고, cross-site POST 는 `SameSite=Lax` 가 막는다
- **한쪽만 지운다.** `/parents/logout` 은 자녀 쿠키를 건드리지 않는다 — **가족 태블릿에 둘이 함께 앉아 있다**
- **삭제 쿠키의 속성은 발급 코드와 같은 자리에서 나와야 한다.** 복사해 적으면 언젠가 갈라지고, 갈라지면 **아무것도 안 지워지는데 204 는 그대로 나간다**

> **구현 상태 (2026-09-07 저녁 갱신)** — **붙었다** (E-3, `5d3e0f6`). 삭제 `Set-Cookie` 가 발급과 같은 속성으로 나가 쿠키가 실제로 지워진다.
> **로그아웃은 `token_version` 을 올리지 않는다 — 다른 기기는 그대로다.** 이 기기에서 내려오는 것이 로그아웃이고, **모든 기기를 끊는 것은 학부모의 재발급·삭제뿐**이다 (위 「폐기」 표). 가족 태블릿에서 내려왔다고 자기 다른 기기까지 잃으면, **접속 코드가 1회용이라 재발급 없이는 아무 데서도 못 들어온다** — 「아이가 스스로를 가둔다」의 더 넓은 판이다. 테스트가 물고 있다(`test_자녀_로그아웃은_다른_기기를_끊지_않는다`).
>
> **2026-09-07 PM 정정** — 이 자리에 한때 「로그아웃하면 다른 기기도 끊긴다」가 들어갔다. **옛 문장이 「아직 구현 전」과 「구현 뒤에도 참인 설계」를 한 문장에 담고 있어, 앞을 뒤집으면서 뒤까지 같이 뒤집혔다.** **구현 상태와 설계를 한 문장에 쓰지 않는다.**

### CORS

```http
Access-Control-Allow-Origin: https://app.geulmoheom.app   # 정확 일치. 와일드카드 불가
Access-Control-Allow-Credentials: true
Vary: Origin
```

preflight(`OPTIONS`) 응답에 추가 — **둘 다 `*`는 무효다.**
```http
Access-Control-Allow-Methods: GET, POST, PATCH, DELETE
Access-Control-Allow-Headers: Content-Type
Access-Control-Max-Age: 600        # 미설정 시 기본 5초
```

- **`allow_origins=["*"]`를 쓰지 않는다.** Starlette는 `allow_credentials=True`와 함께 써도 에러를 내지 않고 **요청 오리진을 그대로 반사한다.** CORS 오류가 안 나서 정상으로 보이지만, 실제로는 **임의의 사이트가 아이 세션으로 API를 호출할 수 있는 상태**다
- **`OPTIONS`는 인증을 요구하지 않는다.** preflight에는 쿠키가 실리지 않는다
- **예외·500 응답에도 CORS 헤더가 붙어야 한다.** 안 붙으면 프론트 콘솔에 CORS 오류만 보이고 진짜 원인이 감춰진다
- 인증 응답에 `Cache-Control: no-store` — Cloudflare가 앞단이다
- 클라이언트는 fetch에 **`credentials: 'include'`**. cross-origin이라 없으면 쿠키가 안 나간다

### iOS — 「홈 화면에 추가」가 접속 코드보다 먼저다

**iOS 홈 화면 앱은 Safari와 쿠키를 공유하지 않는다.** 쿠키·localStorage·IndexedDB 전부 별도 파티션이다. Safari 탭에서 접속 코드를 넣어 로그인한 뒤 홈 화면에 추가하면 **아이콘으로 연 앱은 로그아웃 상태**다.

**그리고 접속 코드는 1회 사용이다**(`Stage0.md` 1절). 즉 이것은 「두 번 입력」 불편이 아니라 **막힘**이다 — 탭에서 코드를 써버리면 홈 화면 앱에서는 학부모가 재발급하기 전까지 들어갈 수 없다.

**계약에 거는 규칙**: 자녀 인증 화면은 **standalone(홈 화면 실행)에서만 연다.** 브라우저 탭이면 설치 안내를 먼저 띄우고 **코드 입력을 열지 않는다.** 감지는 `matchMedia('(display-mode: standalone)')`·`navigator.standalone`. **E-3/E-4와 튜토리얼 「나침반 깨우기」(A-6) 설계에 걸린다.** iOS 26부터는 매니페스트 없이도 홈 화면 추가가 기본 standalone이라 적용 범위가 넓어진다.

> 일부 문서가 「설치 시 쿠키 1회 복사」를 주장하나 다수 출처가 부정한다. **복사되지 않는 전제로 설계한다.** 되면 보너스다.

### `*.pages.dev`에서는 인증이 동작하지 않는다 — 그대로 둔다

`pages.dev`가 Public Suffix List에 등재돼 있어 `<project>.pages.dev`의 등록가능 도메인은 `<project>.pages.dev`이고 **`geulmoheom.app`과 cross-site**다. 프리뷰 배포에서는 `Set-Cookie`가 저장되지도, 기존 쿠키가 실려 나가지도 않는다.

**커스텀 프리뷰 서브도메인을 붙이지 않는다.** 1인 체제라 `main` 직접 push이고(`adr/0008`) 상시 프리뷰 배포가 없다. **`*.pages.dev`를 CORS 오리진 목록에 넣지 않는다** — 넣는 순간 그 목록 자체가 공격면이 된다. 인증 흐름 확인은 **로컬(`.test` https)과 운영 도메인에서만** 한다.

## `/child/auth` 속도 제한 (2026-09-07 대표 승인)

**아이가 접속 코드를 넣는 경로는 토큰을 받기 전이라 위 표의 「자녀 토큰 기준」이 걸리지 않는다.** 별도로 건다.

**막으려는 것은 「코드를 계속 바꿔가며 찍어보는 것」이다.** 코드는 6자리(10⁶)·24시간·1회용이고, 지금 막고 있는 것은 해시 유니크와 **401 통일**(없는·만료된·이미 쓴 코드를 구분하지 않는다)뿐이라 **찍는 행위 자체는 안 막힌다.**
**무게는 여기 있다** — 노리는 쪽이 **특정 아이를 고르지 않아도 된다.** 그 시간에 살아 있는 코드가 여럿이면 **「아무 아이에게나」 걸린다.** 파일럿은 아이 10~30명이 동시에 코드를 들고 있는 상태다.

| | 무엇 | 무엇을 줄이나 |
|---|---|---|
| ① | **같은 기기에서 5회 실패 → 15분 잠금** | 찍는 속도 |
| ② | **같은 IP 는 더 느슨하게 병행** (시간당 30회 정도) | 찍는 속도 |
| ③ | **한 학부모가 동시에 살려둘 수 있는 코드를 자녀 수만큼으로 제한** | **걸릴 표적 수** |

**앞의 둘과 셋째가 다른 면을 막는다.** 셋을 같이 넣는다.

> **⚠ 함정 — 5회를 「코드마다」 세면 이 공격에 안 듣는다.**
> 공격자는 매번 **다른 코드**를 넣으므로 각 코드는 1회씩만 시도되고 **카운터가 5에 못 간다.**
> **세는 단위는 「요청자」다** — 기기를 먼저 보고 IP 를 보조로. 「5회 제한」이라고 하면 자연스럽게 코드 단위가 떠오르는 자리라 여기 적어 둔다.

**IP 를 빡빡하게 잡지 않는 이유** — 학교·가정처럼 **여러 아이가 같은 인터넷을 쓴다.** 여기서 조이면 **아무 잘못 없는 아이가 막힌다.** 기기 단위가 주고 IP 는 보조다.

**코드 자릿수는 늘리지 않는다** (대표 판정). 8자리로 늘리면 확률은 내려가지만 **아이가 옮겨 적기 어려워지고** 학부모 화면과 아이 화면이 함께 바뀐다.

**검토했다가 뺀 것 — 링크·QR.** 「숫자 대신 링크로 건네면 찍을 값이 없어진다」는 맞지만 **링크는 브라우저 탭에서 열린다.** 우리는 **탭에서 코드 입력을 아예 막아 두었다**(`문구.md` 3.2 — 1회용이라 탭에서 써버리면 홈 화면 앱으로 못 들어온다). **링크 방식은 그 막음을 무력화한다.**

**⚠ `CLIENT_IP_HEADER` 가 `PILOT_REQUIRED` 에 들어갔다.**
비어 있으면 **모든 요청이 앞단 IP 하나로 뭉쳐 시간당 30회가 전체 사용자에게 걸린다** — ②가 보호가 아니라 **장애**가 된다. 그래서 기동에서 막는다.
**`X-Forwarded-For` 를 그냥 읽지 않는다** — 클라이언트가 채워 보낼 수 있다. **어느 헤더를 믿을지는 앞단이 정하는 것이라 배포마다 다르고, 그래서 설정이다.**

**아이 화면 문구는 `문구.md` 2.1 `RATE_LIMITED` 다** — 2026-09-08 에 **「조금만 천천히 가볼까요」에서 「지금은 코드를 넣을 수 없어요. 15분 뒤에 다시 해볼까요」로 바꿨다.** 「조금만」이 15분에 대해 거짓이었다. **프론트에 새 분기는 필요 없다** — 자녀 인증 화면이 이미 `error.message` 를 그대로 띄운다 (`web/src/app/child/auth/page.tsx`).
