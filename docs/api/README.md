# API 계약 문서

**이 폴더는 할 일 목록이 아니라 계약 사양이다.** "이대로 만들라"이지 "지금 이걸 만들라"가 아니다.
**무엇을 언제 만드는지는 `docs/주차계획/`에 있다.**

| 파일 | 무엇 | 언제 읽나 | 바뀌는 빈도 |
|---|---|---|---|
| `공통규약.md` | Base URL · 인증 · 오류 코드 · 원문 취급 · 속도 제한. **Stage 0·1 공유** | 항상 | 거의 안 바뀜 |
| `Stage0.md` | Stage 0 엔드포인트 · 서버 처리 순서 · 데이터 모델 대응 | Stage 0 구현·화면 작업 | 자주 |
| `미결.md` | 아직 안 정한 것과 판단 기준, 결정 시점 | 그 항목을 정할 때 | 결정될 때마다 |
| `Stage1.md` | Stage 1 엔드포인트 | W6부터 | — (아직 없음) |

**구현할 때는 `공통규약.md` + 해당 스테이지 파일만 읽으면 된다.** `미결.md`는 결정하는 자리에서만 연다.

## 무엇이 진실인가 (SSOT)

| 무엇 | 진실 |
|---|---|
| 필드 · 응답 스키마 · 상태 코드 | **`/openapi.json`** — `make contracts`가 여기서 프론트 타입을 만든다 |
| 서버 처리 순서 · `outcome` 3분기의 의미 · 원문 취급 · 안전 규칙 · 아이 화면 문구 | **이 문서들** — OpenAPI가 표현하지 못한다 |

**스키마가 어긋나면 코드가 맞다.** 문서를 고친다.

## 고치는 법

`docs/`는 PM 소유다. 개발자는 직접 수정하지 않고 **커밋 메시지의 `명세 변경:` 줄**로 제안하고, PM이 별도 커밋으로 반영한다.
프론트가 개발 중 API 변경이 필요하면 `api-requests/open/`에 요청을 올린다.

## Stage 1이 생길 때

`Stage1.md`를 **새로 만든다.** `공통규약.md`를 복제하지 않는다 — 복제하면 두 파일이 갈라지고, 갈라진 쪽이 실제로 아이를 막는다.
