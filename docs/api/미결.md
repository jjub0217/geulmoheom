### 11-7. 삽화 URL 을 누가 열 수 있나 · **W4 (B-3 둘째 조각, 2026-09-08 발견)**

**「대표 몫」이다** (`CLAUDE.md` ③ 프라이버시 경로). 백엔드가 착수 직전에 올렸다.

> **⚠ 이것이 프리테스트 체인 위에 있다** (2026-09-08 백엔드 지적). 남은 조각이 「`attempts` 에서 비동기로 굽고 `artworks` 폴링에 실제 상태를 물린다」인데, **폴링 응답의 `url` 이 무엇인지가 곧 접근 정책**이다. **아이가 그림을 보려면 서빙 경로가 있어야 하고, 그 경로 모양이 이 판정의 답이다.**
> **그래서 저녁 보고까지 기다리지 않고 먼저 올린다.** 백엔드는 그동안 **서빙 자리를 안 만들고 멈춰 뒀다** — 만드는 순간 정책이 「공개」로 굳는다. 대비로 오브젝트 키에 난수를 붙였고, **판정이 오면 바꿀 자리는 `공개URL()` 하나**다.

**구멍** — 설정 이름이 `r2_public_base_url` 이라 **공개 버킷을 전제**한다. 그런데 **삽화는 아이 원문과 같은 창작물**이고 「내 책」의 `visibility` 는 **Stage 0 에서 항상 `private`** 이다(`Stage0.md` 6절). **URL 하나만 알면 누구나 열린다면 그 `private` 은 이름뿐**이다. `공통규약.md`·이 문서 어디에도 규칙이 없었다.

**선택지 셋**

| | 어떻게 | 값 |
|---|---|---|
| ① **공개 버킷 + 난수 키** | 추측 불가능한 키에 기댄다 | 싸다. **다만 URL 이 새면 끝이다** — 부모가 링크를 공유하거나 브라우저 히스토리·캐시에 남는다 |
| ② **서명 URL** | 만료 있는 URL 을 매번 발급 | 진짜로 비공개. **책 페이지마다 발급이 붙는다** |
| ③ **api 가 프록시한다** | `GET /artworks/{id}/image` 가 **쿠키 인증 뒤에** R2 에서 읽어 돌려준다 | **이미 있는 인증을 그대로 쓴다.** api 가 이미지 트래픽을 탄다 |

**PM 권고 — ③.** 파일럿 규모(10~30명 × 하루 5장)에서 **트래픽이 무의미하고**, **`private` 을 이름이 아니라 실제로 만든다.** 서명 URL 기계장치를 새로 들이지 않고 **`__Host-gm_child`·학부모 쿠키를 그대로 쓴다** — **남의 자녀 ID 가 404 인 규칙도 그대로 적용된다.** ①은 **「아무도 URL 을 모른다」에 기대는데, 그건 우리가 통제하지 못하는 가정**이다.

**규모가 커지면 ③이 비싸진다** — 그때 ②로 옮긴다. **파일럿 뒤에 다시 본다.**

**대표에게 묻는 것은 하나다 — 「아이 삽화가 URL 만 알면 열려도 되는가」.** 「아니오」면 ③이다.
