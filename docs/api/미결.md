# 아직 정하지 않은 것

**결정할 때 무엇을 고려하는지**를 담는다. 결정이 나면 이 문서에서 지우고 `Stage0.md` 또는 `공통규약.md` 본문에 반영한다.
**언제 정하는지는 `docs/주차계획/`이 정한다** — 여기를 보고 스스로 골라 착수하지 않는다.

**이 문서가 줄어드는 것이 곧 진척이다.**

---

### 11-4. 자정 기준 — 일일 상한 리셋 · **⚠ 시점이 지났다. 파일럿 1이 이 값을 안고 돈다**

**「W3 (A0-5 구현 시점)」으로 적혀 있었는데 A0-5 는 W4 에 섰고 이 미결은 안 정해졌다** (2026-09-10 확인). **정해지지 않은 채 코드가 먼저 갔다** — `card_store.오늘시작()` 이 **UTC 자정**으로 잠정 구현돼 있고 주석이 「미결 11-4 에서 한 번에 정한다」로 자리를 남겨 뒀다.

**⛔ 잠정값이 한국 아이에게 뜻하는 것: 「오늘」이 오전 9시에 바뀐다.** UTC 자정 = **KST 오전 9시**다. 아이가 **아침 9시 전에 쓰면 전날 몫으로 세어진다** — 어제 5장을 다 쓴 아이는 **오늘 아침에 못 쓰고 9시가 지나야 열린다.** 주말·방학에 실제로 밟는다.
**막지는 않는다** — 우회가 아니라 **하루가 밀리는** 방향이라 상한이 헐거워지지는 않는다. **다만 파일럿이 재는 것이 「하루에 얼마나 쓰는가」라 경계가 아이 체감과 다르면 그 데이터가 흔들린다.**

제안: 클라이언트 타임존 헤더(`X-Timezone`), 서버 계산 (2절 참조)

- 일일 상한은 **MVP 필수 가드레일**이다. 클라이언트가 보낸 타임존을 그대로 믿으면 **헤더를 바꿔 상한을 우회**할 수 있다
- 대안: 서버 KST 고정 / 자녀 생성 시점에 타임존을 확정해 저장 후 변경 불가
- 밤 11시 50분에 시작한 세션이 자정을 넘길 때의 처리도 함께 정한다
- **학부모 화면의 「오늘 썼어요」도 같은 경계를 본다** (2026-09-08 추가). `card_store.오늘시작()` 한 자리로 모았다 — **갈라지면 「오늘 했다는데 카드가 안 준다」가 된다.** **이 미결을 정할 때 학부모 화면도 같이 움직여야 한다** — 아이 쪽만 자녀 타임존으로 옮기면 **그날 두 화면이 다른 하루를 센다**
