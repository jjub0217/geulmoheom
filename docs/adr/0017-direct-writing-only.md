# 0017 — 본편은 직접 쓰기로만 진행한다

결정: 2026-09-19, 사용자 명시 요청 「선택지를 없애고 직접 쓰기만 제공」.

## 맥락

비전은 아이가 직접 쓴 문장으로 모험을 진행하고 그 글과 삽화를 책에 남기는 경험이다. 그러나 종전 본편은 GM이 작성한 선택지를 누르는 것만으로도 최대 12턴 뒤 완결할 수 있었다. 선택지 라벨은 아이 글이 아니므로 책에서 제외되었고, 직접 쓴 턴이 없으면 책 본문이 비었다. 문장의 평가를 선택지에도 적용하는 것만으로 직접 쓰기가 보장되지는 않았다.

## 결정

- `/chapter`에서 선택지 버튼을 제거한다. 힌트로 전환하거나 선택 문장을 입력칸에 자동으로 채우는 기능도 만들지 않는다.
- 상황을 읽고 자신의 행동·방법·느낌을 직접 입력하여 보낸다. 입력창 라벨은 「탐험가는 어떻게 할까?」다. 「아니면 네가 직접 써도 돼」는 사용하지 않는다.
- 인증된 `POST /turns`는 직접 입력한 `text`만 진행시킨다. 구형 `choice_id` 요청은 기존 검증 오류 형식의 422로 거부하며 평가·GM·턴 소비·저장을 시작하지 않는다.
- 인증, 안전 검사, 개인정보 가림, 되묻기, 일일 상한, 시련의 네 해결 경로, 챕터 완결 규칙은 유지한다. 글자 수를 새 통과 조건으로 삼지 않는다.
- 책에는 기존대로 개인정보 가림 후 아이의 원문을 저장한다. 과거 선택 기록이나 이미 저장된 책은 삭제·재작성하지 않는다.
- 스키마 필드와 GM 내부 `choices` 생성은 구형 응답·저장 상태 호환을 위해 당장 제거하지 않는다. 화면에서는 쓰지 않으며 선택 제출도 허용하지 않는다. 스키마에 필드가 남아 있다는 이유로 선택지 진행을 복원하지 않는다.

## 대체하는 규칙

`MVP_PRD.md` 2.4의 선택지 입력, A-1의 선택지 노출, A-3의 선택지·입력 동시 노출, B-1의 선택지 평가 규칙, `api/Stage1.md` 2절의 선택 제출 허용, `용어사전.md`의 선택지·직접 쓰기 설명, `문구.md` 1.18의 선택지 뒤 유도 문구를 대체한다. 과거 구현·검증 기록은 당시의 사실로 남긴다. 비전의 직접 쓰기 원칙은 변경하지 않는다.

## 결과와 확인 범위

처음부터 글쓰기가 유일한 진행 방법으로 보인다. 막힌 아이에게는 기존 되묻기가 남는다. 새 안내의 이해도나 동기는 UI 검사만으로 판단할 수 없으며, 실제 아이의 사용 관찰은 별도다.
