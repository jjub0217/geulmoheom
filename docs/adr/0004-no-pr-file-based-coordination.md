# 0004 — PR·GitHub 이슈·브랜치 보호를 쓰지 않고, 저장소 파일과 직접 push로 운영한다

날짜: 2026-08-30 · 상태: 채택

## 맥락

팀은 둘이다. `@jinioh88`(PM 겸 백엔드, 저장소 소유자)과 `@jjub0217`(프론트). 두 사람 모두 Claude Code로 작업한다.

처음에는 표준적인 게이트를 설계했다 — feature 브랜치 → PR → PM 승인 → `main`, CODEOWNERS로 소유자 지정, 브랜치 보호로 강제. 설계 과정에서 세 가지가 드러났다.

1. **패키지별 소유자를 두면 머지가 막힌다.** `web/ @jjub0217`로 두면 그 패키지의 유일한 개발자가 곧 PR 작성자이고, GitHub은 자기 PR을 자기가 승인할 수 없다. 승인 가능한 사람이 0명이 된다.
2. **PM 게이트가 반쯤 가짜다.** `@jinioh88`은 PM이자 백엔드다. 자기 PR을 자기가 승인할 수 없으므로 admin 권한으로 직접 머지하게 된다. 백엔드 코드에는 처음부터 실질 리뷰가 없다.
3. **저장소가 비공개 무료 플랜이라 기술적 강제가 불가능하다.** 브랜치 보호를 걸 수 없고, CODEOWNERS 자동 리뷰어 지정도 동작하지 않는다. GitHub Pro(월 $4)가 필요하다.

즉 유료 전환 없이는 강제할 수단이 없고, 유료로 가더라도 게이트의 절반은 형식이었다.

## 결정

**절차를 최소화하고, 조율을 저장소 안의 파일로 옮긴다.**

1. **PR을 쓰지 않는다.** `main`에 직접 push한다
2. **GitHub 이슈를 쓰지 않는다.** 프론트↔백엔드 조율은 `api-requests/` 폴더로 한다 — `open/`(미결) → `done/`(완료), 종류는 `요청`·`합의`·`작업`
3. **브랜치 보호를 걸지 않는다.** `.github/CODEOWNERS`는 지우지 않고 **책임 소재 기록으로만** 남긴다
4. **`docs/`는 PM 소유**로 하되 규약으로만 지킨다. 프론트는 직접 수정하지 않고 `api-requests/`에 올리거나 PM에게 말한다

## 근거

- **막을 수단이 없는 규칙은 규칙이 아니다.** 무료 플랜에서 브랜치 보호를 못 쓰는 이상, PR 정책은 지켜지기를 바라는 관습일 뿐이다. 그럴 바에는 절차를 없애고 그 사실을 명시하는 편이 정직하다
- **게이트가 이미 반쯤 가짜였다.** 백엔드 코드는 어차피 admin 머지였다. 형식만 남은 절차는 리듬만 끊는다
- **충돌이 드물다.** 두 사람이 `web/`·`api/`로 갈려 있어 같은 파일을 만질 일이 거의 없다
- **예방을 앞단으로 옮겼다.** 루트·`api/`·`web/`의 `CLAUDE.md` 「절대 하지 않는 것」은 **코드가 써지기 전에** 작동한다. PR은 써진 뒤에 잡는 사후 장치다
- **저장소 하나로 완결된다.** 이슈에 흩어지지 않고, 나중에 GitHub을 떠나도 기록이 남는다

## 대안

- **GitHub Pro (월 $4)** — 브랜치 보호와 CODEOWNERS가 작동한다. 지금은 쓰지 않기로 했다. **되돌릴 때 가장 먼저 볼 선택지**
- **저장소 공개 전환** — 무료로 보호가 열리지만, 아동 대상 제품의 미공개 기획·페르소나·안전 정책이 전부 들어 있어 불가
- **`pre-push` 훅으로 `main` 차단** — 만들었다가 철회했다. 로컬 장치라 설치한 사람에게만 적용되고 `--no-verify` 한 번에 넘어간다. 강제가 아니면서 마찰만 준다

## 결과 — 감수하는 것

- **코드 리뷰가 없다.** Claude가 쓴 코드를 아무도 읽지 않은 채 `main`에 들어갈 수 있다. Claude의 오류는 컴파일되고 린트를 통과하는 모양이라 CI가 못 잡는다
- **알림이 없다.** 상대가 무엇을 올렸는지 아무도 알려주지 않는다
- **판단 근거가 흩어진다.** PR 본문이 없어 커밋 메시지가 유일한 기록이다
- **CI가 사후 통보다.** 깨진 코드가 `main`에 들어간 다음 빨간불이 뜬다
- **`main`이 공용 작업대다.** 반쯤 된 것을 올리면 상대가 즉시 막힌다

## 결과 — 대신 세운 것

- **`CLAUDE.md` 3종의 「절대 하지 않는 것」** — 원문 로깅, `types.gen.ts` 수동 편집, 아이 화면 금지어. 앞단 예방
- **커밋 전 Claude에게 `git diff` 검토 요청** — PR 리뷰의 대체품 중 가장 싸다
- **`/api-check`** — 알림의 보조. 단 사용자가 칠 때만 동작한다
- **선택적 PR** — 정책이 아니라 판단. ① 계약 변경 ② 파일 5개·200줄 초과 ③ 안전·프라이버시 경로
- **contracts 검증 잡** (`ci.yml` `TODO(W1)`) — 사람이 절대 못 잡는 계약 어긋남을 기계가 잡는다. **이 체제에서 가장 값어치가 큰 장치이므로 W1에 반드시 켠다**

## 재검토 시점

아래 중 하나라도 해당하면 이 ADR을 다시 연다.

- **사람이 3명 이상**이 될 때 — 충돌 빈도와 리뷰 필요가 함께 오른다
- **GitHub Pro로 올릴 때** — `.github/CODEOWNERS`와 `ci.yml`의 `all-green`이 그대로 게이트로 켜진다. `docs/작업흐름.md`에 절차가 적혀 있다
- **`main`이 깨져 상대가 막히는 일이 반복될 때** — 규약이 안 지켜진다는 신호다
- **아이 원문이 로그에 남는 사고가 한 번이라도 날 때** — 앞단 예방이 실패했다는 뜻이므로 사후 장치가 필요하다
