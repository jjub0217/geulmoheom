# 0005 — LLM 프로바이더를 Anthropic `claude-opus-5`에서 Google Gemini로 교체한다

날짜: 2026-08-31 · 상태: 채택 · **`MVP_PRD.md` 9장 #1(2026-08-29)을 대체함**

## 맥락

PRD 9장 #1은 Evaluator·GM 모두 `claude-opus-5`로 확정했다. 그 근거는 이랬다 — **"파일럿 총 비용 ≈ $30 수준이라 비용보다 루브릭 일치율(B-2, 80%)을 우선한다."** 비용이 무시할 만한 크기라는 전제 위에 품질을 골랐다.

2026-08-31 대표가 프로바이더를 Google Gemini(`google-genai` SDK)로 바꾸기로 했다. **교체 동기는 비용이다.** 즉 위 근거의 전제가 뒤집혔다. 근거를 고쳐 쓰지 않고 결론만 바꾸면 PRD가 거짓말을 하게 되므로 ADR로 남긴다.

바꾸는 시점이 가장 싸다는 점도 작용했다. W1 5번 「LLM 스모크」가 아직 미착수여서 **LLM 호출 코드가 저장소에 한 줄도 없다.** 프롬프트·루브릭은 프로바이더 무관이고, LangGraph도 무관하다.

## 결정

1. **프로바이더를 Google Gemini(`google-genai`)로 교체한다.** GM · Evaluator · 상태 추출기 전부
2. **구체 모델명은 지금 정하지 않는다.** W1 5번 스모크로 후보를 좁히고, W2 예시셋 40개 벤치로 Evaluator 모델을 확정한다. PRD 1.5절·4.5절에 모델명 대신 **역할별 요구사항**만 남긴다
3. **유료 티어를 쓴다.** 무료 티어는 쓰지 않는다 (아래 근거 2번)
4. **루브릭 일치율 80%(B-2)는 합격 조건으로 유지한다.** Gemini가 이를 못 넘기면 이 ADR을 되돌린다 — 비용 때문에 바꾼 것이지 기준을 낮춘 것이 아니다
5. **E-1 Moderation 구조는 W2 검증 후 결정한다.** 현재 구조(별도 Moderation 단계)를 기본으로 두되, Gemini 내장 안전 필터로 대체 가능한지 확인한다 (아래 「미결로 남는 것」)

## 근거

- **비용이 대표의 판단 기준이 되었다.** 파일럿 $30은 감당할 수 있어도, 파일럿 이후 사용자당 반복 비용은 다른 크기의 문제다. Stage 0은 세션당 LLM 호출이 Evaluator 1회로 고정되어 있어(아키텍처 문서 2장) 사용자 수에 정비례한다
- **지금이 교체 비용의 최저점이다.** 호출 코드 0줄. 하루만 늦어도 Evaluator·상태 추출기·Safety 세 곳에 프로바이더 코드가 박힌다
- **이식 비용이 낮다.** Evaluator 루브릭 G0~G3, few-shot 예시셋, GM 프롬프트, 스캐폴딩 템플릿은 전부 프롬프트라 그대로 옮겨간다. 구조화 출력도 양쪽 다 지원. LangGraph 상태 머신은 프로바이더를 모른다
- **`/api/v1` 계약이 안 바뀐다.** 프론트(`@jjub0217`) 영향 0. `docs/api/Stage0.md`의 서버 처리 순서에서 모델명 한 줄만 바뀐다
- **무료 티어를 쓰지 않는 이유** — Gemini API 무료 티어는 입력을 제품 개선에 활용한다(유료 티어는 아니다). PRD 1.1b와 `docs/api/공통규약.md`가 못 박은 원칙은 "아이 원문의 라벨링 활용은 `parents.labeling_consent` 게이트를 통과해야 한다"이다. 무료 티어를 쓰면 **동의하지 않은 아이의 문장까지 외부 학습에 들어간다.** 이는 제품의 4대 가드레일 중 프라이버시 축을 정면으로 깨고, KPI 「안전 CS 이슈 0건」과도 충돌한다. **교체의 동기가 비용이었으므로 이 결정은 동기를 일부 되돌린다** — 그럼에도 뒤집을 수 없는 선이다

## 대안

- **`claude-opus-5` 유지** — 8/29 결정 그대로. 루브릭 일치율이 검증된 적은 없으므로(W2 예정) 품질 우위는 아직 가정이다. 되돌릴 때의 기본 선택지
- **역할별 프로바이더 분리** (Evaluator만 Gemini, GM은 Anthropic) — 비용의 대부분은 호출 빈도가 높은 Evaluator다. Stage 1까지 GM 품질을 지키면서 비용을 줄이는 절충안. 지금은 배포·키·SDK를 둘로 늘릴 만한 근거가 없어 채택하지 않았다. **W2 벤치에서 GM 품질이 문제되면 가장 먼저 볼 안**
- **Gemini 무료 티어** — 비용 0. 위 근거대로 채택 불가
- **W1 스모크를 양쪽으로 돌려 실측 후 결정** — 가장 정확하지만 W1 일정에 반나절~하루가 더 든다. 대표가 교체를 이미 정했으므로 실측은 W2 벤치로 미룬다

## 결과 — 감수하는 것

- **비용 이점의 크기를 아직 모른다.** 유료 티어 기준 실제 절감액은 W1 5번 스모크에서 토큰·지연과 함께 실측한다. 절감이 기대 이하면 이 ADR의 동기 자체가 흔들린다
- **품질이 검증되지 않았다.** 8/29 결정은 품질 우선이었고, 이번 교체는 그 축을 비용으로 옮긴다. B-2 일치율 80%가 유일한 안전장치다
- **E-1 일정 위험.** Gemini는 안전 필터가 API 호출에 내장되어 별도 Moderation을 두는 현재 구조와 다르다. `docs/안전_어휘_기준.md` 2장 화이트리스트(검·베다·찌르다·폭탄·저주 등 판타지 전투 허용)를 필터 임계값으로 재현하지 못하면 오탐이 늘고, 그것은 그 문서가 실패 모드로 적어둔 바로 그 지점이다 — "오탐은 아이의 흐름을 끊고 글쓰기 울렁증을 건드린다". W2 B-1/B-2, W3 E-1 일정 재검토가 필요할 수 있다
- **약관은 변한다.** 무료/유료 티어의 데이터 활용 조항은 Google이 바꿀 수 있다. 한 번 확인하고 끝낼 일이 아니다

## 미결로 남는 것

| 무엇 | 언제 | 판단 기준 |
|---|---|---|
| **약관 확인 + 티어 선택 기록** | **W1, 스모크(5번) 착수 전** | 유료 티어의 데이터 활용 조항을 실제 약관에서 확인하고 날짜·조항을 이 ADR에 덧붙인다. 확인 전에는 아이 원문을 API에 보내지 않는다 |
| 구체 모델명 (Evaluator) | W2 | 예시셋 40개 일치율 80% + 1.5초 이내 (PRD 4.5) |
| 구체 모델명 (GM, Stage 1) | W6 전 | 롤플레잉 일관성·한국어 아동 어휘 |
| E-1 Moderation 구조 | W2 | 안전 어휘 화이트리스트 30개 시나리오에서 **미탐 0건**을 유지하면서 오탐이 허용 범위인가. 못 넘으면 별도 Moderation 단계 유지 |
| 절감액 실측 | W1 5번 | 스모크에서 토큰·지연·단가 기록 |

## 재검토 시점

- **B-2 일치율이 80%에 못 미칠 때** — 되돌리거나, 「대안」의 역할별 분리로 간다
- **E-1 오탐이 안전 시나리오 30개에서 허용 범위를 넘을 때** — W3 이전에 구조를 되돌린다
- **W1 실측 절감액이 기대 이하일 때** — 교체 동기가 사라진다
- **Google이 데이터 활용 조항을 바꿀 때**
