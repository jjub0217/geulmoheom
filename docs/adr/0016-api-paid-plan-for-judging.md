# 0016 — 심사 기간 동안 **api 만 유료 요금제**로 올린다

날짜: 2026-09-17 · 상태: **✅ 채택** (2026-09-17 대표 판정) · **`adr/0012` 「감수하는 것 ①」을 심사 기간에 한해 대체한다**

## 맥락

**AI 해커톤에 제출한다** (2026-09-17 확정 · 마감 **09-18**). **심사자가 심사 기간 동안 서비스 주소로 들어와 직접 써 본다.**

**`adr/0012` 가 무료 요금제를 고르며 값 셋을 감수했고, 그중 ① 이 여기 걸린다.**

> **⛔ ① Cold Start 30~50초 — 아이가 맞는다**
> Render 무료 인스턴스는 **15분간 요청이 없으면 잠든다.** … 아이가 앱을 열면 **30~50초를 기다린다**

**⛔ 배포가 안 된 것이 아니다.** 주소는 살아 있고 누구나 들어올 수 있으며 요청이 거절되지도 않는다(Vercel 프록시 상한 120초 > 콜드 스타트 30~50초). **첫 요청이 느릴 뿐**이다.

**그런데 심사에서는 「느리다」가 「안 된다」와 같다.**
- **심사자는 우리를 모른다.** 화면이 떴는데 30초 넘게 아무 반응이 없으면 **고장으로 읽고 닫는다**
- **심사자는 띄엄띄엄 들어온다.** 한 명 보고 20분 뒤 다음 사람이 오면 **또 걸린다** — 15분만 비면 다시 잠든다
- **⛔ 삽화까지 못 본다.** 삽화 폴링이 **15초 타임아웃**(`Stage0.md` 5절)이라 잠들어 있으면 **기본 에셋으로 떨어진다.** **「썼더니 그림이 나왔다」가 첫 심사자에게만 안 보인다** — 이 제품이 파는 것이 그것이다

## 결정

**`geulmoheom-api`(Web Service) 하나만 유료로 올린다.**

| 서비스 | 요금제 | 왜 |
|---|---|---|
| **`geulmoheom-api`** (web) | **free → Starter** | **잠드는 것이 이것 하나다** |
| `geulmoheom-cache` (Key Value) | free 그대로 | 잠들지 않는다. **캐시라 날아가도 된다**(`0012` 감수 ③) |
| `geulmoheom-db` (Postgres) | **free 그대로** | 잠들지 않는다. **90일 삭제(`0012` 감수 ②)는 12월 중순이라 심사와 무관**하다 — `미룬것.md` 에 그대로 둔다<br>**⛔ 2026-10-12 정정 — 「90일 · 12월 중순」은 틀렸다.** 실제 만료는 30일이라 **2026-10-10 에 만료됐고, 2026-10-12 에 유료(월 $6)로 올렸다** (`adr/0018`) |

**돈 — 월 $7 ≈ 약 9,800원** (환율 1달러≈1,400원 대략값).

**⛔ 「돈 안 드는 길을 먼저 찾는다」를 지켰다.** 무료 갈래(**외부 모니터링이 5~14분마다 `/healthz` 를 때린다** — `0012` 「따라오는 작업」 ②)를 먼저 올렸고, **대표가 그걸 보고 유료를 골랐다.** 근거는 **확실성**이다 — 두드리는 간격 사이에 배포가 새로 돌면 그때는 또 걸린다.

## ⛔ 요금제가 두 층이다 — **여기서 한 번 헤맸다** (2026-09-17)

**Render 의 「요금제」가 두 개이고 이름이 비슷해 섞인다.**

| 층 | 무엇 | 값 | 우리 |
|---|---|---|---|
| **워크스페이스 요금제** | **계정 등급.** `Billing → Update Plan` 에 있다 — **Hobby / Pro / Scale** | Hobby **$0** · Pro **$25** · Scale $499 | **⛔ Hobby($0) 그대로 둔다** |
| **서비스 컴퓨트** | **서버 하나의 크기.** 각 서비스 화면의 `Compute` 에 있다 | $0(Free) · **$7** · $25 … | **✅ `geulmoheom-api` 만 $7** |

**⛔ 우리가 올리는 것은 아래층이다.** **`Billing → Update Plan` 화면에는 $7 이 아예 안 나온다** — 거기는 위층이다. **거기서 Pro 를 고르면 $25 가 따로 붙고 서버값은 그대로 남는다. 3.5배를 내고 문제는 안 풀린다.**

**⚠ 다만 카드는 위층 화면(또는 `Billing → Payment Method`)에서 넣는다.** **유료 컴퓨트를 고르려면 결제 수단이 먼저 있어야 한다** — 없으면 `failed to update plan: invalid plan 0.5c-512mb. Plan requires payment information on file` 가 뜬다. **결함이 아니라 순서 문제다.**

**⭐ 카드를 넣어도 Hobby 는 $0 이다.** 청구되는 것은 **$7 서버값뿐**이다.

**⚠ 무료 시간이 모자란 것이 아니다** — 화면이 `Free Instance Hours 19.72 / 750` 로 보여 준다. 한 달이 720시간이니 **무료로도 계속 켜 둘 양은 된다.** **문제는 시간이 아니라 「안 쓰면 내려간다」는 규칙**이고, 그래서 **무료로 두드려 깨우는 갈래(㉠)도 시간 안에 들어온다** — 대표가 그것을 보고도 확실성을 골랐다.

## ✅ 실행됐다 — 2026-09-17

**사용자가 카드를 등록하고 `geulmoheom-api` 를 `$7 / 0.5 CPU / 512 MB` 로 올렸다.** 워크스페이스는 **Hobby($0) 그대로**다.

**⏳ 확인은 아직이다** — **20~30분 아무 요청도 없이 두었다가 서비스 주소를 열어 바로 뜨는지 본다.** 그게 유일한 확인이다.

**⛔ 그리고 여기서 따라오는 규칙 하나 — 심사 기간에는 `main` 에 push 하지 않는다.**
**Render 가 `main` push 를 보고 자동 배포**하고, **새 배포 직후의 첫 요청은 유료여도 느리다.** **유료는 「안 잠드는 것」이지 「시작이 즉시」가 아니다**(아래 「되는 것 / 안 되는 것」).
**세 세션이 다 `main` 에 직접 push 한다**(루트 `CLAUDE.md` — PR 없음). **그래서 이 규칙은 사람이 지켜야 하고, 막아 주는 장치가 없다.**
**⚠ 급한 결함이면 물론 올린다** — **다만 「올렸다」를 그 자리에서 서로 알린다.** 심사자가 그때 들어오면 느린 것이 그 때문이지 요금제가 안 먹은 게 아니다.

## ⛔ 실행은 대시보드다. 이 저장소에서 안 된다

**Render 대시보드 → `geulmoheom-api` → Settings → Instance Type.**

**`render.yaml` 의 `plan: free` 를 고쳐도 아무 일도 안 일어난다** — 그 파일은 **적용되지 않는다**(Web Service 를 손으로 만들었으므로 「값의 출처」로만 읽힌다. 파일 머리말과 `943a0e0` 참조). **여기 값을 적는 것은 기록이지 설정이 아니다.**
**2026-09-17 하루에 같은 자리를 두 번 만났다** — `TUTORIAL_ENABLED` 와 헬스체크. **둘 다 사람이 대시보드에 넣어서 돌았다.**

## ⏳ 안 정한 것 — **심사 뒤에 내릴 것인가**

**정하지 않았다.** 적어 두는 이유는 **안 적으면 계속 나가기 때문**이다.

- **내린다면** — 되돌리는 순간 `0012` 감수 ① 이 그대로 돌아온다. **베타를 열면 그때 또 걸린다**
- **둔다면** — 월 약 9,800원이 계속 나간다. **베타 전에 어차피 필요할 수 있다**

**⛔ 베타 범위를 정할 때 같이 본다.** 그때까지는 **켜 둔다.**

## 되는 것 / 안 되는 것

**✅ 된다** — 심사자가 언제 들어와도 **첫 화면이 바로 뜬다.** 삽화도 15초 안에 온다.
**⛔ 안 된다** — **새 배포 직후의 첫 요청은 여전히 느리다.** 유료는 「안 잠드는 것」이지 「시작이 즉시」가 아니다. **심사 기간에는 배포를 안 하는 것이 맞다.**
**⚠ 안 바뀌는 것** — `0012` 감수 ②(Postgres 90일)·③(Redis 영속성)은 **그대로**다.
**⛔ 2026-10-12 정정 — 감수 ② 는 「90일」이 아니라 「30일 만료 + 14일 뒤 삭제」였고, `adr/0018` 에서 유료 전환으로 닫혔다.** ③ 은 그대로다.
