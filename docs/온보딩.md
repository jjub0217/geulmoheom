# 글모험 — 합류 가이드

> **새로 합류한 개발자가 첫 주에 읽는 지도.** 무엇을 어떤 순서로 읽고, 각 문서에서 무엇을 얻어야 하는지를 적었다.
> **이 문서는 지도이지 내용이 아니다.** 내용을 여기 복사하지 않는다 — 복사한 순간 원본과 갈라지고, 갈라진 쪽을 누군가 믿는다.
> 다 읽는 데 **약 4~5시간**, 첫 커밋까지 **2~3일**을 잡는다.

---

## 0. 30초 요약

**아이가 직접 쓴 문장으로만 움직이는 모험.** 초등 5~6학년 아이가 장면을 마주하고 "무엇을 할지" 자기 말로 쓴다. 구체적으로 쓸수록 세계가 선명하게 반응한다 — 더 좋은 삽화, 더 극적인 전개. AI는 대필자가 아니라 **아이의 문장을 기다리는 게임 마스터**다. 모험은 아이의 책이 되어 남고, 안전한 울타리 안에서 모든 사용자에게 공유된다.

**우리가 지금 증명하려는 것은 딱 하나다** — *시각 보상만으로 아이가 더 구체적으로 쓰게 되는가*(가설 H2). 그게 참이면 나머지를 만든다.

## 1. 첫날 · 왜 만드는가 (약 40분)

### 1-1. `docs/비전.md` — 정독한다

**다른 어떤 문서보다 먼저 읽는다.** 짧지만 이 저장소에서 유일하게 "바뀌지 않아야 하는" 문서다. 기능이 늘고 사람이 바뀌어도 이건 그대로다.

읽고 나면 **이 다섯 가지를 자기 말로 설명할 수 있어야 한다.**

| 원칙 | 한 줄 | 이게 깨지면 |
|---|---|---|
| ① 노력이 보상을 만든다 | 버튼이 아니라 **써서** 얻는다 | 그냥 또 하나의 게임이 된다 |
| ② AI는 대필하지 않는다 | "알아서 써줘"에 우리는 쓰지 않는다 | 학부모가 우리를 믿을 이유가 사라진다 |
| ③ 끝이 있다 | 20분이면 끝난다. **세션 시간은 KPI가 아니다** | 우리가 반대하던 그 앱이 된다 |
| ④ 모든 아이의 방식을 인정한다 | 검·설득·관찰·돌봄이 **같은 보상** | 절반의 아이를 잃는다 |
| ⑤ 안전은 첫날부터 있는 바닥 | 나중에 붙이는 기능이 아니다 | 한 건으로 끝난다 |

**4장의 질문 5개는 외워둔다.** 새 기능·새 제안 앞에서 하나라도 "아니오"면 멈추는 기준이고, 두 사람 의견이 갈릴 때 돌아오는 곳이다. 비전 7장의 안내대로, **읽고 나서 그 5개를 자기 말로 다시 써서 팀에 공유한다** — 이게 합류 첫날의 유일한 과제다.

**5장 「우리가 하지 않을 것」은 특히 중요하다.** 나중에 좋은 아이디어처럼 보이는 것들이 여기 미리 적혀 있다.

### 1-2. `docs/페르소나정의.md` 3장·4장·7장 — 누구를 위해

전체를 다 읽을 필요는 없다 (길다). **3장(학생), 4장(학부모), 7장(4대 가드레일)**만 본다.

- 학생 페르소나는 **둘**이다 — A 이민준(행동·성취) / B 김서윤(서사·관계). **성별 구분이 아니라 플레이 동기 구분**이다. 원칙 ④가 여기서 나온다
- **만 10~12세만 타깃**이다. 중학생·저학년은 지금 타깃이 아니다
- 타깃 연령·페르소나·KPI 수치는 **이 문서가 단일 진실 원천(SSOT)**이다. 다른 문서와 충돌하면 이쪽이 맞다

> 이 시점에 답할 수 있어야 하는 질문: **"우리는 왜 아이에게 점수를 보여주지 않는가?"**

## 2. 둘째 날 · 무엇을 목표로 하는가 (약 50분)

**우리는 기능을 만드는 게 아니라 가설을 검증한다.** 이 구분이 온보딩에서 가장 중요하다.

### 2-1. `docs/검증가설_성공지표.md` 1장·2장·5장

- **H0**이 제품 전체를 한 문장으로 담고, **H1~H5**는 그걸 쪼갠 것이다
- **Stage 0은 H2 하나만 판정한다.** H3(재방문)를 여기서 재지 않는 이유가 1장에 적혀 있다 — 서사가 없는 슬라이스에서 재방문율이 낮으면 "보상이 안 먹혀서"인지 "이야기가 없어서"인지 **구분할 수 없기 때문**이다
- **합격선·경고선**이 곧 판정 기준이다. 5장 판정 규칙까지 본다

### 2-2. `docs/페르소나정의.md` 8장 — 출시 후 KPI

챕터 완결률 85% · 회당 입력 150자 · Sean Ellis 40% · NPS 60 · 30일 리텐션 60% · **안전 CS 이슈 0건**.

**단, 파일럿에는 그대로 쓰지 않는다.** 표본이 작고 제품이 거칠어서 `검증가설_성공지표.md`가 별도 합격선을 둔다. 헷갈리면 파일럿 = 합격선, 출시 = KPI.

> 이 시점에 답할 수 있어야 하는 질문: **"내가 지금 짜는 이 코드는 어떤 가설을 검증하나?"** 답이 안 나오면 우선순위를 잘못 잡은 것이다.

## 3. 셋째 날 · 어디까지 만드는가 (약 90분)

"어디까지"에는 **층위가 다른 답이 셋** 있다. 셋 다 알아야 한다.

| 질문 | 답이 있는 곳 | 시간 축 |
|---|---|---|
| 제품 전체로 어디까지? | `docs/백로그.md` — P0-a / P0-b / P1 / P2 | 분기 |
| 이번 MVP로 어디까지? | `docs/MVP_PRD.md` 3장(기능 상세) · 8장(마일스톤) | 월 |
| **이번 주에 어디까지?** | **`docs/주차계획/W<n>.md`** | 주 ← **실무에서 이게 경계다** |

### 3-1. 2단계로 나눠 만든다

| 단계 | 이름 | 무엇 | 증명할 것 |
|---|---|---|---|
| **Stage 0** | 나침반 퀘스트 | 서사 없는 단일 턴 — 장면 카드 → 묘사 입력 → 등급별 삽화 해금 | **H2** |
| **Stage 1** | TRPG | Stage 0 위에 GM 서사·상태·챕터·하드 피니시 | H1·H3·H5 |

**Stage 0을 통과하지 못하면 Stage 1을 만들지 않는다.** 이게 이 저장소의 가장 큰 범위 결정이다 (`docs/adr/0001`).

Stage 0 코드는 버려지는 습작이 아니다. **같은 코드가 세 가지로 쓰인다** — 파일럿 1 검증 슬라이스 → 신규 사용자 튜토리얼 「나침반 깨우기」 → 기존 사용자 「나침반 연습」 모드.

### 3-2. 안 만드는 것을 먼저 안다

- `docs/비전.md` 5장 — **원칙상 영원히 안 만드는 것**
- `docs/백로그.md` 4·5장 (P1·P2) — **나중에 만들 수도 있는 것.** 지금은 아니다
- 소설/그림책/만화 멀티 포맷, 소셜 커뮤니티, PDF, 오프라인 미션 = 전부 Next Phase

**"좋은 아이디어인데 왜 안 하죠?"의 답은 대부분 백로그 0장(우선순위 기준)과 6장(분류 판단 기록)에 이미 있다.** 물어보기 전에 거기부터 본다.

### 3-3. `docs/MVP_PRD.md` — 개발자가 실제로 구현하는 문서

길다. **처음에는 이 순서로만 본다.**

| 절 | 무엇 | 누가 |
|---|---|---|
| 1.1b | **아이 원문의 지위** — 로그가 아니라 창작물 | **전원 필독** |
| 1.5 | 확정 기술 스택 | 전원 |
| 2장 | 핵심 사용자 흐름 | 전원 |
| 3장 EPIC A0·B | 나침반 퀘스트 루프 · Evaluator | 전원 |
| 3장 EPIC E | 안전 & 프라이버시 | 백엔드 |
| 4장 | 에이전트 스펙 (GM 프롬프트, 루브릭 G0~G3, 스캐폴딩) | 백엔드 |
| 5장 | 로깅 스펙 | 백엔드 |
| 8장 | 주차 마일스톤 | 전원 |
| 9장 | 결정 사항 — **"왜 이렇게?"의 답이 여기 많다** | 전원 |

> 이 시점에 답할 수 있어야 하는 질문: **"아이가 쓴 문장은 어디에 저장되고, 어디에는 절대 안 남는가?"**

## 4. 넷째 날 · 어떻게 일하는가 (약 60분)

### 4-1. `docs/작업흐름.md` — 개발자가 매일 여는 문서

전체를 읽되 **3장·3-2·5장은 외운다.**

- **`claude`를 어디서 띄우는가**에 따라 읽히는 규칙이 달라진다. 개발 작업은 **반드시 자기 패키지 안에서**
- **3-2 「개발자는 무엇부터 보는가」** — 주차계획 → `tasks/` → `docs/api/` → `api-requests/`. 매일의 진입 순서다
- **5장 관통하는 규칙** — 짧다. 표 하나다. 전부 지킨다

### 4-2. `docs/용어사전.md` — 여기가 이 프로젝트의 특이점

**아이 화면 / 내부 용어 / 코드 식별자 — 세 열을 넘어 섞지 않는다.**

같은 것을 부르는 말이 층마다 다르다. 코드에서 `boss_encounter`라고 부르는 것을 아이 화면에 "보스"라고 쓰면 안 된다. **8장 폐기·금지어**(보스, 앨범, 연습하기, 점수 등)는 지금 외워둔다 — 나중에 고치면 UI 문자열을 전부 훑어야 한다.

**새 용어는 코드보다 사전에 먼저 등록한다.**

### 4-3. `CLAUDE.md` 3종 — 읽는 게 아니라 작동하는 파일

| 파일 | 언제 읽히나 |
|---|---|
| 루트 `CLAUDE.md` | 항상 (제품 결정·페르소나·문서 인덱스) |
| `api/CLAUDE.md` | `api/` 안의 파일을 다룰 때 |
| `web/CLAUDE.md` | `web/` 안의 파일을 다룰 때 |

각 파일의 **「절대 하지 않는 것」**은 Claude가 코드를 쓰기 **전에** 작동하는 예방 장치다. 이 저장소에는 PR도 코드 리뷰도 없어서(§8), 이게 사실상 유일한 앞단 방어선이다.

### 4-4. `docs/adr/` — "왜 이렇게 했지?"의 답

한 결정 = 한 파일. **번호가 낮은 것부터 전부 읽는다.** 지금 5개뿐이고 짧다. 특히 `0004`(PR을 쓰지 않는 이유)와 `0005`(LLM 프로바이더 교체)는 지금 일하는 방식을 직접 규정한다.

## 5. 역할별 · 추가로 읽을 것

### 5-1. 백엔드로 합류했다면

| 순서 | 문서 | 무엇 |
|---|---|---|
| 1 | `api/CLAUDE.md` | **「절대 하지 않는 것」 3개를 먼저.** 원문 로깅 / `docs/` 섞인 커밋 / 화이트리스트 하드코딩 |
| 2 | `api/README.md` · `api/tasks/README.md` | 스택 전제, 진척 체크 방식 |
| 3 | `docs/api/README.md` → `공통규약.md` → `Stage0.md` | **계약 사양.** "이대로 만들라"의 기준이지 할 일 목록이 아니다 |
| 4 | `docs/api/미결.md` | 아직 안 정한 것 + 판단 기준·결정 시점. **이게 줄어드는 게 진척이다** |
| 5 | `docs/안전_어휘_기준.md` | 판타지 전투 허용 화이트리스트. E-1 구현의 기준 |
| 6 | `docs/MVP_PRD.md` 4장·5장 | 에이전트 스펙 · 로깅 스펙 |
| 7 | `docs/아키텍처 및 구현난의도.md` | Stage 0/1 요청 흐름, 영역별 난이도 |

**스키마의 진실은 `/openapi.json`이다.** 문서가 아니라 실행 중인 서버가 SSOT다 (`docs/api/README.md`).

**가장 자주 사고 나는 지점** — 디버깅하다 `logger.info(f"입력: {text}")` 한 줄. 그 한 줄이 PRD 1.1b를 깬다. 임시 로그도 커밋에 남는다.

### 5-2. 프론트로 합류했다면

| 순서 | 문서 | 무엇 |
|---|---|---|
| 1 | `web/CLAUDE.md` | **「절대 하지 않는 것」 4개를 먼저.** `types.gen.ts` 수동 편집 / 아이 화면 금지어 / 원문 클라이언트 로깅 / `docs/` 직접 수정 |
| 2 | `web/README.md` · `web/tasks/README.md` | 스택 전제, 진척 체크 방식 |
| 3 | `docs/api/Stage0.md` | 화면이 무엇을 받는지. **`outcome` 3분기**(`result`/`scaffold`/`blocked`)가 화면 분기의 축이다 |
| 4 | `docs/장면카드_초안.md` | 아이가 실제로 보는 20장 + 튜토리얼 T1~T3 |
| 5 | `docs/캐릭터/` | GM 가이드 캐릭터 에셋. 표정 PNG 4종과 `expression` 매핑 |
| 6 | `docs/용어사전.md` 「아이 화면」 열 | **화면 문자열은 전부 여기서 온다** |

**타입은 손으로 안 만든다.** `make contracts`가 `/openapi.json`에서 생성한다. 타입이 안 맞으면 그 파일이 아니라 **API가 틀린 것**이고, `api-requests/open/`에 요청을 올린다.

**`docs/`는 PM 소유다.** 명세가 틀렸다고 판단돼도 직접 고치지 않는다 — `api-requests/open/`에 올리거나 PM에게 말한다. 강제 장치는 없고 규약이다.

**대사를 프론트에서 지어내지 않는다.** 가이드 캐릭터 대사는 서버가 내려주는 `guide` 객체를 그대로 쓴다.

## 6. 문서 층위 지도

문서가 많아 보이지만 **층이 다르다. 중복이 아니다.** 위층이 아래층을 지배한다.

| 층 | 문서 | 바뀌는 주기 | 충돌하면 |
|---|---|---|---|
| **불변** | `비전.md` | 거의 안 바뀜 | 항상 이긴다 |
| **정의** | `페르소나정의.md` · `용어사전.md` · `검증가설_성공지표.md` | 분기 | 페르소나·KPI 수치는 `페르소나정의.md`가 SSOT |
| **스펙** | `MVP_PRD.md` · `백로그.md` · `docs/api/` · `안전_어휘_기준.md` | 월 | 스키마는 **`/openapi.json`이 SSOT** (문서 아님) |
| **실행** | `주차계획/` · `api/tasks/` · `web/tasks/` | 주 | PRD 8장이 상위. 어긋남이 주차를 넘으면 8장도 고친다 |
| **기록** | `adr/` · 커밋 메시지 | 결정할 때마다 | 뒤집을 땐 지우지 않고 새 ADR |
| **작동** | `CLAUDE.md` 3종 · `.claude/commands/` | 필요할 때 | 읽는 문서가 아니라 실행되는 규칙 |

**충돌을 발견하면 고치지 말고 먼저 알린다.** 어느 쪽이 맞는지는 층위로 정해지지, 나중에 쓰인 쪽이 맞는 게 아니다.

## 8. 솔직히 알아야 할 것 — 이 저장소에 없는 장치

`docs/작업흐름.md` 7장과 `docs/adr/0004`에 이유가 있다. **모르고 부딪히면 사고가 난다.**

- **PR도 코드 리뷰도 없다.** `main`에 직접 push한다. 아무도 안 읽은 코드가 들어갈 수 있다
- **브랜치 보호가 없다.** 비공개 무료 플랜이라 걸 수 없다
- **알림이 없다.** 상대가 무엇을 올렸는지 아무도 알려주지 않는다 → **올렸으면 직접 말한다**
- **CI는 사후 통보다.** push 후에 돌아서, 깨진 코드가 들어간 다음 빨간불이 뜬다 → **커밋 전에 로컬에서 lint·test를 돌린다**

그래서 **`main`은 항상 돌아가는 상태로 유지한다.** 반쯤 된 것을 올리지 않는다 — `api`가 깨지면 프론트의 `make contracts`가 그 자리에서 실패한다.

**선택적 PR** — 정책이 아니라 판단이다. ① 계약이 바뀔 때 ② 파일 5개·200줄을 넘는 큰 변경 ③ 안전·프라이버시 경로(Moderation, PII 마스킹, 로깅).

### 당신이 3번째 사람이라면

**위 체제는 「팀이 둘」을 전제로 설계됐다.** `docs/adr/0004`가 명시적으로 적어둔 재검토 조건이 **"사람이 3명 이상이 될 때"**다. 합류와 함께 그 전제가 깨지므로, **ADR 0004를 다시 여는 것이 합류 첫 주의 팀 과제**다. 되돌릴 때 주의점(패키지별 소유자를 두면 승인 데드락이 재현된다)도 그 문서에 있다.

## 9. 막혔을 때 어디로 가나

| 막힌 것 | 가는 곳 |
|---|---|
| 이 기능을 왜 만드나 | `비전.md` 4장 질문 5개 → 안 풀리면 PM |
| 이걸 만들어야 하나 말아야 하나 | `백로그.md` 0장·6장 → `비전.md` 5장 |
| 이번 주에 뭘 하나 | `docs/주차계획/W<n>.md` — **여기서만 고른다** |
| 아직 안 정해진 설계 결정 | `docs/api/미결.md`. **언제 정하는지는 주차 계획이 정한다** — 보고 스스로 골라 착수하지 않는다 |
| API가 없거나 틀렸다 (프론트) | `api-requests/open/`에 항목 → **백엔드에게 직접 말한다** |
| 상대가 처리했나 | `/api-check` |
| 이 말을 화면에 써도 되나 | `docs/용어사전.md` 「아이 화면」 열 + 8장 금지어 |
| 이 표현을 아이가 써도 되나 | `docs/안전_어휘_기준.md` 2·3·4장 |
| 왜 이렇게 결정했나 | `docs/adr/` → `MVP_PRD.md` 9장 |
| 상대가 어제 뭘 했나 | `git log -p --since=yesterday` — **유일한 경로다** |

**문서에 답이 없으면 그건 문서를 보강할 순간이다.** 물어보고, 답을 들었으면 **파일 본문에 적는다.** 말로 정한 것은 3주 뒤 사라진다.
