# api — 백엔드 작업 규칙

> 이 파일은 `api/` 안의 파일을 다룰 때 함께 읽힌다. **저장소 전체 규칙은 루트 `CLAUDE.md`**, 스택 전제는 `api/README.md`. 여기 있는 건 백엔드에만 해당하는 것들이다.

## 절대 하지 않는 것

- **아이 입력 원문을 로그에 남기지 않는다.** `logger.info(f"...{text}")`, 예외 메시지에 입력 끼워넣기, APM 태그, 오류 리포터 payload 전부 해당. 디버깅용 임시 로그도 안 된다 — 커밋에 남는다.
  원문이 가도 되는 곳은 **`card_attempts.text` 단 하나**다. 그건 로그가 아니라 아이의 책 콘텐츠다 (PRD 1.1b).
  요청·응답 body 마스킹 미들웨어를 우회하는 경로를 만들지 않는다.
- **이 PR에서 `docs/`를 함께 고치지 않는다.** 응답 스키마·오류 코드·처리 순서가 바뀌면 PR 본문의 「명세 변경 요약」에 적어두고, 문서 반영은 **별도 PR**로 한다.
  (@jinioh88은 PM을 겸하므로 권한상으로는 가능하다. 그래도 나누는 이유 — 코드 리뷰와 문서 검토는 보는 눈이 다르고, 섞이면 명세 변경이 코드 diff에 묻힌다.)
- **안전 어휘 화이트리스트를 코드에 하드코딩하지 않는다.** 기준은 `docs/안전_어휘_기준.md`다. 코드에 복사해 두면 문서와 갈라지고, 갈라진 쪽이 실제로 아이를 막는다.

## 항상 하는 것

- 아이에게 나가는 모든 문자열은 `docs/용어사전.md`의 **아이 화면** 열을 쓴다. **오류 응답의 `message` 필드도 아이가 읽는다** — `VALIDATION_ERROR` 같은 코드는 `code`에, 사람 말은 `message`에.
- 입출력 **양방향** Moderation. 출력(GM 서사·삽화 프롬프트)도 검사 대상이다.
- `POST /attempts`는 `outcome` 3분기(`result` / `scaffold` / `blocked`)를 항상 명시적으로 반환한다. 프론트가 이 값으로 화면을 가른다.
- 응답 스키마를 바꿨으면 `/openapi.json`이 갱신되는지 확인한다. 프론트의 `make contracts`가 그것만 본다.

## 확인할 것

- `api-requests/open/` — 프론트가 기다리는 요청. 구현 후 `done/`으로 옮기고 완료 기록을 채운다 (`api-requests/README.md`)
