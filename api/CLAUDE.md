# api — 백엔드 작업 규칙

> 이 파일은 `api/` 안의 파일을 다룰 때 함께 읽힌다. **저장소 전체 규칙은 루트 `CLAUDE.md`**, 스택 전제는 `api/README.md`. 여기 있는 건 백엔드에만 해당하는 것들이다.

## 절대 하지 않는 것

- **아이 입력 원문을 로그에 남기지 않는다.** `logger.info(f"...{text}")`, 예외 메시지에 입력 끼워넣기, APM 태그, 오류 리포터 payload 전부 해당. 디버깅용 임시 로그도 안 된다 — 커밋에 남는다.
  원문이 가도 되는 곳은 **`card_attempts.text` 와 `chapter_turns.text` 둘**이다. 그 둘은 로그가 아니라 아이의 책 콘텐츠다 (PRD 1.1b).
  **`chapter_turns.text` 는 2026-09-16 에 사용자가 더했다** (종전 「`card_attempts.text` 단 하나」). **Stage 1 턴 문장도 책 콘텐츠다** — `A-7` 이 「챕터 완결 = 책 한 장 · 문장은 아이 원문 그대로」이고, 그 칸이 없으면 **책을 세울 수 없다** (`docs/api/Stage1.md` 2절 11번 정정 · `dc975e5`).
  **⛔ 가르는 선은 「로그냐 책 콘텐츠냐」다. 금지되는 것이 줄지 않았다** — `logger`·APM·예외 메시지·오류 리포터·이벤트 payload 는 그대로 금지다. **DB 의 책 콘텐츠 칸만 예외**이고, 그 칸도 **아이 원문 그대로 보관하는 자리**라 마스킹을 지난 문장이 들어간다.
  **⛔ 셋째 칸을 늘리려면 사용자가 이 줄을 직접 고친다.** 이 파일은 그 세션에서 사용자가 말해야 고쳐진다.
  요청·응답 body 마스킹 미들웨어를 우회하는 경로를 만들지 않는다.
- **코드 커밋에 `docs/` 수정을 섞지 않는다.** 응답 스키마·오류 코드·처리 순서가 바뀌면 커밋 메시지에 `명세 변경:` 줄로 적고, 문서 반영은 **별도 커밋**으로 한다.
  (같은 사람이 PM 역할도 쓰므로 권한상으로는 가능하다. **그래서 더 나눠야 한다** — 막아주는 구조가 없고 규율뿐이다. 섞이면 명세 변경이 코드 diff에 묻혀서 나중에 왜 바뀌었는지 추적할 수 없다. `docs/` 반영은 루트 PM 세션에서 별도 커밋으로.)
- **안전 어휘 화이트리스트를 코드에 하드코딩하지 않는다.** 기준은 `docs/안전_어휘_기준.md`다. 코드에 복사해 두면 문서와 갈라지고, 갈라진 쪽이 실제로 아이를 막는다.

## 항상 하는 것

- 아이에게 나가는 모든 문자열은 `docs/용어사전.md`의 **아이 화면** 열을 쓴다. **오류 응답의 `message` 필드도 아이가 읽는다** — `VALIDATION_ERROR` 같은 코드는 `code`에, 사람 말은 `message`에.
- **화면에 그대로 나가는 문장은 `docs/문구.md` 가 SSOT 이고 코드가 따라온다. 없는 문구를 코드에서 지어내지 않는다.**
  **`용어사전.md` 는 낱말, `문구.md` 는 문장이다** — 여기 낱말 기준만 적혀 있던 탓에 **문장 기준이 규칙에 없었다**(2026-09-10 대표 점검).
  **목·픽스처·예시도 이 문서를 읽는다** — 2026-09-09 에 둘이 났고 둘 다 사람이 눈으로 찾았다(목 강제 경로의 결과 대사 · 카드 화면 가이드 대사).
  **백엔드가 `문구.md` 를 런타임에 읽는 것은 W4 에서 그 항목을 받아서지 이 규칙이 시켜서가 아니었다.** 이제 규칙이 시킨다.
- 입출력 **양방향** Moderation. 출력(GM 서사·삽화 프롬프트)도 검사 대상이다.
- `POST /attempts`는 `outcome` 3분기(`result` / `scaffold` / `blocked`)를 항상 명시적으로 반환한다. 프론트가 이 값으로 화면을 가른다.
- 응답 스키마를 바꿨으면 `/openapi.json`이 갱신되는지 확인한다. 프론트의 `make contracts`가 그것만 본다.

## 이번 주에 할 일

계획은 `docs/주차계획/W<n>.md` 「작업 쪼갬 · 백엔드」, 진척 체크는 **`api/tasks/W<n>.md`**.

- **`api/tasks/W<n>.md` 가 없으면 먼저 `/my-week W<n>` 을 돌리라고 알린다.** 계획에서 이 패키지 몫만 뽑아 만든다
- **범위를 진척 파일에서 조용히 바꾸지 않는다 — 새로 생기면 PM 에게 말한다.**
  **막지 않는다.** 계약이 바뀌거나 실기기에서 결함이 나오면 **그것을 만난 세션의 파일에 먼저 앉는 것이
  정상이다.** 2026-09-09 하루에 넷이 그랬고 **셋은 막혔으면 아예 안 나왔다**(배포 · 액자 · 즉시 `ready`).
  **대신 `신설` + 날짜 + 근거 커밋을 적고 PM 에게 말한다.** 계획이 원본이라는 것은
  **「거기서 태어나지 않는다」가 아니라 「거기로 옮겨 간다」**는 뜻이다
  (**2026-09-10 정정** — 09-09 에 이렇게 고친 것이 `web/` 에만 내려가 **api 만 옛 「바꾸지 않는다」로 남아 있었다**)
- 항목을 끝내면 그 파일의 체크박스를 갱신하고, 상대에게 말할 것이 있으면 함께 짚는다
- **하위 체크박스 하나가 한 세션 분량이다.** 하나를 끝내면 커밋하고 **세션을 새로 띄우라고 권한다** — 한 세션에서 크게 하면 컨텍스트가 늘어져 위의 「절대 하지 않는 것」을 뒤로 갈수록 놓친다

## 커밋하기 전

- `make -C .. lint && uv run pytest` — **로컬에서 먼저 돌린다.** CI는 `main` push 후에 도는 사후 통보다
  - **`ruff check` 를 직접 부르지 않는다.** 종전 줄에는 `ruff format --check` 이 빠져 있었고,
    2026-09-14 에 **포맷만 틀린 커밋이 이 줄을 통과해** `main` 의 `make lint` 가 빨갰다.
    같은 검사가 **Makefile · `ci.yml` · 여기 셋**에 따로 적혀 있어 한 곳이 빠진 것이라,
    **한 곳(루트 Makefile `lint`)을 가리킨다** — 검사가 늘 때 고칠 자리가 하나다
  - **`-C ..` 가 붙는 이유.** Makefile 은 저장소 루트에 있고 make 는 상위를 안 뒤진다 —
    `api/` 에서 그냥 `make lint` 를 부르면 `No rule to make target` 로 죽는다 (2026-09-15 실측)
  - **`web` 의 eslint 도 같이 돈다** (둘 합쳐 6초). 백엔드만 고쳤어도 그렇다 —
    **타깃 하나를 가리키는 값**이고, 공용 `main` 이라 어차피 봐야 하는 것이다
- `main`은 프론트와 공용이다. **반쯤 된 것을 올리지 않는다** — `api`가 깨지면 프론트의 `make contracts`가 실패한다

## api-requests — **휴면이다** (2026-09-06~)

**`api-requests/` 는 돌지 않는다.** 요청자와 담당자가 같은 사람(`@jjub0217`)이 되어 **왕복이 성립하지 않는다**
(`adr/0008` · 루트 `CLAUDE.md`). **`open/` 이 비어 있는 것이 정상이고, `/api-check` 를 습관으로 돌리지 않는다.**
**개발자가 둘이 되면 되살린다** — 그때 아래 절차가 그대로 다시 선다(`api-requests/README.md`).

**그때까지 그 자리를 대신하는 것 셋**

- **아직 안 정한 설계 결정** → `docs/api/미결.md`
- **대표 판단이 필요한 것** → 주차 계획의 「막힌 것」에 적고 **대표에게 직접 말한다**
- **명세가 바뀌었다** → 커밋 메시지에 `명세 변경:` 줄 · `/openapi.json` 이 갱신되는지 확인
  (프론트의 `make contracts` 가 그것만 본다). 문서 반영은 **루트 PM 세션에서 별도 커밋**

**⛔ 「알림 장치가 없어 커밋만으로는 전달되지 않는다」는 폐기됐다** (2026-09-09, 루트 `CLAUDE.md`).
**대표가 커밋 메시지와 메모를 전부 읽는다 — 그 전제가 사실이 아니었다.**
**대신 조건이 붙는다: 안전·프라이버시 경로는 커밋 메시지 「첫 줄」에 드러나야 한다.** 본문에 묻으면 못 읽는다.
**바뀌지 않은 것 — 판정이 필요한 것은 여전히 직접 말한다.** 알림과 판정은 다르다.

## 이 패키지의 관례

- **`pytest` 를 두 개 동시에 돌리지 않는다.** `tests/conftest.py` 가 세션 시작에 테스트
  DB 를 **drop 하고 다시 만들면서 `pg_terminate_backend` 로 남의 커넥션을 끊는다.**
  겹치면 **둘 다 이상하게 죽는다** — 그리고 **밖에서 보면 「백엔드가 멈췄다」와 구분이
  안 된다.** 2026-09-08 에 실제로 밟았고, 배경으로 던져 놓고 또 던져서 그렇게 됐다.
  **앞 실행이 끝난 것을 보고 다음을 돌린다.**
- **⛔ `pytest` 를 돌리기 전에 브라우저 e2e 가 도는지 본다** (2026-09-16 추가).
  **`web/e2e/_서버하네스.mjs` 의 기본 DB 가 `geulmoheom_test` 로 위와 같은 DB 다** —
  `pytest` 를 돌리면 **프론트가 돌리는 `pnpm e2e:server` 의 행이 흐름 중간에 사라진다.**
  - **그때 브라우저에서 보이는 것은 「인증이 끊겼다」는 401 이다** — 세션이 몇 요청
    지나고 죽는 모양이라 **인증 결함과 구분이 안 된다.** 2026-09-16 에 실제로 밟았고,
    프론트가 **8번 완료 조건(가로채지 않는 e2e 갈래)이 막혔다**고 올려 왔다.
    로그의 `reason` 이 **`행없음`** 이면 이것이다
  - **위 「두 개 동시에」와 같은 사고인데 한쪽만 적혀 있어서 그대로 밟았다.**
    같은 DB 를 드롭하는 것이 원인이고, **`pytest` 끼리든 e2e 와든 똑같다**
  - **가르는 값은 `DATABASE_URL` 이다** — 하네스가 그 환경변수를 먼저 본다.
    e2e 를 **다른 DB 로 돌리면 영영 안 겹친다**(그 DB 에 `alembic upgrade head` 와
    `scripts/seed_cards.py` 가 필요하다 — CI `web-slow` 가 그렇게 돈다)
  - **세션이 셋이라 「내가 안 돌리면 된다」가 안 통한다.** 전체를 돌릴 참이면
    **프론트 세션에 먼저 말한다**
- **고치는 파일만 돌리고 전체는 커밋 직전 한 번.** 450여 개에 테스트 DB 를 매 실행
  다시 만들어 **한 번에 2~3분**이다. 매번 전체를 돌리면 그 시간이 통째로 쌓인다.
  **위 두 줄이 그 습관을 더 값지게 만든다** — 전체를 덜 돌리면 남의 e2e 를 덜 깬다.
