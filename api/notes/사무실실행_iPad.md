# 사무실 실행 — iPad 를 개발 머신에 붙인다

**W4 「사무실 실행 준비」.** 대표가 도메인을 보류해(「테스트 단계에는 무리」) 학부모·아이를
사무실로 초대하고 **우리 기기**로 돈다. 여기는 **당일에 즉흥으로 하면 안 되는 것**만 적는다.

## ⛔ 아이·학부모 기기에는 안 깐다

**남의 기기에 우리 루트 CA 를 설치하게 하는 것은 그 기기의 모든 https 를 우리가
들여다볼 수 있게 만드는 것**이다. **프라이버시를 지키겠다고 모은 자리에서 정반대를
요구하는 것**이 된다. **우리 iPad 한 대만 쓴다.**

## ⚠ 태블릿이어야 한다. 노트북으로 대체하지 않는다

**손가락으로 쓰는 것과 키보드로 쓰는 것은 입력 글자 수가 다르고, 그게 H2 핵심
지표다**(관찰 신호 2번 「첫 입력 글자 수」). **개발 머신 브라우저에서 되는 것은 완료
조건이 아니다** — **아이가 쓸 그 기기에서 아이 계정으로 한 판을 끝내는 것**이 조건이다.

## 이름을 무엇으로 하나 — **mDNS 이름을 주로, LAN IP 를 예비로**

**`.test` 는 못 쓴다.** `/etc/hosts` 로 푸는 것이라 **이 머신 안에서만** 듣고 iPad 에는
아무 효력이 없다.

**mDNS(`<머신이름>.local`)를 주로 쓴다.**
- iOS 가 **별도 설정 없이** 푼다. 라우터를 안 건드린다
- **DHCP 로 주소가 바뀌어도 이름이 안 변한다.** 이게 편의가 아니다 —
  **PWA 를 홈 화면에 설치하면 오리진이 고정으로 박히는데, 주소가 바뀌면 설치본이
  깨진다. 접속 코드는 1회용이라 아이가 다시 못 들어온다**

**LAN IP 를 예비로 같이 담는다.** **사무실 Wi-Fi 가 멀티캐스트를 막으면 mDNS 가 안 되고**,
그때 인증서를 다시 구우려면 그 자리에서 할 일이 는다. **미리 한 장에 둘 다 넣는다.**

**`__Host-` 쿠키와 CORS 는 안 건드린다.** 같은 호스트의 다른 포트라 지금 `.test` 두
이름과 성질이 같다 — **cross-origin 이고 same-site 다.** 쿠키는 포트를 안 가리고,
`__Host-` 는 `Secure`·`Path=/`·`Domain` 미부착만 요구하므로 이름이 무엇이든 그대로 선다.
CORS 는 오리진 문자열 하나가 바뀔 뿐이다(`CORS_ORIGINS` 환경 변수).

## 순서

```
make certs-lan     # 인증서에 .test 둘 + mDNS 이름 + LAN IP 를 한 장에 담는다
                   # **별도 터미널에서.** Claude 세션 안에서는 sudo 프롬프트가 안 먹는다
make dev-lan       # api·web 을 LAN 에 연다. 열 주소를 출력한다
```

**iPad 쪽 (미리 해 둔다 — 아이 앞에서 하지 않는다)**

1. **루트 CA 설치** — `~/Library/Application Support/mkcert/rootCA.pem` 을 iPad 로 보내
   프로파일 설치
2. **⚠ 신뢰를 따로 켠다** — 설치만으로는 안 된다.
   **설정 → 일반 → 정보 → 인증서 신뢰 설정**에서 스위치를 켜야 https 가 선다.
   **여기서 막히면 화면이 아무 말도 안 해 준다**
3. **PWA 를 홈 화면에 설치한다** — **자녀 인증 화면은 브라우저 탭이면 코드 입력을
   막는다**(`문구.md` 3.2). **아이 앞에서 그 벽을 만나면 안 된다**
4. **아이 계정으로 한 판을 끝까지 돌려 본다** — 쓰기 → 그림 → 내 책

**끝나면 `dev-lan` 을 끈다.** 개발 DB 에 실제 자녀 계정이 있고, **사무실 망의 아무나
닿을 수 있는 상태**다. 평소 `make dev` 는 loopback 그대로라 안 열린다.

## 이 장치로 **못 재는 것**

- **삽화 `<img>` 에 쿠키가 실리는지** — 여기서는 api·web 이 **같은 호스트의 다른 포트**인데
  운영은 **다른 서브도메인**이다. **구조가 달라 재지 못한다.** 파일럿 직전에 처음 재게
  되고, **그때 안 되면 그림이 0%** 다 (`미결.md` 「검증 대기」)
- **`Set-Cookie` 가 Cloudflare 앞단을 지나는 동안의 동작** — 앞단이 없다
- **정적 빌드(`output: "export"`)로 나가는 경로** — 여기서는 `next dev` 다

## ① 통과한 것 — **기기·인증서·이름·네트워크는 다 섰다**

**잰 것** — iPad Safari 로 `https://<호스트>:8000/healthz` → **`{"status":"ok"}`**

**그래서 아래가 전부 통과라는 뜻이다.** 다음에 여기를 다시 의심하지 않는다.

- 루트 CA 설치 · **⚠ 신뢰 스위치를 따로 켜기** — **사람이 밟는 이 순서가 실제로 통했다**
- **mDNS 이름이 풀린다** — 사무실 Wi-Fi 가 멀티캐스트를 안 막았다. LAN IP 로 안 갈아탔다
- TLS · 포트 · 방화벽

## ② 고친 것 — CORS 대소문자 (`75fec63`)

**증상** — `:3000` 을 열면 「장면을 펼치는 중…」에서 멈춘다.

**원인** — **브라우저는 `Origin` 헤더의 호스트를 소문자로 정규화해서 보낸다.**
`LAN_HOST` 에는 `scutil --get LocalHostName` 이 준 **`osejin-ui-MacBookPro.local`** 이
그대로 들어갔고 **FastAPI `CORSMiddleware` 는 정확 문자열 비교**라 안 맞았다.

```
Origin: …MacBookPro.local:3000  → access-control-allow-origin 옴
Origin: …macbookpro.local:3000  → 헤더 없음      ← 브라우저가 보내는 것
```

**고침** — `LAN_HOST` 를 소문자로 내렸다. **인증서는 안 다시 뽑는다**(TLS 호스트 매칭은
대소문자를 안 가린다). **대소문자를 둘 다 넣지 않는다** — 브라우저가 절대 대문자로
안 보내므로 **다음 사람이 「대문자도 지원한다」로 읽는다.**

### ⛔ **`curl` 로는 절대 안 걸린다. `curl` 은 `Origin` 을 안 보낸다**

**이 한 줄이 이 절에서 제일 중요하다.** 「Mac 에서 `curl` 200」을 보고 **통과로 읽었고
그게 틀렸다.** **「서버가 200 을 준다」와 「브라우저가 읽을 수 있다」는 다른 자리다.**
LAN 경로를 검사할 때는 **`-H "Origin: …"` 을 반드시 붙인다.**

덧 — 이 결함은 **LAN 경로에서만 난다.** 평소 개발 이름(`app.geulmoheom.test`)에는
대문자가 없다. 그리고 **`scutil` 이 준 값은 우리가 고른 문자열이 아니라 기기에서
읽어 온 값**이라 **우리가 안 정한 성질이 붙어 있었다.**

## ③ ⛔ 막힌 것 — **실기기에서 JS 가 살아나지 못한다** (iPadOS 17.7.10)

**CORS 를 고친 뒤에도 같은 자리에서 멈춘다. 여기서 끝났다.**

**증상 셋이 같은 것을 가리킨다.**

- **화면은 뜨는데 「나가기」를 눌러도 무반응** — 이벤트 핸들러가 안 붙었다
- **API 를 아예 안 부른다** — 서버 로그에 `/api/v1/...` 이 한 줄도 없다.
  `next` 은 `/`·`/manifest.webmanifest`·`/child/auth` 를 계속 200 으로 주고 있었다
- **오류 화면조차 안 뜬다** — **그리는 것도 JS 다**
- `/child/auth` 도 「확인하는 중…」에서 멈춘다

**즉 서버가 그린 HTML 은 왔는데 하이드레이션이 끝나지 않았다.**

**서버는 결백하다.** CORS 를 전부 확인했다 — `access-control-allow-origin` ·
**`access-control-allow-credentials: true`** · 프리플라이트 200 · 401 은 정상(로그인 전).
**「서버가 답했는데 브라우저가 버린 것」도 아니다** — 그 경우라면 **요청이 로그에 찍힌다.**

**설정 문제도 아닌 것 같다** — Next 16 기본 지원 범위가 Safari 16.4 이상이라 17.7 은 그 안이다.
**문법이 아니라 실행 중 오류일 가능성이 크다.**

### 다음에 할 것 — **추측을 멈추고 콘솔을 본다**

```
iPad : 설정 › Safari › 고급 › 웹 검사기 켜기 → USB 연결 → 「이 컴퓨터를 신뢰」
Mac  : Safari › 설정 › 고급 › 개발자용 기능 보기 → 개발자용 › [iPad] › 그 페이지
```

**빨간 오류 한 줄이면 고치는 것은 짧다. 지금은 그게 없어서 후보만 좁히고 있다.**

**같이 볼 것 — `next dev` 와 `output: "export"` 프로덕션 빌드가 다를 수 있다.**
**dev 번들은 최신 문법을 그대로 쓰고 프로덕션 빌드는 낮춰 굽는다.** 프리테스트는
`dev` 로 도는데 **둘이 다르면 파일럿에서 또 다른 얼굴로 나온다.**
**정적 빌드를 구워 같은 iPad 로 열어 보는 것이 값싼 갈래 검사다** — 거기서 살아나면
**dev 전용 문제**로 좁혀진다.

**후보를 좁힐 때 참고** — `web/src/lib/api.ts` 의 `baseUrl()` 은 값이 비면 **던진다.**
경계가 없으면 트리가 통째로 죽어 **화면이 멈추고 네트워크에는 아무것도 안 나간다.**
지금 증상과 모양이 같으니 **콘솔에서 그 메시지가 보이는지 먼저 본다.**

### ⚠ 진단에서 헛디딘 것 — `lsof` 로 판단하지 않는다

「8000 에 연결이 없다」를 보고 「요청이 안 나간다」로 읽으면 안 된다.

# 2026-09-09 낮 — **③ 은 풀렸다. 대신 진짜 막고 있던 것이 드러났다**

## ③ 「JS 가 안 산다」 → **`next dev` 쪽 문제였다. 정적 빌드에서는 산다**

**정적 빌드를 3001 에 나란히 세워 갈랐다** (`make build-out` → `make serve-out`).
**`next dev` 를 안 내리고 두 포트를 동시에 띄워 같은 기기에서 번갈아 열었다.**

**정적 빌드에서 JS 가 살아 있다는 증거 넷.**

- 청크·CSS·폰트가 **전부** 내려갔다
- **`sw.js` 가 요청됐다** — **서비스워커 등록은 클라이언트 JS 가 실행돼야만 일어난다**
- api 를 불렀다 (`/api/v1/cards/next` 401)
- **어제 무반응이던 「나가기」가 눌린다** — 확인 창과 그 안의 버튼 둘까지 그려졌다.
  **이벤트 핸들러가 붙었다 = 하이드레이션이 끝났다**

**그래서 프리테스트는 정적 빌드로 서빙한다.** 덤으로 **「사무실 실행은 정적 빌드 경로를
안 탄다」던 한계가 사라진다** — 파일럿과 같은 경로가 된다.

**`next dev` 에서 왜 죽는지는 안 밝혔다.** 프리테스트가 정적 빌드로 돌면 급하지 않다.
**다만 개발 중에는 그대로 못 쓴다는 뜻이라 어딘가에 남아야 한다.**

### 정적 서빙에서 미리 잡은 함정 — **301 → 404**

`output: "export"` 는 `/child/auth` 를 **`.html` 파일과 같은 이름의 디렉터리로 둘 다** 굽는다
(디렉터리 안에는 RSC 페이로드가 들어간다). **기본 정적 서버는 디렉터리를 먼저 골라
301 로 보내고, 그 안에 `index.html` 이 없어 404 를 낸다.** **그게 앱 결함처럼 보인다** —
진단 중 가장 나쁜 거짓 신호다. `serve_web_out.py` 가 **`.html` 을 먼저 본다.**
**파일럿 배포처(Cloudflare Pages)는 알아서 하지만, 다른 데로 옮기면 다시 만난다.**

## ⛔ 진짜 막고 있던 것 — **아이가 들어갈 문이 하나도 없다**

**앞의 셋을 걷어내자 이게 드러났다.**

**증상** — 홈 화면 아이콘을 열면 **「다시 한 번 들어와 주세요」**(`문구.md` 2.1 `UNAUTHORIZED`)가
뜨고 **거기서 더 갈 데가 없다.**

**경로** — 매니페스트 `start_url` 이 **`/`** 다(`scope: /`). iOS 가 그것을 따른다(로그로 확인:
아이콘 요청 뒤 `GET /` 가 왔다). `/` 는 `/cards/next` 를 부르고 **로그인 전이라 401** 인데,
`web/src/app/page.tsx` 의 401 처리(`거절화면`, 115행)가 **`DAILY_CAP_REACHED` 만 따로 보고
나머지는 문구만 띄운다.** **`UNAUTHORIZED` 를 자녀 인증 화면으로 보내는 갈래가 없다.**

**우회로가 없다.**
- **탭** — 코드 입력을 **우리가 일부러 막아 놨다**(1회용 코드 보호, `문구.md` 3.2).
  **이 가드는 옳고 실기기에서 실제로 물었다**
- **홈 화면 앱** — 주소창이 없어 `/child/auth` 로 갈 방법이 없다

**곁가지 — 로그인 전 화면에 「나가기」가 있다.** 확인 문구가 「다시 들어오려면 부모님께
새 접속 코드를 받아야 해요」인데 **들어온 적 없는 아이에게는 겁만 주는 말**이고
**사실도 아니다**(잃을 세션이 없다). **문구는 맞게 쓰였고 놓인 자리가 틀렸다.**

**즉 「로그인 전」이라는 상태가 화면으로 없다.** 첫 진입 화면이 **이미 들어와 있는 아이**를
전제로 그려져 있다 — 「**다시** 한 번」 · 「**다시** 들어오려면」 · 로그아웃 버튼.

**고칠 자리는 프론트다.** `start_url` 을 `/child/auth` 로 돌리는 것은 답이 아니다 —
**이미 들어온 아이가 매번 인증 화면부터 보게 되고**, 본체(로그인 전 상태가 없음)가 그대로 남는다.

### ⚠ 왜 아무도 몰랐나 — **E2E 142개가 전부 초록이다**

**검사가 인증된 상태로 시작하거나 `/child/auth` 로 바로 들어간다.**
**아이가 제일 먼저 만날 화면을 아무도 안 본 채였다.**
어제의 「검사는 멀쩡했고 재는 기기가 달랐다」에 한 줄이 더 붙는다 —
**「그리고 재는 상태도 달랐다.」** W5 축 훑기 재료다.

## ⛔ 아직 안 풀린 것 — **결과 화면 액자 높이** (2026-09-09)

**기기가 있어야 더 나간다.** 다음에 붙일 때 **이것부터** 한다.

**실측이 갈렸다. 폭은 같고 높이만 다르다.**

| | 폭 | 높이 | 비율 |
|---|---|---|---|
| 실기기 (홈 화면 앱 · iPadOS 17.7) | **260** | **237** | **1.10** |
| Playwright WebKit 26.6 (정적 빌드 · 1024×748) | **260** | 449 | 0.579 |
| Chromium (dev · 1024×768) | 267 | 461 | 0.579 |

**폭이 260 으로 같다** — `60svh` 도 `maxWidth` 계산도 기기에서 같다는 뜻이다.
**깨진 것은 `aspect-ratio` 가 높이를 잡는 부분 하나다.**

**「크롭으로 그렇게 보인 것 아니냐」는 스크린샷으로 걸렀다.** 근거 셋 —
① **레터박스가 없다**(액자 안 세로선에 배경색 픽셀 0개) ② **배지가 안 겹친다**
(449 였다면 y 20~469 인데 「기본」 배지가 289 에서 시작한다) ③ **위아래 모서리가 둘 다
둥글다** — 잘린 것이 아니라 **상자가 거기서 끝난다.**

**가장 그럴듯한 후보 — 엔진 버전이다.**
**Playwright 의 WebKit 은 26.6 이고 그 iPad 는 6세대라 iPadOS 17.7 에서 멈춰 있다.**
`aspect-ratio` 가 그 사이에 고쳐졌다면 **양쪽 실측이 둘 다 참**이다.
**「사파리로 잰다」가 「그 기기의 사파리로 잰다」는 아니다** — 프론트도 그 한계를 적었다.
**standalone 방향은 반대로 커져야 해서 설명이 안 된다**(크롬이 없으면 `svh` 가 커진다).
