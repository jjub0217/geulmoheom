  체크리스트를 만들 때 **범위 표와 작업 쪼갬을 대조하는 것**이 이걸 잡는 유일한 장치다
- **1번의 실제 위험은 `.test` https 다.** 계약 수정 자체는 작고, 위험 표도 「월요일에 먼저
  친다」고 지목한다. **https 전환을 먼저 끝내고 커밋을 나눈다**
- **`make certs` 는 별도 터미널에서 돌린다.** Claude 세션 안에서는 sudo 프롬프트에 입력이
  안 들어가서 **인증서 발급(sudo 불필요)만 되고 키체인·`/etc/hosts` 가 통째로 건너뛰어졌다.**
  `mkcert -install` 이 프롬프트를 못 받아도 0 을 반환해 `set -e` 가 안 잡는다 — **「됐다」를
  출력하면서 절반만 된 상태로 끝난다.** 스크립트가 이제 끝에서 셋을 실제로 검사하고 죽는다
- **2번은 대표 판정 대기다.** 실측에서 나온 것 — 내장 필터는 기본값이면 7/7 미탐, 임계값을
  최저로 조여도 유혈·고문·자해가 새고 「똥」·「바보」가 죽는다. 별도 단계는 오탐 0·미탐 0 이고
  **병렬이면 지연 +13ms**. 순차는 1.5초 예산을 깬다
- **7번은 「범위」 표에 행이 없다** — 「작업 쪼갬 · 백엔드」에만 있다 (W4 에서 당겨온 항목).
  완료 조건이 범위 표에 없어 **5·6번과 반대 방향의 어긋남**이다. 지어낸 것이 아니라
  계획에 실제로 적힌 항목이라 그대로 옮겼다. **PM 에게 말할 것** — 범위 표에 행을 추가한다
- **목 토큰에 한글이 들어가 있어 `Set-Cookie` 가 500 이었다.** 헤더는 latin-1 이라
  값에 한글이 있으면 응답을 만드는 순간 `UnicodeEncodeError` 다. **오늘 프론트에서 난
  「한글 토큰」과 같은 사고가 서버에서 한 번 더 났다** — 이번엔 쿠키 속성 테스트가 잡았다
- **`make contracts` 는 node 24 가 필요하다.** `pnpm` 이 `~/.nvm/versions/node/v24.20.0/bin`
  에만 있어 기본 PATH(v22)로는 `pnpm: command not found` 로 죽는다. `web/.nvmrc` 가 24 다.
  **7번(계약 드리프트 CI)에서 이 자리를 밟는다** — CI 는 `.nvmrc` 를 읽게 해야 한다
