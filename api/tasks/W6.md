### ⛔ 그럼 어제 502 둘은 무엇이었나 — **배포 전환 창이 유력하다**

**콜드로는 재현이 안 된다.** 짧게·길게, `GET`·`POST` 넷 다 502 가 아니었다.
**그리고 로그 전체에 502 가 한 번도 안 찍혔다** — 502 는 **앱에 안 닿은 요청**이다.
콜드에서는 Render 가 기다려 주니 닿는다. **안 닿는 창은 따로 있다:**

```
09:06:43  Deploying...
09:07:09  POST /parents/signup 201      ← 헌 인스턴스가 처리
09:07:13  Application startup complete   ← 새 인스턴스
09:07:16  Shutting down                  ← 헌 인스턴스
```

**이 몇 초에 들어온 요청은 어느 인스턴스에도 안 닿는다 = 502.**
그리고 **어제 502 를 밟은 시각대(06:04~10:06 UTC)에 배포가 수십 번 돌았다** — 문서 커밋마다.

**⛔ 「식은 서버가 502 를 낸다」가 아니라 「배포 중 서버가 502 를 낸다」일 공산이 크다.**
**확정은 아니다** — 그 두 요청의 정확한 시각을 안 적어 둬서 창에 걸렸는지 못 맞춘다.
**교훈은 그 자체다: 502 를 만났을 때 시각을 안 적었다.**

**⭐ 이것이 Ignored Paths 의 급을 또 올린다.** 어제는 「아이 판이 끊긴다」였는데,
이제 **「어제 그 502 의 원인일 수 있다」**다. **깨우기(15번)가 막을 수 없는 종류다** —
깨우기는 잠든 것을 깨우지, **배포 전환을 막지 못한다.**

### 실측 — **짧게 잔 뒤 GET 은 33초에 200 이다. 502 가 아니었다** (2026-09-15 23:41)

```
23:41:29  Vercel /healthz : 200 · 33.33초   ← 콜드
23:42:02  Render /healthz : 200 · 0.68초    ← 방금 깬 것 확인
```

**Render 직접이 0.68초인 것이 앞의 33초가 진짜 콜드였다는 증거다** — 첫 요청이 깨웠고
둘째는 따뜻했다.

**⛔ 세워 둔 전제와 어긋난다.** 우리는 **「깨어나는 시간이 앞단이 기다려 주는 시간보다
길다」**로 적어 왔는데, **Vercel 이 33초를 기다려 주고 200 을 돌려줬다.**

**⛔ 그래도 「502 는 안 난다」로 읽으면 안 된다 — 이 측정의 한계 둘이 크다.**

| | |
|---|---|
| **잠들어 있던 시간이 1분 48초뿐이다** | 마지막 배포 23:22(요청 23:23) → 잠든 추정 **23:38:23**(+15분) → 친 시각 23:41:29. **「그날 첫 아이」는 밤새 잔 서버를 만난다.** 2분 잔 컨테이너와 8시간 잔 컨테이너가 같다는 보장이 없다 |
| **`GET` 을 쟀는데 실제 502 둘은 `POST` 였다** | `POST /parents/children` · `POST /attempts` |

**✅ 말할 수 있는 것** — 잔다(**15분**) · **짧게 잔 뒤 GET 은 33초·200**
**⛔ 못 말하는 것** — 오래 잔 뒤 · `POST`

**다음 한 걸음은 공짜다** — **내일 아침 첫 요청이 「오래 잔 뒤」를 저절로 답한다.**
**⚠ 단 그 첫 요청을 아이가 아니라 우리가 쳐야 한다.** 아이가 먼저 치면 **재는 대신
당한다.**

### 콜드를 맞는 것은 첫 요청 하나다 — 아이 흐름에서는 접속 코드 (2026-09-15 로그)

**운영 로그의 실제 순서** (`14:03:2x`):
`child/auth 200` → `child/me 200` → `cards/next 200` → `attempts 200`

**`POST /attempts` 는 네 번째다.** 그 앞에 **접속 코드가 이미 서버를 깨웠다.**
**콜드는 첫 요청이 다 맞는다** — 아이 흐름에서 그 자리는 **접속 코드 입력**이고,
**거기서 이기느냐 지느냐가 전부**다. 오늘 잰 **33.3초** 대 **코드 입력 십수 초**라
**그 한 자리는 진다.**

**그래서 「보내기」 침묵은 콜드가 아니다** — 따뜻한 값이 기본이고 그건
**`POST /attempts` 2856ms**(평가 1081ms 포함, 나머지 ~1.8초가 DB·검열·삽화 시작)다.
프론트가 「콜드면 36초」로 올리려던 것을 이 순서 근거로 물렸다.

**⚠ 예외 — 세션 중간에 잠드는 경우는 진짜로 있다.** 아이가 **15분 넘게 쓰면**
그 사이 요청이 없어 서버가 잔다. **프론트 깨우기 ②(10분 주기)가 이걸 막는데,
다 막지는 못한다**(프론트가 범위를 좁혀 줬다):

| | |
|---|---|
| **막는다** | **보면서 오래 쓰는 아이** — 탭이 보이는 동안 10분마다 친다 |
| **⛔ 못 막는다** | **탭을 벗어났다 돌아와 곧바로 보내는 아이** — 숨기면 타이머가 멈춘다(요금 조건이었다). 복귀 핑과 제출이 **거의 같이 나가** 33초를 못 번다 |

**후자가 얼마나 흔한지는 모른다 — 관찰로 볼 것이다.**
