# W2 캐릭터 표정 4종 재생성 — 생성 기록

모델 `gemini-3.1-flash-lite-image` (`docs/adr/0006` 확정) · 정본 `docs/캐릭터/캐릭터색상코드.png`

**여기는 생성 기록이다. 캐릭터 확정은 PM 판정이고 `docs/캐릭터/` 반영도 PM 몫이다.**
생성물은 `api/out/character/` (gitignore).

## 왜 다시 뽑았나

현행 표정 PNG는 정본과 **다른 디자인**이다 — 스카프·고글·크로스백이 없다
(`도우미캐릭터설명.md` 「딸려 나오는 일」). 그대로 두면 아이가 보는 가이드와 삽화 속
가이드가 갈린다.

**그리고 현행은 4종이 아니라 3종이다.**

```
캐릭터(묘사부족).png   md5 4d63f6d9513cdafef310cb7fe18b0a6a
캐릭터(세션종료).png   md5 4d63f6d9513cdafef310cb7fe18b0a6a   ← 바이트 동일
```

세션 종료 컷은 없었다. 스캐폴딩 표정을 복사해 둔 것이라 `session_end` 는 재파생이 아니라
**새로 설계한 것**이다.

## W3 삽화에 그대로 걸리는 것 셋 — 문구로는 안 막힌다

**세 가지 모두 프롬프트에 부정 지시를 넣어도 안 막혔고, 레퍼런스 이미지나 출력을 손봐야 통했다.**
W3(B-3·B-5)에서 캐릭터를 삽화에 넣을 때 같은 함정을 다시 밟는다.

| 증상 | 통하지 않은 것 | 통한 것 |
|---|---|---|
| 시트의 **글자가 그림에 박힌다** — 하단 `FUR MARKINGS VEST LEATHER…`, 상단 `SIDE` (첫 판 4장 전부) | `no text, no labels, no watermark` | **레퍼런스에서 글자 영역을 잘라낸다** |
| **꼬리가 둘이 된다** — 3면 시트라 몸이 셋이라서 (2판 8장 중 4장) | `exactly ONE striped tail, never two` → 이번엔 꼬리가 몸을 감는 고리가 됐다 | **정면 1면만 잘라 넣는다** |
| **배경이 4장 다 달라진다** — 바닥재·조명까지 | (배경을 서술한 것 자체가 원인) | **단색 배경을 지시하고 장면을 아예 안 그리게 한다** |

**턴어라운드 원본을 그대로 레퍼런스로 쓰지 않는다.** 정면 1면에도 학사모·고글·스카프·조끼·
크로스백·나침반이 다 보여서 잃는 것이 없다 (`scripts/gen_character.py` 의 `레퍼런스()`).

배경은 정본과 같은 **옅은 회색 단색**으로 갔다. 이 넷은 같은 자리에서 교체되는 표정이라
(아이가 문장을 쓰면 `default` → `compass_bright`) 배경이 함께 바뀌면 표정이 변한 게 아니라
**장면이 순간이동한 것으로 읽힌다.** 화면에는 카드 스케치 삽화가 이미 큰 사각형으로 들어가서
(A0-2) 가이드까지 배경이 있으면 삽화 둘이 경쟁한다. 2026-09-07 PM 판정.

## 규격

| | |
|---|---|
| 비율 | **`1:1` 명시 고정.** W1 벤치의 결함이 이것을 안 준 것이었다 |
| 크기 | **`1K`(1024×1024)가 상한.** `gemini-3.1-flash-lite-image` 는 `2K` 를 400 INVALID_ARGUMENT 로 거부한다 |
| 형식 | **PNG.** API 는 JPEG 로 돌려주고 `image_config.output_mime_type` 은 Gemini API 미지원이라 받은 뒤 로컬에서 바꾼다. **JPEG 압축은 되돌릴 수 없다** — 컨테이너만 무손실이다 |
| 파일명 | `guide.expression` 코드 (`default` / `compass_bright` / `compass_dim` / `session_end`). 프론트 매핑이 그 값이다 |

현행 2048 PNG → 1024 PNG 로 내려간다. 상위 모델(`gemini-3.1-flash-image`, 장당 $0.067)이면
2K가 되지만 **`adr/0006` 확정본과 다른 모델로 만든 에셋이 남는다.** 태블릿 가로에서 가이드가
차지하는 크기를 보면 1024로 충분하다는 판단 (2026-09-07 PM 동의).

## 표정 설계에서 지킨 것

- **밝기 순서** `compass_dim` < `default` < `compass_bright`. 뒤집히면 「나침반은 아이 문장에만
  반응한다」는 장치가 그림에서 무너진다 (`용어사전.md` 3장)
- **`compass_dim` 은 실망이 아니라 호기심.** 되묻기에서 부정어를 금지해 놓고 그림이 실망한
  얼굴이면 뺀 부정어가 그림에서 되살아난다. 프롬프트에 `NOT disappointed, NOT scolding` 을 넣었다
- **`session_end` 는 아쉬움이 아니라 만족.** 「내일 또 보자」에 붙는 그림이 더 하고 싶게 만들면
  하드 피니시를 그림이 스스로 깬다 (비전 5장). 나침반은 꺼진 게 아니라 파우치에서 쉰다

# 2차 — 얼굴·털 되돌림 (2026-09-07)

실행 `PYTHONPATH=. uv run python scripts/gen_character.py gemini-3.1-flash-lite-image 1K 2`
1차 산출물은 `api/out/character_1차/` 로 옮겼다. 새 8장이 `api/out/character/`.

## 왜 다시 뽑았나

아동 4명 확인이 **12표 6:6 동률**로 끝났다 (`docs/캐릭터/비교_결과.md`). 그런데 근거 축이
갈린다 — **장비(고글·크로스백·스카프)는 신규가 4표 전부, 얼굴·털·색은 기존이 4표 전부.**
**두 축은 분리해서 고칠 수 있다.** 장비는 그대로 두고 얼굴·털만 기존 쪽으로 당겼다.

1차의 실제 결함은 눈으로도 보인다 — **몸통이 탁한 갈색이라 머리와 색이 갈리고**, 눈이 작고
털이 평평해 아이들이 말한 "털이 부드러워 보인다"가 안 나온다.

## 바꾼 것 셋

| | 바꾼 것 | 안 바꾼 것 |
|---|---|---|
| **얼굴·털** | 둥근 얼굴선 · 큰 눈 + 캐치라이트 · 부드러운 털결 · **몸통도 머리와 같은 밝은 주황** | 색상코드 `#D45B28` 자체 (`도우미캐릭터설명.md` 가 SSOT). **채도·조명만** 되돌렸다 |
| **반짝임** | 세기·퍼짐을 키웠다 — 팔·가슴까지 번지고 얼굴을 비춘다 | **색 `#33E1FF` 고정.** 색상코드 표가 SSOT다 |
| **레퍼런스** | **둘로 늘렸다** — ① 정본 정면(장비·색) ② 기존 그림의 **머리만 잘라서**(얼굴·털) | 장비 목록 · 1:1 · 1K · 단색 회색 배경 |

**둘째 레퍼런스도 통째로 넣지 않았다.** 기존 그림은 배경이 서재라 그대로 넣으면 장면이
딸려 온다 — 1차에서 배경이 4장 다 달라진 것과 같은 함정이다. 머리만 남기면 아이들이
고른 것(둥근 얼굴선·큰 눈·부드러운 털)은 오고 배경은 안 온다.
**말로도 한 번 더 잘랐다** — "둘째는 얼굴·눈·털에만 쓰고, 없는 장비는 따라가지 마라".

## 실측 — 상태가 눈으로 갈리는가

PM 이 1차 판정에 쓴 것과 같은 지표(픽셀 평균 차이)다. **기존 세트는 「조용할 때」와
「흐려질 때」가 2.6/255 로 사실상 같은 그림이었고, 1차 신규가 15.2 였다.**

| | default↔bright | default↔dim | bright↔dim |
|---|---|---|---|
| **후보 1** | **36.3** | **24.3** | 31.9 |
| 후보 2 | 29.9 | 22.6 | 30.8 |

**후보 1 이 모든 쌍에서 더 벌어진다.** 되묻기 화면이 "나침반이 흐려졌다"로 말을 거는데
그 신호가 그림에서 보여야 한다 — 이게 1차를 살려야 했던 기능적 이유였고 여기서도 지켰다.

배경은 8장 전부 `#E0E0E0` 언저리(모서리 221~227)로 **일치**한다. 같은 자리에서 교체되는
그림이라 배경이 함께 바뀌면 표정이 변한 게 아니라 장면이 순간이동한 것으로 읽힌다.

지연 평균 5,373ms · 8장 · **$0.2688**. 이 항목 누적 28장 · 약 $0.94.
