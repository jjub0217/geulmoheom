# W2 2번 — `POST /attempts` 응답 실측

측정일 2026-09-07 · 실행 `EVALUATOR_MODEL=gemini-3.1-flash-lite PYTHONPATH=. uv run python scripts/bench_attempt.py 3`
기준: PRD 4.5 「Evaluator — 1.5초 이내」 · 모델 `gemini-3.1-flash-lite` (`W2-evaluator-bench.md`)

**`W2-evaluator-bench.md` 가 잰 것은 Evaluator 호출 하나다.** 아이가 기다리는 건 엔드포인트
왕복이라 미들웨어·검증·응답 조립까지 붙여 다시 쟀다. 문장은 `docs/루브릭_예시셋.md` 에서
등급별로 뽑았다 — 실제 아이 문장은 쓰지 않는다.

TestClient 로 앱을 직접 부른다. **uvicorn·소켓 왕복(로컬 수 ms)은 빠지고 그 위는 다 들어간다.**

## 판정 — 통과

| 회차 | 호출 | 평균 | 중앙 | 최대 | 1.5초 초과 |
|---|---|---|---|---|---|
| 1 | 8 | 1,097ms | 1,064ms | 1,423ms | 0/8 |
| 2 | 12 | 1,274ms | 1,045ms | **4,086ms** | **1/12** |
| 3 | 4 | 1,047ms | 1,027ms | 1,245ms | 0/4 |
| 4 | 12 | **1,041ms** | 1,009ms | **1,253ms** | 0/12 |

**36회 중 35회가 818~1,423ms.** 넘은 것은 2회차 **첫 호출 하나**(4,086ms)다.

- 엔드포인트 왕복이 Evaluator 호출보다 **5~15ms** 더 걸린다. 미들웨어·검증·응답 조립은
  1.5초 예산에서 사실상 무시할 수 있다
- 시스템 지시 **2,795자**(입력 약 1,791토큰). `W2-evaluator-bench.md` 의 `all` 모드와 같은 크기다 —
  **운영이 벤치와 같은 프롬프트를 쓴다** (`app/rubric.py` 를 양쪽이 함께 쓴다)

## 넘은 한 번

2회차 첫 호출만 4,086ms 였고 같은 조건 3·4회차에서는 재현되지 않았다(첫 호출 1,060ms·1,253ms).
프로바이더 쪽 꼬리로 본다. **폴백 로그는 `none` 이었다** — 3초 타임아웃이 물린 것이 아니라
단발 응답이 늦은 것이다.

- 이런 꼬리 때문에 타임아웃 3초 → 재시도 1회 → G1 폴백이 있다 (`Stage0.md` 9절 5번).
  **최악은 6초**다. 그 사이 아이는 결과를 못 본다 — 화면 쪽 대기 연출은 W3 몫이다
- **감시할 것은 `eval_fallback` 비율이다.** `none` 이 아닌 줄이 늘면 판정 품질이 조용히
  나빠지고 있다는 뜻이다 (`eval_result` 로그, PRD 5장)

## 남는 여유

`W2-evaluator-bench.md` 가 적은 「여유 139ms」는 그 회차 최대치(1,361ms) 기준이다.
여기서는 최대 1,253ms 로 **여유 247ms**가 나왔다. 회차마다 흔들리므로 **여유를 200ms 안팎으로 보고**,
아래를 건드리면 **다시 잰다.**

- 카드 문맥(상황문·명사 태그)을 프롬프트에 얹을 때 — 되묻기(W2 3번)가 후보다
- 예시셋 40개가 늘어날 때
- 명시적 context caching 을 붙일 때 (입력 단가 $0.25/M → $0.025/M. **아직 안 붙였다**)

## 곁에서 확인한 것

- **등급 12/12 일치.** 예시셋 문장이라 프롬프트에 답이 들어 있는 상태다. 일치율 근거로 쓰지 않는다
  (그건 `W2-evaluator-bench.md` 의 leave-one-out 97.5%)
- **묘사어(`highlights`) 는 G2 1~2개 · G3 4~5개**로 등급을 따라간다. G0·G1 은 0개가 정상이다
- `descriptors` 를 하이라이트의 주 재료로 쓴다. `signals` 는 「캄캄한」처럼 **원형**으로 와서
  문장의 「캄캄했지만」과 안 맞는다 — 종류(`kind`)만 신호에서 가져온다
